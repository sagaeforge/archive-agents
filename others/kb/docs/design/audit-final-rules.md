## 0. 결론

**이대로 구축하면 안 된다.** blocker 7건, major 17건, minor 11건을 찾았다.

blocker는 네 묶음이다.

| 묶음 | 항목 | 내용 |
|---|---|---|
| 구현이 돌지 않는다 | RULE-01 | worktree 격리와 커밋 금지가 충돌한다. 앞 파동의 코드가 다음 파동에 전달되지 않고, 메인 세션이 병합해야 한다 |
| 기본 상태가 지침을 어긴다 | RULE-02, RULE-03 | 승인이 없으면 스케줄이 0개이고 다른 세션이 KB를 조회할 경로가 없다. 그런데 ADR은 "막지 않는다"고 적는다 |
| 활성 소스 목록이 틀렸다 | RULE-04, RULE-05 | GitHub atom, PyPI JSON, arXiv API, Netflix, KOBACO가 robots 거부다(실측). D18, D19는 `www.youtube.com`이라 결정 1과 WP-21 시험에 모순된다 |
| 죽은 데이터가 활성으로 나간다 | RULE-06, RULE-07 | `superseded` 주어의 주장이 기본 검색에 남고, L1·L2 경로에는 적재 전 확인이 없다 |

**ADR 부록 A의 충족 표시는 믿을 수 없다.** R6, R7, R9, R11, R12, R15, R17, R19, R20은 "충족"으로 적혀 있지만 기본 상태나 경로 일부에서 성립하지 않는다(4장).

**사용자가 정해야 할 것.** 다음 넷은 코드로 풀 수 없다.

1. 구현 방식: 격리를 빼거나, 파동별 커밋을 승인한다(RULE-01).
2. 결정 3과 결정 7을 "미결정이어도 되는 항목"에서 구축 완료 조건으로 올릴지 정한다(RULE-02, RULE-03).
3. robots 거부 소스의 처리 기준을 정한다. 공식 API는 예외로 둘 수 있지만 사용자가 승인해야 한다(RULE-04).
4. 머신 밖 경로를 끝내 두지 않을 경우 first_party를 열 방법이 없다. 단일 사본 위험을 감수하는 개방을 허용할지 정한다(RULE-08).

## 2. 결함

### 2.1 blocker

#### RULE-01. 구현 워크플로우가 파동 사이에 코드를 넘기지 못한다

- **위치.** 계획 L13(격리), L16(커밋), L45(스크립트), L157(`venv-<git sha>`)
- **결함.** 계획은 worktree 격리로 병렬 구현하고, 패키지는 커밋하지 않으며, 메인 세션이 소유 경로를 합친다고 적었다. worktree는 추적된 파일만 체크아웃하므로 미커밋 결과는 다음 파동에 보이지 않는다. 메인 체크아웃으로 합쳐도 마찬가지다. 게다가 병합은 메인 세션의 직접 작업이라 지침 1을 어긴다.
- **근거.** 실측(git 2.53). 이 저장소는 커밋 0개이고 `CLAUDE.md`, `docs/`는 미추적이다.

| 시험 | 결과 |
|---|---|
| 커밋 0개에서 `git worktree add -b` | `No possible source branch, inferring '--orphan'`. worktree에 `.git`만 있다 |
| 빈 기준 커밋 뒤 새 worktree | `CLAUDE.md`, `docs/`가 없다 |
| worktree A의 미커밋 파일을 두고 worktree B 생성 | 파일이 없다 |
| 그 파일을 메인 체크아웃에 복사하고 worktree C 생성 | 파일이 없다 |
| 커밋 0개에서 `git rev-parse HEAD` | `fatal`. `ops/bin/deploy`의 `<git sha>`를 구할 수 없다 |

1차 출처: Claude Code worktree 문서는 "checks out only tracked files", "untracked files ... are not present"라고 적고, 원격이 없으면 로컬 `HEAD`로 대체한다고 적는다. `.worktreeinclude`는 gitignore된 파일만 복사한다. Claude Code 자체의 커밋 0개 저장소 동작은 재현하지 않았다(추론: 빈 트리이거나 실패).

- **수정.** 둘 중 하나를 사용자가 고른다.
  - 안 1: `isolation`을 뺀다. 같은 파동의 소유 경로가 이미 겹치지 않으므로 메인 체크아웃에서 바로 병렬 실행한다. 병합이 사라져 지침 1도 해결된다. 소유 경로 위반은 사후에 `git status`로 검사한다.
  - 안 2: 빌드 브랜치의 파동별 커밋을 사용자가 승인한다. `worktree.baseRef: "head"`를 설정하고, 병합은 전담 에이전트가 맡는다.
  - 공통: `ops/bin/deploy`는 `git sha` 대신 소스 트리 내용 해시를 쓴다.

#### RULE-02. 기본 상태에는 스케줄이 없는데 ADR은 막지 않는다고 적는다

- **위치.** ADR L1197, L1203, L1053~1058, L1000~1003. 계획 L28, L585, L588
- **결함.** 트리거 넷 중 Windows 작업과 systemd 타이머는 결정 3 뒤다. 남는 것은 이 저장소 세션 훅과 수동 실행이다. 사용자가 이 저장소 세션을 열지 않으면 수집은 멈추고 알리는 곳도 없다. 사본 A~D도 전부 결정 2, 3 뒤라 라이브 데이터는 `ext4.vhdx` 1벌이다. 지침 6의 "수집 스케줄링으로 데이터가 절대 죽지 않게"가 기본 상태에서 성립하지 않는다.
- **근거.** 문서. ADR L1197은 "각 항목의 미결정 상태는 시스템을 막지 않는다"고 적는다. 완료 기준 L585는 WP-00~WP-19의 인수 전부 통과를 요구하는데, WP-14의 `[사용자 입회]` 조건(L409)은 결정 3 없이 통과할 수 없어 스스로 모순이다. 보고 항목 L588의 "재부팅 시험 전"은 타이머가 설치된 것처럼 읽힌다.
- **수정.** 결정 3을 구축 완료 조건으로 올린다. ADR L1197을 "결정 3, 7이 없으면 지침 3, 6 미충족"으로 고친다. 완료 보고에 "스케줄 없음, 이 저장소 세션을 열 때만 수집, 사본 1벌"을 명시한다.

#### RULE-03. 전역 등록 없이 다른 세션이 조회할 경로가 설계에 없다

- **위치.** ADR L970, L1207, L1258. 계획 L32, L363, L372, L588
- **결함.** 저장소의 목적은 다른 세션의 요청에 반환하는 것이다(CLAUDE.md 3행, 지침 3). 그런데 결정 7이 없으면 "이 저장소 세션에서만 사용"이다. 부록 A는 R9를 "충족 [F10]"으로 적었고, 완료 보고 L588에는 이 사실이 없다. ADR L970의 "기본값은 A"도 L1207과 어긋난다. A는 승인 없이 적용되지 않는다.
- **근거.** 문서. 전역 변경 없이 쓸 수 있는 경로가 실제로는 있지만 어느 문서에도 없다.

| 경로 | 전역 변경 | 문서 | 한계 |
|---|---|---|---|
| `runtime/bin/kb search`, `kb get`, `kb api` 절대 경로 | 없음 | 없음 | 다른 세션이 존재를 모른다. `kb request` CLI가 없다 |
| `claude --mcp-config <파일>` | 없음 | 시험에만 쓴다 | 세션 시작 때 사용자가 넘겨야 한다 |
| 교차 세션 메시징 | 없음 | 없음 | 이 저장소 세션이 살아 있어야 한다 |

WP-12의 목표는 "다른 프로젝트의 세션"인데 인수 시험 어디에도 다른 cwd에서 도는 조건이 없다.

- **수정.** `ops/mcp/kb.mcp.json`과 사용 안내를 산출물에 넣는다. `kb request` CLI를 추가한다. `test_claude_real.py`를 임시 다른 프로젝트 cwd에서 돌린다. 결정 7을 구축 완료 조건으로 올리거나, 미결정이면 완료 보고에 적는다. 부록 A의 R9를 "결정 7 전 미충족"으로 고친다.

#### RULE-04. 활성 소스 다수가 robots 거부이고 실패 표에 이 경우가 없다

- **위치.** ADR L629, L685, L674~679, L787~799. 계획 L261, L284, L523
- **결함.** tick은 robots를 준수한다. 그런데 활성 소스의 주 경로가 robots 거부다. 실패 판정표에 robots 행이 없어 동작이 정의되지 않았다. 건너뛰면 조용히 수집되지 않고, 실패로 세면 약 140개 저장소 때문에 WP-21의 `failed_sources <= sources * 0.1`이 깨진다. ADR L685는 P07을 robots로 껐으므로 활성 목록에도 같은 기준을 써야 한다.
- **근거.** 실측. UA `kb-collector/0.1`, 호스트당 `robots.txt` 1회, `*`와 `$`를 처리하는 매처를 썼다.

| 호스트 | 규칙(`User-agent: *`) | 영향 소스 |
|---|---|---|
| `github.com` | `Disallow: /*.atom$`, `Disallow: /*/*/commits/` | C01 피드, C12, C14, C15, C16, O01, O08, O11, U04, L02, L03, G4 저장소 약 140개 |
| `pypi.org` | `Disallow: /pypi/*/json`, `Disallow: /simple/` | X17 PyPI, 생존 신호 M07, M08, M09 |
| `export.arxiv.org` | `Disallow: /` | X15, D16. C·F의 유일한 `paper` 경로 |
| `www.netflix.com` | `Disallow: /` | X11. 계약의 시계열 예시 |
| `www.kobaco.co.kr` | `Disallow: /` | D11 |

대조한 URL 30건 중 나머지 24건(`raw.githubusercontent.com`, `code.claude.com`, `learn.chatgpt.com`, npm, HF, MCP Registry, 피드 다수)은 허용이다.

- **수정.** 소스에 `robots: enforce | official_api`를 두고 `official_api`는 약관 근거 URL을 필수로 한다. 사용자 결정 표에 올린다. GitHub는 REST·GraphQL API로 옮기는 안을 함께 낸다. Netflix, KOBACO는 비활성으로 옮기고 사유를 적는다. 실패 표에 `robots_denied` 행을 넣어 경고로 드러낸다. `test_registry.py`에 활성 URL의 robots 판정 고정 표본을 넣는다.

#### RULE-05. D18, D19가 `www.youtube.com`이라 결정 1과 WP-21 시험에 모순된다

- **위치.** ADR L679, L744, L745, L1201. 계획 L26, L277, L284, L527
- **결함.** `D17~D23` 활성에 D18(`https://www.youtube.com/trends/`)과 D19(`https://www.youtube.com/howyoutubeworks/recommendations/`)가 들어 있다. 결정 1의 기본 동작은 "전부 꺼짐"이다. WP-07을 계획대로 만들면 tick이 매일 `www.youtube.com`을 자동으로 호출한다. WP-21의 `test_hosts.py`는 `youtube.com` 요청 0건을 요구하므로 마지막 파동에서 실패한다. 비활성 시험 목록(L284)에 두 소스가 없어 그 전에는 드러나지 않는다.
- **근거.** 1차. YouTube 약관: "자동화된 수단(로봇, 봇넷 또는 스크래퍼 등)을 사용해 서비스에 액세스하면 안 됩니다." 예외는 robots를 따르는 공개 검색엔진과 사전 서면 승인이다. robots는 두 경로를 언급하지 않지만 약관 조항은 robots와 별개다. ADR이 P05, P06을 끈 조항과 같다. `support.google.com`의 D15, D22는 robots 허용으로 확인했다.
- **수정.** D18을 결정 1 항목으로 옮긴다. D19는 `support.google.com/youtube/answer/16089387`로 교체하고 `www.youtube.com` URL을 뺀다. `test_registry.py` 비활성 목록과 호스트 차단 시험에 추가한다.

#### RULE-06. `superseded` 주어의 `state`, `howto` 주장이 기본 검색에 남는다

- **위치.** ADR L362, L573, L837. 계획 L191, L234, L304. 계약 L121, L636
- **결함.** ADR L573은 `removed`, `superseded` 대상의 주장이 활성으로 나가지 않는다고 적는다. 그런데 구현 근거인 ADR L362, WP-02, 계약 2.7은 "주어가 `dead`면"만 계산한다. 시험도 dead와 removed만 본다. 그대로 만들면 `superseded` 주어의 주장은 기본 검색에 남는다. CLAUDE.md의 "유지보수가 끊긴 도구"는 대부분 `superseded`다.
- **근거.** 문서. `sources-inventory-g.md` 10장에서 `superseded`가 10행(`autogen`, `openai/skills`, `openai/swarm`, `crystal`, `kimi-cli`, GSD, `opencode`, `wshobson/commands`, MCP 참조 서버, `claude-code-sdk`), `removed` 계열이 7행이다.
- **수정.** `eff_status`를 "주어의 `status`가 `dead` 또는 `superseded`이면 `state`, `howto`도 그 값"으로 고친다. 병합(`merged_into` 있음)은 제외하고 주장을 대상으로 옮긴다. ADR L362, WP-02, 계약 2.7, WP-04와 WP-08 시험, fixture를 함께 고친다.

#### RULE-07. L1·L2 경로에 적재 전 생존 확인이 없고 WP-21에 종단 시험이 없다

- **위치.** ADR L564, L573, L714, L723, L726, L428. 계획 L304, L321, L484, L518, L522~528

#### RULE-16. 수집 경계에 호스트 정책이 없어 비활성 소스를 우회할 수 있다

- **위치.** ADR L563, L641~649, L666~667, L1130. 계획 2.3, L268, L527. CLAUDE.md 작업 규칙
- **결함.** `enabled=false`와 `needs_contact`는 소스 단위 판단이고 `safe_fetch(url, **limits)`에는 소스도 호스트 정책도 없다. 묶음 `snapshot`은 `source`가 필수가 아니다. `kb_fetch`, 묶음, `kb_put`으로 `www.youtube.com`이나 `sec.gov` URL을 넘기면 경계를 지난다. 수집 에이전트가 WebSearch로 그런 URL을 만나는 경로는 자연스럽다. robots, 서킷, 호스트 간격은 tick 3단계에만 있어 이 경로에 적용되지 않는다. `kb-researcher`의 WebFetch는 `fetch_log`에도 남지 않는다. WP-21의 호스트 시험은 사후 검사다.
- **근거.** 문서.
- **수정.** 비활성 소스에서 호스트 거부 목록을 만들어 `safe_fetch`가 강제한다. robots, 서킷, 간격을 공용 함수로 옮긴다. `ops/job-settings/*.json`에 `WebFetch(domain:...)` 거부 규칙을 둔다. 우회 시험을 추가한다.

#### RULE-17. 판단 문장이 보관되고 LLM 판정으로 활성이 될 수 있다

- **위치.** ADR L605, L724, L728. 계획 L293, L484
- **결함.** `R_JUDGEMENT`는 거부가 아니라 `needs_review` 저장이다. `attributed`, `speaker` 없는 "~해야 한다"가 원장에 남는다. 함의 판정은 "인용구가 문장을 뒷받침하는가"를 보므로 원문이 권고면 통과하고 `claim.review`로 `quote_found`가 된다. 귀속 없는 판단이 기본 검색에 나간다. 판단어 표는 `해야 한다`, `추천` 등이고 영어와 명령형 표현이 없다. G3 활용법 소스의 권고는 대부분 명령형이다. 이 경로의 인수 시험이 없다.
- **근거.** 문서.
- **수정.** `R_JUDGEMENT`를 함의 승격 대상에서 뺀다. 원문에서 화자가 확정되면 `attributed`로 저장하고 아니면 거부한다. `kind=howto`는 기본 `attributed`로 둔다. 영어·명령형 어휘를 넣는다. `tests/gate/test_judgement.py`를 추가한다.

#### RULE-18. 수집 에이전트가 `record`로 게이트를 우회해 판단을 저장할 수 있다

- **위치.** ADR L468, L556, L569, L921. 계획 L208, L293, L518
- **결함.** `kb-collect`의 `kb_ingest_submit`이 `record`를 받는다. 전송이 MCP이면 작성자는 `agent:<세션>`, `on_behalf_of=user:sagae`다. first_party는 인용 게이트와 판단어, 주입 검사를 지나지 않고 `policy_lint`는 속성 이름만 본다. 비신뢰 웹 페이지를 읽는 자율 에이전트의 문장이 사용자를 대신한 기록이 되고, 개방 뒤 기본 검색에 나간다. 지침 5의 "자체 판단"이고 시나리오는 레드팀 2.8과 같다.
- **근거.** 문서.
- **수정.** collector 프로필과 `producer=agent:*` 묶음의 `record`를 `E_POLICY`로 거부한다. `first_batch.jsonl` 시험은 사람 경로로 옮기고 거부 시험을 추가한다.

#### RULE-19. `kind=event`에 시점이 필수가 아니고 생존 필터에서 면제된다

- **위치.** ADR L362, L406, L565. 계획 L484, L518. CLAUDE.md 죽은 데이터 3항
- **결함.** CLAUDE.md는 역사적 사실에 시점을 붙이라고 요구한다. 그런데 `valid`는 선택 항목이다. `event`는 `eff_status` 면제이므로 모델이 현재 상태 문장을 `event`로 분류하면 주어가 죽어도 활성으로 남는다.
- **근거.** 문서.
- **수정.** `kind=event`에 `valid.from` 또는 `changed_on`을 필수로 하고 없으면 `E_EVENT_TIME`으로 거부한다. L2 동적 스키마에도 반영한다.

#### RULE-20. rtk·trail 금지 명령을 실제로 막는 장치가 없다

- **위치.** ADR L1078~1094. 계획 L434, L441
- **결함.** 설계 경로는 깨끗하지만 금지는 문장뿐이다. 가드는 허용 목록을 재작성만 하고 나머지는 통과시킨다. 에이전트가 `rtk ...`를 직접 부르면 변수가 없어 전역 DB에 쓴다. `trail note`, `trail init`, `rtk init -g`도 막히지 않는다. 인수 시험은 저장소 파일에 문자열이 없는지만 본다.
- **근거.** 실측. 가짜 HOME에서 변수 없이 `rtk git status`를 실행하자 `~/.local/share/rtk/history.db`가 생겼다.
- **수정.** `.claude/settings.json`에 `permissions.deny`를 둔다(`Bash(rtk init*)`, `Bash(trail init*)`, `Bash(trail note*)`, `Bash(trail upgrade*)`). 가드가 `rtk `로 시작하는 명령에도 접두사를 붙인다. 시험은 deny 규칙과 직접 호출의 상태 경로를 확인한다.

#### RULE-21. `incidents`가 실행 중에 전달되지 않고 해제할 수 없다

- **위치.** 계획 L44~48, L60, L450, L524, L528. ADR L822, L1123
- **결함.** CLAUDE.md는 메인 세션이 실행 중에도 사고를 확인해 알리라고 요구한다.
  - `parallel`은 장벽이라 로그가 파동 전체가 끝난 뒤 나간다. ADR의 "받자마자"와 어긋난다.
  - `.filter(Boolean)`이 죽은 에이전트의 결과를 버린다. 전역 파일을 쓴 뒤 죽은 에이전트의 사고가 사라진다.
  - `log()`는 사용자 진행 화면 표시이고 메인 모델 문맥에 들어가지 않는다(추론).
  - "미확인 사고"의 확인 절차가 없다. 사고가 한 번 나면 치명이 영구히 남고 WP-21의 `.incidents.open == 0`을 통과할 수 없다.
- **근거.** 1차(워크플로우 문서), 문서.
- **수정.** 에이전트 단계 안에서 즉시 기록한다. 메인 세션이 감시할 파일(`$KB_HOME/ops/incidents.ndjson`)에 추가한다. `null` 결과는 `agent_lost` 사고로 남긴다. `kb incident ack <id> --note`를 추가하고 사용자 보고 뒤 닫는다.

#### RULE-22. 승인 뒤에도 수집이 멈춘 것을 시스템이 알지 못한다

- **위치.** ADR L634, L792, L809, L816, L824, L1039~1049. 계획 L417, L419~426, L406, L434
- **결함.**
  - 워치독이 tick의 8단계라 tick이 돌지 않으면 검사도 없다. WP-15의 목표가 "침묵을 실패로 드러낸다"인데 침묵을 재현하는 인수 시험이 없다.
  - `kb-tick.service`에 `TimeoutStartSec`이 없다. `Type=oneshot`은 시작 시간 제한이 기본으로 꺼져 있다(1차). `--max-runtime`을 확인하지 못하는 구간에서 멈추면 타이머가 재발화하지 않고, 다른 트리거는 `tick.lock`에 걸려 조용히 끝난다(추론).
  - 소스 고장은 경고 1회다. 세션 훅은 치명만 받으므로 소스별 정지가 어디에도 드러나지 않는다.
  - `kb status` 값이 호출 시 계산인지 마지막 tick 값인지 정의가 없다.
  - 세션 훅은 `kb`가 없으면 조용히 끝난다. 배포가 깨져도 침묵한다.
  - L2 큐 나이 경고는 "L2 가동 뒤"라 가동 전에는 꺼져 있다.
  - `ops.db`는 "잃었을 때"만 정의돼 있고 손상은 없다(추론).
- **근거.** 문서, 1차.
- **수정.** `kb status`가 호출 시 `last_tick_at` 나이를 계산해 치명으로 올린다. 유닛에 `TimeoutStartSec=14min`을 둔다. 잠금 보유 시간을 기록한다. 세션 훅에 경고 건수 1줄을 넣고 `kb`가 깨졌으면 그 사실을 낸다. 침묵 시험을 추가한다.

#### RULE-23. 생존 판정 이벤트에 후속 대상이 없어 대체 처리가 끊긴다

- **위치.** ADR L381, L567, L837, L847. 계획 L312
- **결함.** CLAUDE.md는 "대체 처리"를 요구하고, ADR은 `superseded` 카드에 "체인"을 표시한다. 그런데 `survival.verdict`와 `liveness` 항목에 후속 필드가 없고 `SUCCESSOR_OF`를 만드는 곳이 없다. 어떤 도구가 무엇으로 대체됐는지 그래프에 남지 않는다. 이벤트 형식이라 데이터가 쌓인 뒤 고치면 업캐스터가 필요하다.
- **근거.** 문서. `SUCCESSOR_OF`는 타입 표 1곳에만 나온다.
- **수정.** `survival.verdict`, `liveness`에 `successor`를 넣고 투영이 엣지를 만든다. `superseded`에 필수로 하고 후속이 불명이면 `removed`로 둔다.

#### RULE-24. `inbox/` 처리를 부르는 경로가 없다

- **위치.** ADR L532, L625~635, L772~783. 계획 L208, L217
- **결함.** `kb inbox`는 있지만 tick 단계와 내부 작업 표에 없다. 넣은 파일이 조용히 남는다. TTY 밖에서 `f:user`를 만드는 유일한 경로다.
- **근거.** 문서.
- **수정.** tick 1단계에 스캔을 넣고 시험을 추가한다.

## 5. 확인해서 통과한 항목

- rtk 상태 경로 설계(ADR 19.1)는 F9를 재현했고 수정안이 동작한다.
- `trail build`, `trail mcp`, 도구 호출은 전역 쓰기가 없다.

- `incidents`가 ADR, 계획, 스키마, 시험에 일관되게 필수다.
- User-Agent에 개인 정보를 넣지 않는 규칙과 시험이 있다.
- `/tmp`에 큰 파일을 두지 않는 규칙이 패키지에 반영됐다.
- 커밋과 푸시는 승인 경계 안에 있다.
- 시스템 파일 설치는 전부 기본 건식 실행이다.
- 활성 목록과 비활성 목록 사이에 중복 ID가 없다.
- `support.google.com`의 D15, D22는 robots 허용이다.
- 공개 URL 18건(A~F 16건, G 2건)이 `kb-collector` UA로 HTTP 200을 줬다.
