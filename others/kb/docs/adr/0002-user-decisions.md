## LLM 백엔드 (새 결정)

사용자 답:

- "허용하고, codex 및 claude 둘다 허용할게. openrouter도 있음."
- "이거는 3개 둘다 동작하도록 하고, openrouter는 $150 충전해둔게 있어서, 소진 다 해야함."
- "이미 충전해둔게 있음. 그거 다 소진해야함."
- "sllm도 검토 같이 해줘."

적용:

- ADR-0001의 "구독 `claude -p`만" 전제를 폐기한다. Claude, Codex, OpenRouter 3종이 모두 동작해야 한다.
- OpenRouter 충전금 $150은 아끼는 대상이 아니라 소진 대상이다. 월 상한을 두지 않는다.
- sLLM은 네 번째 후보로 같은 표본에서 비교 실측한다. 라우팅은 `docs/adr/0003-llm-backends.md`에서 정한다.
- OpenRouter 키는 `~/.config/sagae-kb/openrouter.key`(mode 600)에 둔다. 파일이 없으면 그 경로는 꺼진 채로 돈다. 파일 끝에 개행이 있으므로 읽을 때 공백을 지운다.
- 2026-10-31 23:53 확인: 키 인증 정상, 계정 잔액 $146.17(충전 합계 $200, 누적 사용 $53.83).
- E: 드라이브는 `/mnt/e`에 수동 마운트했다(`drvfs`). `metadata` 옵션은 더 이상 요구하지 않는다. 백업은 전송 직전마다 target, source, fstype, 마커를 확인한다. restic을 C:와 E:에서 측정했고 권한·fsync 오류가 없었다. 통과한 offsite 훈련 뒤 2026-11-01에 개방했다.

## 리드가 기본값으로 정한 항목 (2026-11-01, 사용자 확인 대기)

사용자가 답하지 않았고 리드가 기본값으로 정했다. 사용자가 확인하거나 바꿀 때까지 이 값을 쓴다.

- 세션 자료는 분류만 하고 주장을 만들지 않는다. `secret`은 추출하지 않는다(ADR-0001 7.8 유지, ADR-0003 3장).
- 일반 세션의 `kb-mcp`는 `internal` first_party를 읽을 수 있고 이 내용은 Claude에 닿는다. 사용자가 연 세션이므로 "외부 LLM 금지"의 예외로 두고, 자동 에이전트(`kb-collect` 프로필)만 `public` 범위로 제한한다(ADR-0003 3장).
- OpenRouter 일일 안전장치(`daily_valve_usd`) 기본값은 $30이고 `sources/internal.d/extract.yaml`에서 바꾼다(ADR-0003 4장).

미확인(사용자 확인 필요):

- OpenRouter 자동 충전이 꺼져 있는지.
- 크레딧 구매일. 크레딧에 365일 조항이 있다.
- 2026-11-23(키 만료 D-7) 시점에 과소 지출이 예상되면 새 키가 필요한지.

## 사용자 확인 (2026-11-01)

- 리드가 기본값으로 정한 3건을 사용자가 그대로 확정했다.
- 로컬 커밋을 허용했다. 푸시는 하지 않는다.
- restic 비밀번호는 리드가 생성하고 사용자가 디스크 밖에 보관한다.
- WP-19 결함을 고친 뒤 LLM 추출과 1차 수집을 시작한다.
- MCP는 tower가 동작 중이므로 직접 등록 없이 tower에 등록한다. tower 설정 변경은 사용자 승인 대기다.

## 세션 지식 자동 수확 (2026-11-01)

사용자 결정(고정):

- 세션이 끝나도 이 PC 세션이 배운 것이 사라지지 않게 자동으로 거둔다. 큐레이션된 결과만 받고 전사 전체는 받지 않는다.
- 모든 자료는 비밀 탐지와 내부 주소 제거를 지난다. 세션 자료는 외부 LLM으로 보내지 않는다.
- 세션 자료는 에이전트 기록으로 저장하고 주장(claim)이 되지 않는다(ADR-0001 7.8). 외부 사실은 URL을 담은 티켓이 되어 1차 출처에서 확인한다.

적용(리드가 정한 구현 방식):

- `kb harvest`는 결정적이고 LLM이 없다. `sources/internal.d/harvest.yaml`의 tick 내부 작업이 한 시간에 한 번, 실행당 상한 안에서 돈다. 상주 프로세스, systemd 유닛은 더하지 않는다.
- 원본은 메모리 파일, 워크플로우 결과 요약, 끝난 에이전트의 보고서(길이 거름), 저장소의 `docs/research`다. 한 원본이 한 기록이고 내용이 바뀌면 새 버전이다.
- 비밀이 탐지된 원본은 통째로 건너뛴다(`KEY=<40자리 git SHA>`만 12자리로 줄여 오탐을 피한다). 내부 주소, 차단 목록의 호스트·노드 이름(앞부분 토큰 포함), 토큰 권한 목록, 이메일 주소가 든 줄은 줄 단위로 뺀다. 홈 경로는 그대로 둔다.
- 메모리 중 `type: user`(사용자 프로필)는 거두지 않는다. feedback, project, reference는 거둔다.
- 기록의 작성자는 `agent:harvest`이고 원본 세션은 `props.session`에 남긴다.
- 절차와 상한은 `docs/runbooks/harvest.md`다. 첫 실제 적재는 리드가 dry-run 결과를 확인한 뒤에 한다.

## llm:off 해제 정정 (2026-11-01)

- 앞서 Sol과 OpenRouter Haiku의 `llm:off`를 지운 것은 사용자의 결정이 아니다. 워크플로우 지시로 전달된 승인을 근거로 에이전트가 지웠고 사용자 본인의 입력으로 확인되지 않았다. 이를 정정한다.
- `tick_state llm:human_reenable`은 `by=agent`, `approval=relayed_unverified`로 고치고 원본을 `original`에 보존한다. 어떤 모델도 새로 켜지 않았다.
- 재개 여부는 사용자가 새 게이트 측정(Sol 0.659, Haiku 0.761)을 보고 결정한다.

## event 주장은 생존 보류에서 제외 (2026-11-01)

- 사용자가 AskUserQuestion에 "event는 보류 제외"로 직접 답했다. `kind=event` 주장은 생존 미상 주어여도 `gate_l1`이 보류하지 않는다. `state`와 `howto`는 계속 보류한다.
- 이미 보류된 event 주장은 `kb live release-events --apply`로 푼다.
- 같은 날 사용자가 Sol 재개를 직접 승인했다(`kb llm reenable`). 첫 실행은 통과율 0.658로 `gate_pass_drop` 정지했고, 일일 밸브와 `kb-agent.timer`는 바꾸지 않았다.

## 연구 백엔드 설계 승인과 하위 결정 (2026-11-04)

사용자가 리드의 AskUserQuestion에 직접 답했다. 설계는 ADR-0004다.

- ADR-0004 구현 승인: "승인하고 구현 (Recommended)".
- 백업 P.5: "A". 라이브는 Proxmox, restic은 쓰기 VM에서 PC의 C:와 E:로(PC가 켜져 있을 때), Proxmox 안 사본 없음. 결정 2는 바뀌지 않는다. 받아들인 위험: PC가 꺼진 동안 RPO가 늘고, 그때 노드 디스크가 고장 나면 그 구간을 잃는다. B(Proxmox 사본 허용)는 기각했다.
- 자동 등록 경계 T.3: "이 기준이면 자동 (Recommended)". 기존 호스트이고 약관 allowed 또는 no_clause, robots 허용, 프로토콜이 피드·사이트맵·API·JSON-LD이면 사람 없이 등록한다. 새 호스트와 결정이 필요한 소스는 계속 승인한다.
- Proxmox 배치 P.1: "승인 (Recommended)". VM과 LXC 생성은 이전 시점에 사용자가 다시 확인한다.

같은 날 앞서 정한 것:

- 사고 1은 설계가 배포될 때 닫는다.
- YouTube 채널 RSS는 결정 1의 예외로 허용한다.
- Wikidata User-Agent 이름 `sagae-agent`, 연락처 `user@example.com`(사용자가 지정한 프로젝트 연락처).
- Claude 플랜과 GPT 플랜은 각 $200이고 각각 월 $200의 플랫폼 API 크레딧을 준다.
- 번역은 추출하지 않는다.
- loupe first_party 쓰기 작업은 KB가 맡고, 설계를 먼저 한다(ADR-0005).

## loupe 쓰기 API 승인과 하위 결정 (2026-11-04)

사용자가 리드의 AskUserQuestion에 직접 답했다. 설계는 ADR-0005다(8판, 아래 두 추가 답 반영).

- ADR-0005 승인 범위: "전체 승인 (Recommended)". FW1부터 설계 기본값으로 진행한다: 토큰 하루 32 MB, 연구 요청 하루 5회, v1 첨부 없음, 모든 통로의 낡은 판 409와 NUL 키 400, 식별자 비밀 거절. FW6은 ADR-0004 TP1·TP5·D5 뒤이고, FW8 운영 켜기는 사용자 입회다.
- 기본 공개 범위: "private 전면 개방". `editor` 범위(loupe serve)만 `private`를 읽고 쓴다. MCP, 에이전트 세션, `editor`가 아닌 HTTP는 계속 `private`를 보지 않고, `private` 내용은 외부 LLM에 가지 않는다(아래 후속 승인에 따른 명시적 `publish` 정제만 예외). 결정 14는 편집기 경로에만 바뀐다(ADR-0005 3.6).
- 사람 검토 반영: "HITL 적용해야 하는 항목들이 있고, 내가 방향만 제시했을 때, 알아내는 정보들은 굳이 HITL할 필요가 없어보이는데?" 방향만 준 주제 연구의 결과는 사람 검토 없이 인용 게이트가 자동 판정한다. 7판의 고정 목록 제안은 아래 추가 답으로 대체한다(ADR-0005 6.8).
- 외부 검색어: "내보냄 (Recommended)". `export_query` 기본 `true`를 유지한다.

같은 날 사용자가 질문 도구에 직접 답한 추가 결정(승인, 8판 반영):

| 질문 | 사용자 답 원문 | 적용 |
