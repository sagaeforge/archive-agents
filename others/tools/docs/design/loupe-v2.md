# loupe v2 설계: 지식 작업 공간

- 상태: UX 설계안. 코드는 없다. 기준일 2026-11-04. 사용자가 D1, D2, D4, D5, D6, D12, D16, D17을 정했다(12절). Codex 교차 검토 결과를 반영했다(부록 B). 구현은 최소 트랙(11.1절)부터이고, 첫 쓰기는 KB의 ADR-0005가 나온 뒤다.
- 대상: `tools/loupe`. v1 설계(`docs/design/loupe.md`)의 읽기 화면, 그래프, 시간 여행, 주장 단위 출처, 안전한 렌더링은 그대로 두고 그 위에 로그인, 쓰기, 작업 공간을 더한다.
- 입력: 사용자 요구 7건과 결정(2026-11-04), v1 설계, KB 계약 0.3.2(`data-interface-v0.md`, `openapi.yaml`), KB 세션의 first_party 쓰기 답(2026-11-04, KB HEAD `9d5c141`), KB ADR-0001과 ADR-0004 T.1·T.7·T.8, `docs/design/relief-v2.md` 1~2절, `docs/design/kms.md`.
- **쓰기 인터페이스의 주인은 KB다.** KB는 ADR-0005(loupe용 first_party 쓰기 인터페이스)를 쓴다. 그것이 나오기 전까지 경로와 형식은 `[가정-KB]`이고, 쓰기 호출은 어댑터 하나(5.1절)에 가둔다. loupe가 ADR-0005에 바라는 것은 10절에 모았다. 오늘의 inbox와 MCP 경로를 장기 API로 삼지 않는다.
- **Obsidian과 Notion은 UX 참고일 뿐이다**(사용자, 2026-11-04). loupe 데이터가 그 프로그램에서 보일 필요는 없다. 내보내기, 가져오기, 왕복 호환은 범위에서 뺐다(1절).

**바뀐 규칙(D1, 정함).** 사용자가 loupe의 first_party 쓰기를 승인했다(2026-11-04). `CLAUDE.md` 구조 원칙의 "뷰어는 읽기 전용이다"를 "뷰어(loupe)는 KB의 쓰기 인터페이스로 first_party 기록만 쓰고, 수집된 사실을 고치지 않는다"로 고쳤다. 같은 줄의 "파생값을 KB에 되쓰지 않는다"는 그대로다.

| 원칙 | v2에서 |
|---|---|
| 뷰어는 읽기 전용이다 | **바뀌었다.** loupe는 first_party 기록(메모, 문서, 주제)과 조사 요청만 KB 쓰기 인터페이스로 낸다. 외부 사실(주장, 스냅샷, 엔티티)은 고치지 않는다 |
| KB는 계약으로만 읽는다 | 유지. 쓰기도 ADR-0005의 경로로만 한다. DB 파일, inbox 파일, MCP를 UI 쓰기 경로로 쓰지 않는다 [계약: C 1] |
| 파생값을 KB에 되쓰지 않는다 | 유지. 레이아웃, 커뮤니티, 인용 확인 결과, 정리 제안은 브라우저 안에만 둔다. KB는 저장만 하고 점수나 순위를 갖지 않는다 [KB답] |
| 도구끼리 종속되지 않는다 | 유지. loupe는 tower, relief, KMS의 코드를 쓰지 않는다. 에이전트 실행은 KB의 일이다(7절) |

## 1. 목적, 완료 기준, 비범위

KB를 사용자의 지식 작업 공간으로 쓴다. 주제를 중심으로 그래프를 보고, 빠르게 찾고, 블록 편집기로 문서를 쓰고 표로 훑으며, 메모를 주제로 키워 KB에 조사를 요청하고, 비밀은 따로 잠근다.

**완료 기준(v2 전체)**

1. 허용된 Google 계정으로 로그인한 사람만 KB 내용을 읽고 쓴다. 다른 출처의 페이지, 다른 UID, DNS 재바인딩은 읽기도 쓰기도 못 한다.
2. 팔레트에서 이름을 치고 Enter 한 번으로 그 주제, 문서, 메모, 엔티티에 닿거나 새 주제나 문서를 만든다. 한글 조합 중 Enter는 선택하지 않는다.
3. 메모 하나를 버튼 한 번으로 주제로 바꾸면 KB에 조사 요청이 가고, 주제 화면에서 요청 상태, KB가 고른 엔진, 비용, 도착한 것이 보인다. 나간 글은 메모 제목뿐이다.
4. 문서를 쓰고 저장하면 판이 하나 늘고, 손대지 않고 닫으면 판이 늘지 않는다. 저장한 판은 이력에 남고 되돌릴 수 있다.
5. 비밀 값이 검색, 그래프, 브라우저 이력, URL, 로그, 기기 저장소에 남지 않는다. 메모에 키를 넣으면 격리 경고가 뜨고 그 메모는 화면과 실행 취소 이력에서 사라진다.
6. v1 완료 기준 1~5(인용 두 번 클릭, URL 재현, 과거 보기 오인 불가, 그래프 예산, KB 없이 깨지지 않음)를 그대로 지킨다.

| 비범위 | 이유 |
|---|---|
| Obsidian, Notion과의 데이터 호환(내보내기, 가져오기, 보관함 왕복, 머리말) | UX 참고일 뿐이다(사용자, 2026-11-04) |
| 외부 주장, 스냅샷, 엔티티 이름의 편집 | 수집 경로의 게이트를 지나야 한다 [계약: C 6.1]. 틀린 것은 제보 요청으로 보낸다 |
| 수집 방식, 엔진, 예산의 선택 | KB의 일이다(D4, ADR-0004) |
| 완전 삭제(`kb redact`), 비밀 격리 해제(`kb secret release`) | TTY 전용이다 [KB답]. loupe는 명령을 안내만 한다 |
| 첨부 파일, 이미지 업로드 | KB에 첨부가 없다 [KB답] |
| 블록 단위 링크와 백링크 | 계약 v1에 없다 [계약: C 6.3] |
| 실시간 공동 편집(Yjs) | 사용자 1명이다. 에이전트 세션과의 충돌은 낙관적 잠금으로 다룬다(5.3절) |
| 휴대 기기 화면 | 데스크톱 먼저. 태블릿 메모만 9절에 둔다 |

**호환 요구를 뺀 덕에 단순해진 것.** 본문 형식은 KB가 Markdown을 저장하므로 Markdown 그대로다. 다만 다음이 없어진다.

- 머리말(front matter)을 쓰지도 읽지도 않는다. 제목과 속성은 기록 필드(`title`, `props`)뿐이다.
- 링크는 `[[id]]` 하나다. 저장 본문에 `[[제목]]` 표기를 남길 이유가 없고, 제목과 ID를 오가는 변환표, 이름 바꾸기 추적이 필요 없다.
- 데이터베이스 보기 블록의 정의는 loupe 전용 형식이어도 된다. Obsidian Bases나 Dataview와 맞출 필요가 없다.
- 가져오기의 충돌 처리, 비밀 검사, 링크 해결 경로가 통째로 없다. 시험 대상이 한 갈래 준다.
- 편집기 기준에서 "Obsidian이 읽는 Markdown 방언"이 빠진다. 기준은 KB 본문 왕복과 읽기 화면(remark)과의 일치뿐이다.

## 2. 정보 구조와 이동 (A)

### 2.1 객체

오늘 KB의 first_party 타입은 `Note`, `Decision`, `Artifact`, `Learning`, `Project`, `Record`다. `Memo`와 `Topic`은 아직 없고 ADR-0004가 `Topic`과 생애 주기를 더했다 [KB답].

| 객체 | KB 표현 | 만드는 곳 | 비고 |
|---|---|---|---|
| 주제 | first_party 기록 `type: Topic`. `title`이 라벨, `body`가 범위 설명, `props`에 `aliases`, `domain`, `parent`, `exclude`, `promoted_from`. 노드 ID `e:topic:<slug>`, 상태 `active`, `paused`, `retired` [ADR-0004] | 팔레트, 메모 승격 | ID는 KB가 정한다. 만들 때 ID를 보내지 않는다 [KB답]. `collect_mode`는 loupe가 쓰지 않는다(D4) |
| 문서 | first_party 기록. 종류는 ADR-0005 `[가정-KB]`. `body_format=markdown` | 팔레트, 슬래시 명령, 메모 옮기기 | `[[id]]`는 `LINKS_TO`다 [KB답] |
| 메모 | first_party 기록. 종류는 ADR-0005의 `Memo`, 그전에는 ADR-0004가 적은 `Note` `[가정-KB]` | 빠른 메모 | 제목 규칙 2.5절. 자동 삭제 없음 |
| 데이터베이스 보기 | 문서 안의 보기 블록(` ```loupe-view `), loupe 전용 형식 | 슬래시 명령 | 새 종류가 필요 없다(4.3절) |
| 엔티티, 주장, 출처 | 외부 데이터 | KB 수집 | v1 화면 그대로. 읽기 전용 |
| 조사 요청 | 티켓 `t-…`. 상태 `queued`, `in_progress`, `done`, `unanswerable`, `blocked_policy` [KB답] | 주제 만들기, "조사 다시 요청" | 비슷한 요청은 KB가 합친다(7.2절) |
| 비밀 | KB에 없다. KMS | KMS | 8절 |

| 연결 | 표현 | 화면 |
|---|---|---|
| 문서, 메모 → 엔티티 | 본문 `[[e:…]]` → `LINKS_TO` [KB답] | 엔티티 페이지의 "노트 백링크" [v1: 2절] |
| 문서 → 주제 | `[[e:topic:…]]` → `LINKS_TO` | 주제 화면의 문서 목록 |
| 주제 → 승격한 메모 | `Topic -LINKS_TO-> 메모`, `props.role=promoted_from` [ADR-0004] | 메모의 주제 칩, 주제 머리 |
| 주제 ↔ 수집된 엔티티, 주장 | KB가 다는 `IN_TOPIC` [ADR-0004] | 주제 지도, "도착한 것" |
| 문서 → 주장 | `[[c-…]]` 인용 블록 → `LINKS_TO` `[가정-KB]` | v1 주장 카드 |

### 2.2 화면 배치

| 구역 | 내용 |
|---|---|
| 왼쪽 레일 | 홈 그래프, 주제, 문서, 데이터베이스, 메모, 변경, 상태. 맨 아래에 비밀(별도 창을 연다, 8절) |
| 상단 | 탭 줄, 연결 상태와 `data_as_of`, 찾기 단추(`Ctrl+Space`), 잠그기 단추. 과거 보기일 때 v1의 호박색 띠와 테두리 [v1: 4절] |
| 본문 | 탭 하나. 각 탭이 v1처럼 hash URL 하나를 가진다 |
| 오른쪽 맥락 패널 | 주제면 요청 상태와 도착한 것, 문서면 백링크, 개요, 판 목록, 엔티티면 v1 요약 |

- 탭은 Obsidian 방식의 UX다. 탭 하나는 URL 하나이고 링크 복사는 활성 탭의 URL이다 [v1: 1절 완료 기준 2]. 열린 탭 목록은 `sessionStorage`에 ID만 둔다.
- 세로 분할 2칸은 나중 단계다(11.2절). 문서를 쓰며 출처를 보는 쓰임새가 분명하지만 최소 트랙에 필요하지 않다.
- **URL과 탭 제목에 본문을 싣지 않는다.** URL에는 ID와 v1 화면 파라미터만 있다. first_party 기록을 연 탭의 `document.title`은 "loupe · 문서", "loupe · 메모"처럼 종류만 적는다. 브라우저 이력은 제목을 저장하고, 메모 제목은 첫 줄이라 비밀이 들어갈 수 있기 때문이다. 외부 엔티티 탭은 v1처럼 라벨을 쓴다.

| 버린 안 | 이유 |
|---|---|
| 자유 도킹(dockview, Golden Layout류) | 배치 상태가 URL로 재현되지 않고, 쓰임에 비해 비싸다 |
| Notion식 페이지 트리 | KB는 그래프다. 위계는 주제(`PART_OF`)와 링크로 표현한다 |

### 2.3 홈: 주제 지도

홈은 **주제와 그 1홉 이웃만** 그린다. 주제는 크게, 엔티티는 원, 문서는 네모, 메모는 마름모로 그린다. 조사 요청이 진행 중인 주제는 점선 테두리다. 주제를 고르면 오른쪽 패널에 요청 상태와 새로 도착한 것이 나오고, 두 번 누르면 깊이 1~2의 로컬 그래프로 들어간다.

- 데이터는 v1의 이웃 경로(`/v1/nodes/{id}/neighbors`)를 주제마다 부른다 [계약: C 4.6]. 주제가 많아지면 일괄 경로가 필요하다(10절 N11).
- 렌더, 오버레이, worker 레이아웃, IndexedDB 좌표 캐시는 v1 Phase 2 코드다 [v1: 6절]. 캐시에는 ID와 좌표만 있다.
- 전체 개요(`/graph`)는 레일의 "그래프" 아래에 남는다.

### 2.4 팔레트

v1 팔레트(cmdk 1.1.1, 서버 검색, NFC, 150 ms 디바운스)를 넓힌다 [v1: 2절].

|---|---|---|
| 주제 | 이름과 별칭 일치, 요청 상태 칩 | `/v1/search`. 주제의 시드어는 별칭 표에 들어가 한영 어느 쪽으로도 찾힌다 [ADR-0004] |
| 문서, 메모 | 제목과 본문 문단 | `/v1/search`의 `record`, `passage` [계약: C 4.8] |
| 엔티티 | v1 그대로 | `/v1/search` |
| 만들기 | "새 주제 '…' 만들고 KB에 조사 요청", "새 문서 '…'", "메모로 저장" | 입력값으로 만든다. 항상 맨 아래 |
| 이동, 시간 | v1 그대로 | |

- **키.** `Ctrl+Space`가 기본이다. 일부 IME 설정은 `Ctrl+Space`를 입력기 전환에 써서 브라우저에 오지 않을 수 있으므로 [가정] v1의 `Ctrl+K`를 대체 키로 남기고 두 키를 함께 적는다. `/`는 편집 영역 밖에서만 연다.
- **한글.** 조합 중(`isComposing` 또는 `keyCode 229`)의 Enter와 화살표는 처리하지 않는다. 결과 선택은 조합이 끝난 뒤에만 한다.
- **Enter.** 첫 항목으로 간다. 만들기 항목은 이름이나 별칭이 같은 주제가 없을 때만 첫 항목이 된다.
- **입력값의 행방.** 팔레트 입력은 검색 요청(`/kb/v1/search?q=`)에만 쓰이고 URL, 이력, `localStorage`에 남지 않는다. `loupe serve`는 요청 경로와 쿼리를 기록하지 않는다 [v1: 10절]. 팔레트의 "만들기"로 만든 주제에서 KB로 가는 조사 요청 글은 7.3절의 확인을 지난다. 팔레트 입력이 그 확인 없이 조사 요청으로 가지 않는다.
- 전문 검색 화면(`/search?q=`)은 v1처럼 질의를 URL에 둔다. 브라우저 이력에 남으므로 질의가 비밀 형태(5.5절 패턴)면 URL에 쓰지 않고 화면 안 상태로만 둔다 `[가정]`.
- **입력 분류.** 팔레트 입력은 검색 요청을 보내기 전에 저장 전 검사(5.7절)를 지난다. 비밀 모양이면 검색하지 않고 "＋ 보안 정보로 넣기(KMS)"를 맨 위에 둔다.
- 비밀 값과 이름은 팔레트에 없다. "비밀 창 열기"와 "보안 정보로 넣기" 명령만 있다(8절).

### 2.5 메모의 제목

KB 기록은 `title`과 `body`가 둘 다 필수다 [KB답].

- **첫 줄이 제목이다.** 첫 줄의 앞뒤 공백과 Markdown 머리 기호(`#`, `-`, `>`)를 지우고 60자(문자소 기준)에서 자르며, 잘렸으면 `…`를 붙인다. 본문은 메모 전체다.
- 첫 줄이 비었거나 기호뿐이면 `메모 2026-11-04 09:14`(KST)를 쓴다.
- 카드에 계산된 제목을 흐리게 보이고 누르면 고칠 수 있다. 고친 제목은 그 뒤로 자동 계산하지 않는다(`props.title_locked`) `[가정]`.
- 메모를 주제로 승격하면 이 제목이 주제 이름이자 범위 설명이 된다(7.1절).

### 2.6 시간 여행과 쓰기

v1의 시간 기준은 그대로다 [v1: 4절]. **과거 보기나 시점 고정에서는 편집할 수 없다.** 편집기는 읽기 모드로 열리고 "현재로 돌아가 편집" 단추를 띄운다. 과거 판을 고치는 길은 판 목록의 "이 판으로 되돌리기"뿐이고 그것은 현재에 새 판을 만든다(5.3절).

## 4. 편집기와 데이터베이스 컴포넌트 (C)

### 4.1 판단 기준

1. **원본이 KB의 Markdown이다.** KB 본문은 `body_format=markdown`(또는 `text`)이다 [KB답]. 블록 JSON을 원본으로 삼는 편집기는 저장마다 변환 손실이 판에 쌓인다.
2. **손대지 않은 문서는 보내지 않는다.** 저장 여부는 직렬화 결과의 비교가 아니라 편집 트랜잭션 유무로 정한다. 그래서 왕복이 바이트 단위로 같지 않아도 열고 닫기만 한 문서에 판이 생기지 않는다. 고친 문서에서는 손대지 않은 블록의 바이트가 바뀌는 비율을 v2-0에서 잰다. AST가 같다는 것만으로는 같은 Markdown이 보장되지 않는다(Codex 7).
3. **한글 IME.** 웹 검색으로는 후보별 한국어 결함 보고를 찾지 못했다 [출처: 부록 C]. 헤드리스 시뮬레이션과 **실제 Windows 한국어 IME 확인** 둘 다 통과해야 확정이다.
4. **읽기 화면과의 일치.** loupe는 읽기에 unified 11.0.5, remark-parse 11.0.0, remark-gfm 4.0.1, rehype-sanitize를 쓴다 [v1: 9절]. 같은 파서를 쓰면 `[[id]]`와 GFM 해석이 한 곳에 있다.
5. 라이선스, 크기, 유지 상태. 아래 후보 전부 설치 스크립트가 없다 [측정: `npm view <패키지> scripts`]. 인증 파일과 셸 설정을 건드리는지는 v2-0에서 잠금 파일 기준 소스 감사로 다시 본다. 크기는 압축 전 패키지 크기가 아니라 **운영 빌드의 gzip 증가분**으로 판정한다.
6. loupe의 7일 릴리스 대기 규칙을 지킨다 [v1: 머리말].

**M0a의 Tiptap 작업과 완료 조건.**

1. **코드 펜스 직렬화.** 펜스 길이를 코드 안의 가장 긴 백틱 연속보다 하나 길게(최소 3) 고르도록 직렬화를 고친다. 물결 펜스도 같은 규칙. 완료: `tilde-code-fence`와 내부 백틱 3·4·5개 표본이 재파싱 뒤 같은 코드 블록 구조와 내용.
2. **`[[id]]` 위키 링크 노드.** 사용자 정의 인라인 노드가 `[[id]]`를 파싱하고 **이스케이프 없이** 그대로 직렬화한다. 화면은 4.4절의 칩. 완료: 코퍼스의 위키 링크 표본 전부가 바이트 일치이고, 같은 본문을 읽기 화면의 remark 플러그인이 같은 ID 목록으로 읽는다.
3. **왕복 실패 감소.** 같은 36개 코퍼스에서 "그 외 변경"을 **17개에서 8개 이하로** 줄이고, 재파싱 구조가 원문과 달라지는 표본은 **0개**로 만든다. 남는 변경은 의미가 같은 형식 차이(목록 기호, 표 정렬 등)만이고 표본별 목록을 남긴다. 4.1절 2번(손대지 않은 문서는 보내지 않음)이 있으므로 이 수치는 고친 문서에만 걸린다.
4. **실제 한글 IME.** 사용자가 Windows 11 Microsoft 한국어 IME(두벌식)로 Chrome에서 스파이크의 13개 사례를 손으로 친다. **이것이 유일한 진짜 IME 근거다.** 최종 글자, 커서, 중복·누락, 조합 중 Enter·Ctrl+Enter·Backspace, 확정 뒤 실행 취소, 블록 이동을 보고 OS·브라우저·IME 판을 남긴다.
5. 운영 빌드 gzip: loupe에 넣은 뒤 편집기 청크의 gzip 증가분을 재고 편집 화면에서만 지연 로드되는지 `check-dist`로 막는다.
6. 4.5절의 악성 붙여넣기 묶음과 Trusted Types 위반 수.

### 4.4 링크와 본문 규칙

`[[id]]`만 `LINKS_TO`가 되고 대상은 공개 ID여야 한다 [KB답]. **저장 본문의 모든 `[[...]]`는 해결된 ID다.**

| 쓸 때 | 저장 본문 | 화면 |
|---|---|---|
| `[[`를 치면 팔레트와 같은 검색이 뜨고 고른 항목이 들어간다(Obsidian UX) | `[[e:product:claude-code]]` | 대상의 현재 라벨로 그린 칩 |
| 고르지 않고 닫았다 | `[[`, `]]` 없이 글자 | 점선 밑줄 "링크 아님" |
| `[[c-…]]` 단독 줄 | 그대로 | v1 주장 카드 `[가정-KB]` |
| ` ```loupe-view ` | 그대로 | 데이터베이스 보기 |

- 별칭 표기 `[[id|라벨]]`은 KB가 받는지 모른다 `[가정-KB]`. 받기 전에는 `[[id]]`만 쓰고 라벨은 읽을 때 붙인다.
- **크기.** 본문이 64 KB를 넘으면 KB가 `raw/fp`로 옮긴다 [KB답]. 편집기 바닥에 크기를 보이고 48 KB에서 노란 칩, 64 KB에서 "큰 본문 저장소로 간다. 나눠 쓰기를 권한다"를 띄운다.
- **첨부 없음** [KB답]. 이미지를 붙여 넣거나 끌어 놓으면 받지 않고 "KB는 첨부를 저장하지 않는다"를 띄운다.

### 4.5 편집기 안전

v1의 읽기 sanitize는 편집기의 안전 근거가 아니다(Codex 3). 편집기는 사용자 붙여넣기와 다른 작성자(`f:agent:…`)의 본문을 DOM으로 만든다.

| 경로 | 규칙 |
|---|---|
| 스키마 | 편집기 스키마는 허용 목록이다: 문단, 머리글, 목록, 할 일, 인용, 코드 블록, 표, 구분선, 강조, 코드, 링크, `[[id]]` 칩, 주장 인용 블록, 보기 블록. 나머지 노드와 표시는 글자로 떨어진다 |
| raw HTML | Markdown 안 HTML은 노드로 만들지 않고 글자로 보인다(v1 `remark-rehype` raw 끔과 같은 방침) |
| 링크 | `href`는 `http`, `https`만. 나머지는 링크를 지우고 글자만 남긴다. 렌더는 v1 외부 링크 규칙(`noopener noreferrer`, `no-referrer`) [v1: 9절] |
| 붙여넣기 | HTML 붙여넣기는 ProseMirror 스키마 파서만 지나고, 그 전에 모든 속성을 지운다(`href`만 위 규칙으로 남김). `img`, `svg`, `iframe`, `style`, `script`, `form`은 버린다. 평문 붙여넣기는 Markdown으로 파싱한다 |
| 노드 뷰 | 칩, 주장 카드, 보기 블록은 React 컴포넌트이고 값은 텍스트 자식으로만 넣는다. `innerHTML`, `dangerouslySetInnerHTML` 금지는 v1 ESLint 규칙 그대로 [v1: 9절] |
| CSP | v1 정책 유지(`script-src 'self'`, `connect-src 'self'`, `default-src 'none'`) [v1: 9절]. 쓰기도 같은 출처 `kb-write/`라 넓히지 않는다 |
| Trusted Types | `require-trusted-types-for 'script'`를 목표로 한다. ProseMirror 클립보드 파서가 분리된 요소에 `innerHTML`을 쓰므로 소독 뒤 통과시키는 이름 있는 정책 하나가 필요할 수 있다 `[가정]`. 적용 가능성과 위반 수를 v2-0에서 잰다. 불가하면 이유를 남기고 CSP와 스키마로 막는다 |

**시험(첫 쓰기 전, 11.1절 M1).** 악성 붙여넣기 묶음(`<script>`, `onerror`, `javascript:`·`data:` 링크, SVG, CSS 표현식, 중첩 `iframe`)과 악성 KB 본문(다른 작성자가 쓴 것으로 kb-mock에 넣음)을 편집기에 넣고 대화상자 0, 페이지 오류 0, 다른 출처 요청 0, CSP와 Trusted Types 위반 0, 저장 본문에 허용 밖 노드 0을 단언한다.

## 5. 쓰기 모델 (D)

오늘 KB의 사실 [KB답]: HTTP는 GET과 HEAD뿐이다(K `serve/http.py:659`, A:673). 원장은 `record.put`, `tombstone`, `redact`를 덧붙인다. 만들기는 ID 없이 `idempotency_key`, 편집은 ID와 필수 `expected_version`. 같은 내용은 새 판을 만들지 않는다. 묘비는 CLI 전용, 완전 삭제는 TTY의 `kb redact`뿐이다. 필드는 `id`, `type`, `title`, `body`, `body_format`(`markdown`, `text`), `sensitivity`, `retention`, `props`, `links {rtype, dst}`, `expected_version`이고 `title`과 `body`가 필수, `dst`는 공개 ID다. 작성자는 서버가 정하고 `f:user`, `f:agent:<세션>`으로 보인다.

HTTP 경로, 묘비의 HTTP화, 오류 코드, 응답 모양은 ADR-0005 전까지 `[가정-KB]`다.

### 5.1 경로

| 안 | 내용 | 판단 |
|---|---|---|
| **A (결정)** | ADR-0005가 정할 HTTP 쓰기. loupe 가정은 쓰기 전용 Unix 소켓과 `loupe serve`의 `/kb-write/*` 프록시 `[가정-KB]` | 응답을 화면에 보일 수 있고 읽기 소켓과 권한을 나눈다 |
| B | `loupe serve`가 `kb put -f`를 부른다 | URL 입력이 argv로 간다 [v1: 7.2절]. 비 TTY라 작성자가 `agent:cli`다 |
| C, D | inbox 파일, tower MCP `kb_put` | 응답이 없거나 UI 경로가 아니다. KB가 장기 API로 쓰지 말라고 했다 [KB답] |

- 브라우저는 같은 출처의 `kb-write/`만 부른다. `loupe serve`는 쓰기에 6절의 세션과 Origin 검사를 모두 요구한다.
- 모든 쓰기 호출은 `src/data/write.ts` 하나를 지난다. 이 어댑터가 필수 필드(`title`, `body`), `[[...]]`의 공개 ID 여부, 민감도 선택지(`internal`, `public`)를 보내기 전에 확인한다. ADR-0005가 나오면 이 파일과 부록 A만 바뀐다.

### 5.2 저장: 최소 트랙은 온라인 수동 저장

| 항목 | 최소 트랙(M1~M2) | 나중(11.2절) |
|---|---|---|
| 언제 | `Ctrl+S`, 저장 단추, 메모의 `Ctrl+Enter`. 저장 안 한 채 탭을 닫으면 경고 | 자동 저장. 아래 조건 |
| KB 끊김 | 저장 단추가 막힌다. 글은 탭 메모리에만 있다 | 기기 안 초안(5.4절) |
| 만들기 | ID 없이 `idempotency_key = <초안 UUID>:create` [KB답]. 응답 ID를 받은 뒤부터 편집 | |
| 편집 | ID + `expected_version`(마지막으로 받은 판) [KB답]. 키 `<기록 ID>:<expected_version>:<본문 sha256 앞 16자>` | |
| 저장 칩 | 저장 안 됨 / 저장 중 / 저장됨 v7 / 변경 없음 / 반영 대기(이유) / 저장 거절 / 비밀 격리 / 충돌 | 기기에만 저장됨 |

**저장 직렬화(Codex 4).**

- 한 기록에 진행 중인 저장은 하나다. 저장 중에 또 저장하면 마지막 내용 하나만 대기열에 남기고, 앞 저장의 응답(새 `version`)을 받은 뒤 그 판을 `expected_version`으로 보낸다.
- 응답을 못 받았다(시간 초과, 연결 끊김)면 **같은 키로** 다시 보낸다. KB는 같은 키에 첫 응답을 돌려준다 [계약: C 6.1]. 그래서 첫 요청이 원장에 들어갔어도 판이 둘 생기지 않는다.
- 내 이전 저장이 원장에 들어갔는데 응답을 잃은 뒤 내용을 더 고쳐 새 키로 보내면 `expected_version`이 어긋난다. 충돌 응답의 현재 판이 내가 마지막으로 보낸 본문 해시와 같고 작성자가 `f:user`면 내 저장으로 보고 그 판 위에 다시 보낸다. 아니면 5.3절의 충돌 화면이다.

**자동 저장을 켤 때의 조건(나중).** 원장은 덧붙이기만 하므로 판은 지울 수 없다. 저장 뒤에 합쳐도 공간을 되찾지 못한다(Codex 4). 그래서 자동 저장은 **모든 계기(입력 멈춤, 초점 이탈, 탭 숨김)에 같은 최소 간격**(30초 `[가정]`)을 적용하고 탭 닫기만 예외로 즉시 보낸다. 판 수 한도는 ADR-0005의 한도 항목이다(N8).

### 5.3 실행 취소, 되돌리기, 충돌, 삭제

- **실행 취소.** 편집기 안의 `Ctrl+Z`는 편집기 이력이다. 저장된 판을 되돌리지 않는다.
- **판 되돌리기.** 판 목록(`/v1/nodes/{id}/history`)에서 판을 고르면 비교해 보이고 "이 판으로 되돌리기"는 그 내용으로 새 판을 만든다 [계약: C 6.4]. 판마다 작성자를 적는다.
- **충돌.** `expected_version`이 어긋나면 [KB답] 편집기를 막지 않고 비교 띠를 띄운다. 기준 판, 내 변경, 다른 쪽 변경을 블록 단위로 나란히 보이고 블록마다 "내 것", "저쪽", "둘 다"를 고른다. 결과는 최신 판을 `expected_version`으로 삼아 저장한다. 충돌 응답이 본문을 주지 않으면 한 번 더 읽는다 `[가정-KB]`. 에이전트 세션(`f:agent:…`)이 같은 문서를 고친 경우가 대표다. 같은 브라우저의 탭 둘은 BroadcastChannel로 "다른 탭에서 편집 중"을 미리 알린다.
- **삭제는 묘비뿐이다.** "보관"은 `tombstone`이고 `status=dead`가 된다 [KB답, 계약: C 2.3]. 오늘 묘비는 CLI 전용이라 **최소 트랙에는 보관 단추가 없다.** 대신 "보관하려면 터미널에서" 안내와 명령 복사만 둔다. HTTP 묘비(N4)가 생기면 단추를 연다. 휴지통 화면은 `status=dead`인 first_party 기록이고 복원의 뜻은 ADR-0005가 정한다.
- **완전 삭제는 터미널에서.** "완전 삭제…"는 설명 상자만 연다: "KB는 TTY의 `kb redact <id>`로만 지운다. 되돌릴 수 없다." loupe는 실행하지 않는다.

### 5.4 기기 안 초안(나중)

Codex 1이 지적했듯 검사 전 내용을 IndexedDB에 쓰면 뒤에 지워도 "남지 않는다"를 지킬 수 없다. 그래서:

- **최소 트랙에는 기기 저장 초안이 없다.** 끊긴 동안의 글은 탭 메모리에만 있고 탭을 닫으면 경고 뒤 잃는다.
- 나중에 초안을 둔다면 **KB와 같은 규칙의 로컬 선검사를 통과한 내용만** 디스크에 쓴다. 규칙 집합은 KB가 내야 한다(N13). 선검사에 걸리면 디스크에 쓰지 않고 5.5절 경고를 미리 띄운다.
- 초안 삭제는 **응답(ACK) 단위**다. 초안에 로컬 판 번호를 두고, 응답이 온 판 번호가 초안의 현재 판과 같을 때만 지운다. 응답 뒤에 더 고친 내용은 남는다(Codex 4).
- 재시작 뒤 재전송은 초안에 저장한 멱등 키 그대로 보낸다. 같은 키라 이미 들어간 저장이 두 번 되지 않는다.

### 5.5 비밀 검사

KB는 비밀을 거절하지 않는다. 규칙에 맞으면 기록을 `sensitivity=secret`으로 격리해 저장하고 읽기에서 숨기며 경고 `secret_detected:<규칙 ID>`를 돌려준다. 해제는 TTY의 `kb secret release <id>`뿐이다 [KB답].

| loupe 동작 | 이유 |
|---|---|
| 경고 카드: "KB가 이 기록을 비밀로 격리했다(규칙 ID)". 값을 다시 보이지 않는다 | 무엇이 일어났는지 안다 |
| 그 기록을 화면, 탭, 백링크, 데이터베이스 행에서 내린다. 열린 탭은 "격리됨" 자리로 바뀐다 | 다시 읽을 수 없고, 화면에 남은 사본도 내린다 |
| **다시 보내지 않는다.** 그 편집기의 저장을 멈춘다 | 원장에 비밀 판이 더 쌓인다 |
| **편집기 상태를 버린다**: 그 편집기의 ProseMirror 상태와 실행 취소 이력을 새 빈 상태로 바꾸고, 대기열의 저장과 팔레트 최근 항목에서 그 ID를 지운다 | `Ctrl+Z`로 값이 돌아오지 않는다(Codex 1) |
| 안내: "키와 개인 정보는 KMS에 넣는다(`kms key add`). 격리를 풀려면 터미널에서 `kb secret release <id>`" | 해제와 KMS 입력은 사람의 TTY 일이다 |
| **보존 설명**: "격리된 판은 KB 원장에 남는다. 읽기에서 숨겨질 뿐 지워지지 않는다. 값을 원장에서 없애려면 터미널에서 `kb redact <id>`" | 원장은 덧붙이기만 한다 [KB답] |
| 기록 ID와 시각만 알림 목록에 남긴다 | 나중에 터미널에서 다루게 |

- 격리 전에 값이 지난 곳: 브라우저 메모리, 같은 출처 요청 본문(`loupe serve`는 본문을 기록하지 않는다), KB 원장. 브라우저 이력과 URL에는 없다(2.2절). 탭 제목에도 없다.
- 이 절은 **뒷받침**이다. 첫 방어는 5.7절의 입력 분류와 저장 전 검사다. KB 격리가 뜬다는 것은 저장 전 검사가 놓쳤거나 규칙 판이 어긋났다는 뜻이므로, 격리 카드는 "저장 전 검사가 놓친 것"이라고 함께 적고 규칙 판을 상태 화면에 보인다.

### 5.6 민감도와 `private`

`sensitivity`는 `public`, `internal`, `private`, `secret`이다. HTTP 읽기는 `internal`까지이고 `private`는 HTTP로 나가지 않는다 [KB답, 계약: C 2.8].

- **loupe는 `private` 기록을 만들지 않는다.** 만들면 저장 직후 다시 읽을 수 없어 편집, 충돌 비교, 판 목록이 깨진다. 선택지는 `internal`(기본)과 `public`이다. 어댑터가 다른 값을 막는다.
- `private`가 필요한 글은 "터미널에서 쓰기" 안내로 보낸다.
- 다른 경로에서 `private`로 바뀐 기록은 404가 되고 열린 탭은 "볼 수 없게 됨"이 된다.
- 이 결정을 바꾸려면 KB가 `private` 읽기 경로를 정해야 한다(사용자 결정 D11).

### 5.7 입력 때의 분류 (D12)

사용자 결정: 비밀은 KB 쪽에서 뒤늦게 알게 되는 것이 아니라 **넣을 때 loupe 화면에서 가른다.** 정보를 넣을 때마다 "일반"과 "보안 정보" 중 하나를 고르는 분명한 조작이 있다.

| 분류 | 가는 곳 | 화면 |
|---|---|---|
| 일반 | KB first_party 기록 | 지금까지의 메모, 문서, 주제 |
| 보안 정보 | **KMS뿐.** KB에는 값이 가지 않는다 | 비밀 창(8.3절)의 "새 보안 정보" 양식 |

**넣는 곳마다의 조작**

| 곳 | 조작 | 보안 정보를 고르면 |
|---|---|---|
| 빠른 메모 | 입력칸 위의 두 칸 전환 `[일반 \| 보안 정보]`. 기본은 일반. `Alt+S`로 바꾼다 | 입력칸을 비우고 잠그며 "보안 정보는 비밀 창에서 넣는다 → 비밀 창 열기"를 보인다. 이미 친 글은 넘기지 않고 지운다(실행 취소 이력 포함). 비밀 창에서 다시 붙여 넣는다 |
| 팔레트 | 만들기 묶음에 "＋ 보안 정보로 넣기(KMS)". 입력이 비밀 모양이면 이 항목이 맨 위로 온다 | 팔레트 입력을 지우고 비밀 창을 연다. 팔레트 글은 넘기지 않는다 |
| 문서 | 슬래시 명령 `/보안 정보`가 **보안 정보 블록**을 넣는다. 블록에는 이름 칸과 "비밀 창에서 값 넣기" 단추만 있다 | 본문에는 참조만 남는다: ` ```loupe-secret-ref ` 블록에 KMS 항목 이름. 값은 없다. 읽기 화면에서는 자물쇠 칩 "보안 정보: <이름> · 비밀 창에서 보기"로 그린다 |
| 데이터베이스 속성 | 속성 유형 "보안 정보 참조". 셀에는 이름만 | 문서와 같다 |
| 주제 대화상자 | 없다. 주제 글은 KB로 가는 글이다(7.3절). 비밀 모양이면 저장 전 검사가 멈춘다 | |

- **값을 창 사이로 넘기지 않는다.** loupe 본 출처와 비밀 창은 메시지를 주고받지 않는다(8.1절). 이미 친 값을 옮기는 길은 사용자가 비밀 창에 다시 붙여 넣는 것뿐이다.
- 보안 정보 블록의 **이름은 KB로 간다.** 이름은 값이 아니지만 문서 본문이라 KB 검색에 잡힌다. 이름 칸 아래에 "이 이름은 KB에 저장된다"를 적는다. KB는 KMS 참조 문자열을 지식으로 투영하지 않는다 [ADR-0004 T.1].

**저장 전 검사.** 일반으로 분류한 입력도 보내기 전에 브라우저 안에서 **KB와 같은 규칙**으로 검사한다.

- 규칙 집합은 KB가 판 번호를 붙여 낸다(N13). loupe는 같은 판을 받아 쓰고, 판이 KB와 다르면 칩으로 알린다. N13이 나오기 전에는 첫 쓰기(M1)를 시작하지 않는다.
- 검사 대상: 메모와 문서의 제목과 본문, 속성 값, 주제 대화상자의 모든 칸, 팔레트 입력(검색 요청을 보내기 전). 팔레트 입력이 걸리면 **검색 요청을 보내지 않고** "비밀처럼 보인다. 검색하지 않았다"와 "보안 정보로 넣기"를 보인다.
- 걸리면 저장을 멈추고 그 구간을 가린 채 표시한다(규칙 ID만, 값은 다시 보이지 않음). 고르는 길은 셋이다.

| 선택 | 결과 |
|---|---|
| 보안 정보로 바꾸기 | 그 구간을 본문과 편집기 실행 취소 이력에서 지우고, 문서라면 그 자리에 보안 정보 블록을 넣고, 비밀 창의 "새 보안 정보"를 연다. 값은 사용자가 다시 붙여 넣는다 |
| 고치기 | 저장하지 않고 편집으로 돌아간다 |
| 일반으로 저장 | "비밀 아님"을 확인하고 보낸다. KB 검사가 같은 규칙이므로 격리될 수 있음을 함께 적는다. 이 선택은 그 구간에만 적용되고 기억하지 않는다 |

- 검사는 브라우저 안에서만 돈다. 값이 서버로 가기 전에 멈추는 것이 목적이다. KB 검사(5.5절)는 그대로 남는 뒷받침이다.
- 규칙이 모든 비밀을 잡지는 못한다. 사람이 고른 분류가 첫째이고 검사는 둘째다.

## 6. 로그인 (D6, D17)

사용자 결정(2026-11-04): loupe에 로그인을 두고, **신원은 Google 계정**이다. 허용 계정은 하나이고 Google의 `sub`로 가린다. loupe 세션은 유휴 1시간이고 갱신이 없다. 시간이 지나면 다시 Google로 로그인한다. 로컬 토큰만으로는 UID를 가르지 못한다는 Codex 1차 3의 지적이 이것으로 닫힌다. 같은 UID는 여전히 막지 못한다(6.7절).

### 6.1 흐름

OIDC authorization code + PKCE(S256), loopback 리디렉션이다. 토큰 교환은 `loupe serve`가 한다. 브라우저는 Google 토큰을 보지 않는다.

1. 로그인 화면은 "Google로 로그인" 단추 하나다. **loupe는 어떤 암호도 받지 않는다**(6.5절 비상 경로 제외). 단추는 `POST /auth/google/start`를 부른다(6.3절 검사). 서버는 `login_id`, `state`(256비트), `nonce`(256비트), PKCE `code_verifier`를 만들어 메모리에 5분 둔다. 응답은 Google 인가 주소와 `login_id`, 그리고 이 탭만 아는 `login_secret`(256비트)이다. SPA는 `login_secret`을 `sessionStorage`에 두고 같은 탭에서 인가 주소로 이동한다.
2. 인가 요청: `response_type=code`, `scope=openid`(이메일도 필요 없다), `redirect_uri=http://127.0.0.1:4812/auth/google/callback`, `state`, `nonce`, `code_challenge`, `code_challenge_method=S256`, `prompt=select_account`, `login_hint`=허용 계정 이메일. `access_type=offline`을 보내지 않으므로 **refresh token이 없다**.
3. Google이 콜백으로 돌려보내면 서버는 `state`가 살아 있는 `login_id`의 것인지 보고(한 번 쓰면 지운다), `code`를 `code_verifier`와 함께 토큰 끝점에서 바꾼다. ID 토큰은 서명(Google JWKS), `iss`(`https://accounts.google.com` 또는 `accounts.google.com`), `aud`(이 클라이언트 ID), `exp`, `iat`, `nonce`(이 `login_id`의 값, 한 번만), **`sub`가 허용 값과 같음**을 확인한다 [출처: Google OpenID Connect 문서]. 이메일은 표시용이고 판정에 쓰지 않는다. Google 액세스 토큰과 ID 토큰은 확인 뒤 버리고 저장하지 않는다.
4. 콜백은 성공이든 실패든 `/#/auth/finish`로 303 이동한다. URL에 코드도 세션도 싣지 않는다. SPA는 `sessionStorage`의 `login_secret`과 `login_id`로 `POST /auth/google/finish`를 부르고, 서버는 콜백이 끝난 `login_id`이고 `login_secret`이 맞을 때만 loupe 세션을 내준다. 다른 탭이나 다른 브라우저가 시작한 로그인에 남의 코드를 끼워 넣는 로그인 CSRF가 여기서 끝난다.
5. 세션: 256비트 임의값, 서버 메모리에 해시만, 응답 본문으로 받아 `sessionStorage`에 두고 `Authorization: Bearer`로 보낸다. **쿠키를 쓰지 않는다** [relief: 1.2절, 2.3절]. 유휴 1시간, 최대 12시간 `[가정]`. 연장 토큰이나 조용한 재로그인은 없다. 만료되면 로그인 화면으로 가고, 저장 안 한 글은 그 탭 메모리에 남아 다시 로그인한 뒤 저장할 수 있다. `loupe serve`가 다시 시작하면 로그아웃이다.
6. 잠그기: 상단 "잠그기"와 `Ctrl+Alt+L`이 서버 세션을 지운다. Google 쪽 로그아웃은 하지 않는다(브라우저의 Google 세션은 사용자의 것이다).

라이브러리는 **oauth4webapi 3.8.8**(MIT, 의존성 0, 설치 스크립트 없음, 2026-09-05 게시)을 쓴다 [측정: `npm view`]. 같은 저자의 openid-client 6.8.9는 jose를 함께 들이고 11-02 게시라 7일 규칙에 걸린다. 직접 구현하지 않는다.

### 6.2 사용자의 설정 절차

에이전트는 이 절차를 대신하지 않는다. 비밀은 저장소에 두지 않는다.

1. Google 계정의 2단계 인증을 켜고 패스키나 보안 키를 등록한다. 이것이 실제 피싱 방어다(6.6절).
2. Google Cloud 콘솔에서 프로젝트를 하나 만들고 OAuth 동의 화면을 "외부", 게시 상태 "테스트"로 두고 자기 계정만 테스트 사용자로 넣는다. 범위는 `openid`뿐이다.
3. 사용자 인증 정보 → OAuth 클라이언트 ID 만들기 → 애플리케이션 유형 **"데스크톱 앱"**, 이름 `loupe`. 데스크톱 앱은 loopback IP 리디렉션(`http://127.0.0.1:<port>`)을 쓰는 유형이고 PKCE를 쓴다 [출처: Google OAuth 2.0 for iOS & Desktop Apps]. loupe의 리디렉션 URI는 `http://127.0.0.1:4812/auth/google/callback`이다. 콘솔이 이 유형에 리디렉션 URI 목록을 받는지는 확인하지 않았다 `[가정]`. 받는다면 이 값 하나만 넣는다.
4. 클라이언트 ID와 클라이언트 보안 비밀을 KMS에 넣는다: `kms key add loupe-google-oauth --to loupe`(TTY, 에코 없음, `kms.md` 6.6절). 티어는 T1이다. KMS agent가 `~/.config/loupe/google-oauth.json`(mode 600, 저장소 밖)으로 렌더한다. Google은 데스크톱 앱의 보안 비밀을 비밀로 지킬 수 없다고 보지만 [출처: 같은 문서] 사용자 결정에 따라 KMS 자료로 다룬다. KMS가 생기기 전에는 `loupe google-setup`(TTY 전용)이 같은 파일을 에코 없이 받아 쓴다.
5. 허용 계정 등록: 터미널에서 `loupe google-enroll`(TTY 전용). 브라우저로 한 번 로그인하게 하고, 받은 `sub`와 이메일을 터미널에 보여 준 뒤 사용자가 `y`를 치면 `sub`만 `~/.config/loupe/auth.json`(mode 600)에 쓴다. 웹에서 허용 계정을 정하거나 바꾸는 길은 없다. 이 파일이 없으면 `loupe serve`는 "설정 필요" 화면만 낸다.
6. 바꾸기: 계정을 바꾸려면 `loupe google-enroll`을 다시 돈다. 바뀌면 모든 세션을 끊는다. 클라이언트 비밀이 새면 콘솔에서 새로 만들고 `kms rotate loupe-google-oauth`.

### 6.3 검사

모든 `/kb/*`, `/kb-write/*`, `/auth/*` 요청이 아래를 통과해야 한다. v1의 `localhost` 허용과 `navigate` 통과는 데이터 경로에서 없앤다 [relief: 2.1절 `guard.ts` 표].

| 검사 | 읽기(`/kb/*`) | 쓰기(`/kb-write/*`), `/auth/*`의 POST | Google 콜백(`GET /auth/google/callback`) |
|---|---|---|---|
| Host | `127.0.0.1:4812` 정확 일치 | 같다 | 같다 |
| Origin | 있으면 `http://127.0.0.1:4812` 정확 일치 | 반드시 있고 정확 일치 | 최상위 이동이라 Origin이 없거나 Google이다. 대신 `state` |
| Fetch Metadata | `sec-fetch-site`가 있으면 `same-origin`만 | 같다 | `sec-fetch-mode=navigate`, `sec-fetch-dest=document`만 |
| 세션 | `Authorization` 유효 | 쓰기는 유효. `/auth/*`는 해당 없음 | 해당 없음 |
| 형식 | GET, HEAD | POST, `application/json`, `X-Loupe-Write: 1` 또는 `X-Loupe-Auth: 1`. CORS 응답 헤더 없음 | `state`, `code` 외 파라미터 무시. 오류 파라미터는 실패로 |

- 바깥 페이지는 `/auth/*` POST의 사전 요청에서 끝나므로 로그인을 시작하거나 끝낼 수 없다. 콜백을 직접 부르게 해도 살아 있는 `state`가 없어 실패하고, 실패는 세지 않는다. 암호가 없으므로 실패 잠금도 없다. 로그인 시작은 분당 10회로 제한한다 `[가정]`.
- 로그인 화면은 `127.0.0.1:4812`로만 연다. `localhost`로 오면 그 주소로 보낸다. `sessionStorage`와 리디렉션 URI가 그 출처에 묶여서다.
- **tower 마운트(`/loupe`)를 끈다.** tower 프록시는 `authorization`을 지우고 GET, HEAD만 지난다 [relief: 2.1절]. v1 10절의 선택 마운트를 철회한다.
- **포트 점유.** v1의 systemd 소켓 유닛이 4812를 늘 쥔다 [v1: 10절]. 빈 포트를 다른 UID가 잡으면 Google 리디렉션의 `code`를 받을 수 있지만 PKCE `code_verifier`가 없어 바꾸지 못한다. 가짜 로그인 화면은 loupe 암호를 받을 것이 없다. 소켓 유닛 없이 띄우면 상태 화면에 적는다.
- `loupe status`는 KB 소켓을 직접 읽으므로 세션이 필요 없다 [v1: 10절].

### 6.4 오프라인

Google 로그인에는 인터넷이 필요하다. WSL이나 PC가 오프라인이면 새 로그인이 안 된다. 이미 열린 세션은 유휴 1시간 동안 계속 쓰인다(세션 확인은 로컬이다). loupe 서버는 시작 때 Google에 닿지 않아도 뜬다. JWKS는 로그인 때 받고 캐시는 메모리에만 둔다.

### 6.5 비상 경로

**결정: TTY로 여는 비상 암호.** Google에 닿지 못할 때만 쓴다.

- `loupe breakglass set`(TTY 전용, 에코 없음, 12자 이상)이 argon2id 해시를 `~/.config/loupe/auth.json`에 둔다(`node:crypto`, 새 의존성 없음 [relief: 2.1절]).
- 평소에는 암호 로그인 경로가 **닫혀 있다.** 터미널의 `loupe breakglass open`(TTY 전용)이 1시간 동안만 연다. 그동안 로그인 화면에 "비상 암호" 칸이 나타나고, 시간이 지나거나 Google 로그인이 한 번 성공하면 닫힌다. 여는 일과 쓰는 일이 모두 상태 화면과 서버 로그(시각만)에 남는다.
- "Google에 닿지 않음"을 서버가 판정해 자동으로 여는 방식은 쓰지 않는다. 네트워크를 막을 수 있는 쪽이 비상 경로를 열 수 있게 되기 때문이다.
- 비상 암호 로그인에는 6.3절의 검사와 relief식 실패 지연(검사를 통과한 시도만 셈, 5회부터 30초, 상한 5분, 영구 잠금 없음)이 붙는다.

| 선택지 | 얻는 것 | 잃는 것 |
|---|---|---|
| **TTY로 여는 비상 암호(결정)** | 오프라인에도 loupe를 쓴다. 평소에는 암호 경로가 없어 피싱할 것이 없다 | 비상 경로가 열린 1시간은 암호 하나가 문이다. 열려면 터미널에 있어야 한다 |
| 없음 | 문이 Google 하나뿐이다 | 오프라인이면 loupe를 못 쓴다. KB는 `kb` CLI로만 본다 |
| 늘 열린 로컬 암호 | 편하다 | 암호 로그인과 다를 바 없다(6.8절에서 버렸다) |

같은 UID는 비상 경로가 없어도 KB 소켓을 직접 읽으므로, TTY를 요구하는 이 경로가 같은 UID에게 새로 주는 것은 없다.

### 6.6 피싱 저항

- **실제 방어는 Google 계정의 2단계 인증, 특히 패스키나 보안 키다.** 패스키는 Google 도메인에 묶여 가짜 Google 화면에서 쓰이지 않는다. loupe는 사용자 계정의 설정을 강제할 수 없으므로 6.2절 1단계로 둔다.
- loupe 쪽: 받는 암호가 없다. `state`는 `login_id`에 묶여 한 번만 쓰이고 5분 뒤 사라진다. `nonce`는 ID 토큰에서 한 번만 받아들인다. PKCE S256이 가로챈 `code`를 쓸모없게 한다. 리디렉션 URI는 고정된 loopback 하나다. `sub` 하나만 들어온다.
- 사용자에게 보이는 규칙: 로그인 화면은 "Google로 로그인" 단추뿐이다. loupe 주소에서 Google 암호를 묻는 칸이 보이면 가짜다. Google 암호는 `accounts.google.com`에서만 친다.

### 6.7 남는 위험

| 주체 | 결과 |
|---|---|
| 다른 출처의 페이지, 다른 로컬 포트의 페이지 | 막는다. 세션은 이 출처의 `sessionStorage`에만 있고 자동 전송이 없다 |
| WSL 다른 UID, host network 컨테이너 | 막는다. 세션 없이는 읽기도 쓰기도 없다. 허용 `sub`로 로그인해야 한다 |
| DNS 재바인딩 | 막는다. Host 정확 일치 |
| 다른 Google 계정 | 막는다. `sub` 불일치 |
| Google 계정 탈취 | 못 막는다. 그 계정이 문이다. 2단계 인증과 패스키가 막는다 |
| 같은 UID(Claude 세션, npm 스크립트, Windows 같은 사용자) | **못 막는다.** KB 소켓을 직접 읽고 loupe 소스나 `auth.json`을 고칠 수 있다 [relief: 1.2절] |
| loupe 출처 안의 XSS | 세션을 쓸 수 있다. 4.5절의 스키마, CSP, Trusted Types가 막는다 |

### 6.8 버린 안

| 안 | 이유 |
|---|---|
| 암호만 쓰는 로그인(이전 판, relief 1단계) | 사용자 결정. 암호는 가짜 화면에 털리고, 피싱 저항을 loupe가 스스로 만들어야 한다 |
| Google refresh token으로 조용히 연장 | 오래 사는 자격이 디스크에 남는다. 사용자가 갱신 없음을 골랐다 |
| 이메일 허용 목록 | 이메일은 바뀌거나 다른 계정에 다시 쓰일 수 있다. Google은 `sub`를 식별자로 쓰라고 한다 [출처: Google OpenID Connect 문서] |
| 암묵 흐름, 브라우저에서 토큰 교환 | 토큰이 URL이나 브라우저에 남는다. Google은 PKCE 코드 흐름을 권한다 |
| "웹 애플리케이션" 클라이언트 유형 | loopback 주소를 쓰는 로컬 서버에는 데스크톱 앱 유형이 Google 문서의 경로다. 웹 유형의 `127.0.0.1` 허용 여부는 확인하지 않았다 |
| 세션 쿠키 | 쿠키는 포트를 가리지 않는다 [relief: 1.2절] |
| oauth2-proxy, tower 앞단 인증 | 서비스가 하나 늘고 tower 프록시가 `authorization`을 지운다. 도구 독립 원칙과 맞지 않는다 |
| 자체 OIDC 구현 | oauth4webapi가 있다(3번 지침) |

### 6.9 relief와의 일관성

relief 문서는 고치지 않는다. 두 도구가 같은 문을 쓰려면 relief 쪽에서 바뀔 것을 적어 둔다.

- relief 2.1절의 "Phase 1은 사람이 정한 암호 하나"가 Google 로그인으로 바뀐다. 쿠키 없는 세션, 정확한 Origin, 사전 요청으로 끝나는 POST 검사는 그대로 맞는다.
- relief는 자기 OAuth 클라이언트(또는 같은 클라이언트에 자기 리디렉션 URI)와 `http://127.0.0.1:4815/auth/google/callback`을 쓰고 허용 `sub`를 따로 등록한다. 세션은 출처마다 따로다. 코드 공유는 하지 않는다(도구 독립).
- relief 8B절의 원격 접근(Tailscale Serve, HTTPS 호스트 이름)은 loopback이 아니므로 그 경로의 리디렉션은 웹 애플리케이션 유형과 그 호스트 이름이 필요하다. relief가 정할 일이다.
- relief 8B.3절의 "패스키로 바꾸고 암호를 없앤다"는 Google 계정의 패스키로 대신할 수 있다. relief의 쓰기 재확인(L2, L3)과 KMS 잠금 해제는 Google 로그인과 별개로 남는다.

## 7. 주제 조사 요청 (E, D4)

사용자 결정: loupe가 에이전트를 움직이는 것이 아니라 **KB에 조사를 요청하는 체계**다. loupe의 동작은 "KB에 이 주제의 조사를 요청한다" 하나이고, 수집이든 에이전트 같은 엔진이든 방법은 KB가 고르며 예산과 상한도 KB가 가진다 [ADR-0004 T.8].

### 7.1 만들기와 요청

**규칙 하나: 나가는 글은 정해진 필드뿐이고, 한 함수가 만들고, 사용자가 보낸 뒤가 아니라 보내기 전에 본다**(Codex 2차 2).

- 필드: 이름, 범위 설명, 별칭, 제외 표현, 우선순위, 사용자가 직접 넣은 URL. KB가 받는 것이 이것뿐이다 [ADR-0004 T.1, KB답].
- 함수: `buildResearchRequest(fields)` 하나가 이 필드로 `Topic` 기록(`title`=이름, `body`=범위 설명, `props.aliases`, `props.exclude`)과 조사 요청(`topic`=이름, `reason`=범위 설명, `priority`, `url[]`)을 만든다. 메모와 문서 객체를 인자로 받지 않는다. `promoted_from`은 기록 ID이고 글이 아니다.
- 미리보기: 보내기 단추는 언제나 그 함수의 결과를 글자 그대로 보여 주는 자리에 있다. `ConfirmedTopicText`는 이 미리보기의 보내기 단추만 만든다.

- **만들기.** 팔레트의 "새 주제 '…' 만들고 KB에 조사 요청"은 대화상자(이름, 범위 설명, 별칭, 제외 표현, 우선순위, URL)를 연다. 대화상자 아래쪽에 "KB에 보낼 글" 미리보기가 있고 그 옆의 "보내기"가 확인이다.
- **메모 승격.** 메모 카드의 단추가 미리보기를 겸한다. 단추 글은 `주제로 승격: 「<메모 제목>」 KB에 보내기`이고 제목 60자를 자르지 않고 다 보인다. 이 단추를 누르는 것이 확인이다. 이름과 범위 설명은 둘 다 메모 제목(2.5절)이고 우선순위는 `normal`, 별칭·제외·URL은 비어 있다. 메모의 둘째 줄부터는 어디에도 들어가지 않는다. 제목을 바꾸고 싶으면 단추 옆 "고쳐서 보내기"가 대화상자를 연다. 보낸 뒤 8초 되돌리기 알림이 같은 글을 다시 보인다(와이어프레임 3). 사용자 결정 D13은 이 형태로 닫는다.
- **"조사 다시 요청"**: 주제 화면에서 같은 대화상자로 새 요청을 낸다.
- **요청 한도.** `topic`, `reason` 각 500자, URL 50개, `priority`는 `low`, `normal`, `high` [KB답]. 대화상자가 넘치기 전에 막는다.
- `collect_mode`, 엔진, 상한 칸은 loupe에 없다.

### 7.2 보이는 것

| 칸 | 내용 | 출처 |
|---|---|---|
| 요청 | 요청 ID, 보낸 시각, **KB에 보낸 글** | 요청 응답 |
| 상태 | `queued` → `in_progress` → `done`, 또는 `unanswerable`, `blocked_policy`. 이름 그대로 보인다. `blocked_policy`는 다시 요청 단추가 없다 | [KB답] |
| 합쳐짐 | 바이그램 Jaccard 0.5 이상이나 별칭으로 합쳐진다 [KB답]. "기존 요청 t-…와 합쳐짐"과 링크 | 응답 `duplicates` |
| KB가 고른 엔진 | 예: 결정적 수집 3, 산문 발견 에이전트 1 | KB가 보고할 때만 `[가정-KB]` |
| 비용 | 이번 달 사용 / 주제 상한(`budget_usd_month`, 기본 $10). **읽기 전용** | KB가 보고할 때만 [ADR-0004 T.8] |
| 승인 대기 출처 | 새 호스트 후보. 승인은 KB 쪽에서 한다 | [ADR-0004 T.3] `[가정-KB: HTTP 읽기]` |
| 도착한 것 | `IN_TOPIC`으로 붙은 주장, 엔티티, 스냅샷. 지난 방문 뒤 새로 온 것 | [ADR-0004] |

- 갱신은 45초 폴링이다 [v1: 7.3절].
- **멈추기.** "주제 멈추기 요청"은 주제 `status=paused`를 쓰는 first_party 갱신이다. KB는 수집기를 지우지 않고 주제 연결만 닫는다 [ADR-0004 T.1]. 진행 중인 엔진 호출을 언제 멈추는지는 KB의 일이다(N7).
- **검토.** 도착한 것은 이미 KB 인용 게이트를 지났다 [ADR-0004 결정 3]. 화면은 주장마다 v1 인용 판정(원문 일치, 위치 보정, 찾지 못함)과 원문 열기를 준다. **한 번에 받는 단추를 두지 않는다.** "원문 일치"는 인용이 원문에 있다는 뜻일 뿐이고 사실 여부나 원문에 심은 지시를 판정하지 않는다는 문장을 표 위에 늘 둔다(Codex 6). 틀린 주장은 "틀림 제보"로 출처 URL을 붙인 요청을 낸다. loupe는 KB 판정을 바꾸지 않는다.

### 7.3 밖으로 나가는 글

first_party 본문은 로컬 모델에만 간다. 외부 LLM은 사용자의 대화형 세션 말고는 보지 않는다 [KB답]. 다만 KB는 주제의 범위 설명과 시드어를 비밀 검사와 내부 주소 제거 뒤 외부 모델 프롬프트에 실을 수 있다 [ADR-0004 T.1].

**정확히 나가는 것:** 사용자가 확인한 주제 이름, 범위 설명, 별칭, 제외 표현, 우선순위, 사용자가 직접 넣은 URL. 이것들은 `Topic` 기록의 `title`, `body`, `props`와 요청의 `topic`, `reason`에 든다.

**나가지 않는 것:** 메모 본문, 문서 본문, 주제에 링크된 기록의 내용, 팔레트에 친 다른 글.

| 강제 장치 | 내용 |
|---|---|
| 타입 | `write.ts`의 주제와 조사 요청 경로는 `ConfirmedTopicText`만 받는다. 이 값은 미리보기의 보내기 단추(대화상자와 메모 승격 단추)만 만든다. 메모나 문서 객체를 받는 시그니처가 없다 |
| 함수 | `buildResearchRequest` 하나만 직렬화한다. 허용 키 밖의 필드가 있으면 보내지 않고 오류다. 미리보기와 실제 요청이 같은 함수의 같은 결과를 쓴다 |
| 화면 | 미리보기 아래에 "이 글은 조사에 쓰여 외부 모델에 갈 수 있다"를 늘 적는다 |
| 시험(경계) | 메모 첫 줄에 표식 A, 둘째 줄 이후에 표식 B를 넣고 승격한다. Playwright가 `kb-write/` 요청 본문을 모두 가로채 **B는 0번, A는 이름과 범위 설명 자리에만** 나오고, 요청 본문이 승격 단추에 보인 글과 바이트 단위로 같음을 단언한다 |
| 시험(다른 경로) | 문서를 링크한 주제를 만들고 문서 본문 표식이 0번, 팔레트에 표식을 친 뒤 만들기를 해 대화상자에서 지운 글이 0번 나오는지 본다. `write.ts` 단위 시험은 허용 키 밖의 필드와 `ConfirmedTopicText`가 아닌 값을 넣으면 실패하는지 본다 |

## 8. 비밀 보기 (D5)

사용자 결정: 별도 KMS 인증 뒤 loupe에서 비밀 값을 볼 수 있다. 가장 적게 드러나게 설계한다. **KMS가 생기기 전에는 잠긴 자리만 있다.** 구현은 KMS M1~M2 뒤의 나중 단계다(11.2절).

### 8.1 구조

| 항목 | 결정 | 이유 |
|---|---|---|
| 출처 | **별도 출처의 비밀 창** `http://127.0.0.1:4814`. 2026-11-04에 이 저장소, KB 저장소, 사용자 systemd 설정에서 4814를 grep으로 찾지 못했고 듣고 있는 프로세스도 없었다. 4815와 4816은 relief(`relief.md` 11절), 4810~4813은 loupe가 쓴다. 레일의 "비밀"은 이 창을 연다. KB 데이터, 사용자 본문, Markdown 렌더, 편집기가 이 출처에 없다 | loupe 본 출처의 XSS(4.5절)가 KMS 토큰과 값에 닿지 못한다 |
| 서버 | 이 출처는 정적 파일만 낸다. 값과 토큰은 **브라우저가 KMS에 직접** 요청한다. `loupe serve`도 비밀 창 서버도 KMS 요청을 프록시하지 않는다 | 서버 로그와 프로세스에 값이 지나가지 않는다 |
| 창 참조 끊기 | 본 창은 비밀 창을 `window.open(url, '_blank', 'noopener,noreferrer')`로만 연다. 두 출처 모두 `Cross-Origin-Opener-Policy: same-origin`을 보낸다. 비밀 창은 시작할 때 `window.opener`가 `null`이 아니면 아무것도 그리지 않고 "loupe에서 다시 열기"만 보이며, `window.name`을 비운다. URL 파라미터와 조각을 읽지 않고 `message` 수신기를 두지 않는다. `frame-ancestors 'none'` | 편집기 XSS가 비밀 창을 이동시키거나 이름으로 겨냥하거나 메시지를 보내지 못한다(Codex 2차 1) |
| 포트 점유 | `loupe.socket`에 `ListenStream=127.0.0.1:4814`를 `FileDescriptorName=secret`으로 더해 systemd가 4814를 늘 쥔다. relief 터미널이 같은 이유로 소켓을 쥔다 [relief: 7.1절]. `loupe serve`는 `secret` fd를 받았을 때만 비밀 창을 내고, 받지 못했으면(소켓 유닛 없이 띄움) 본 창의 "비밀" 단추를 막고 이유를 적는다. 비밀 창을 TCP 포트에 직접 바인딩하는 길은 없다 | 다른 UID가 빈 4814를 먼저 잡아 가짜 KMS 로그인으로 암호와 TOTP를 모으지 못한다 |
| 가짜 화면 대비 | 포트를 쥐는 것이 1차 방어다. 페이지 스스로는 자기가 진짜임을 증명할 수 없으므로(가짜 페이지는 검사를 돌리지 않는다) 남는 방어는 사람 쪽이다: 본 창의 "비밀" 단추로만 열고, 주소 표시줄이 `127.0.0.1:4814`인지 본다. KMS가 출처에 묶인 로그인(패스키)을 지원하면 `loupe-reader`를 그것으로 바꾼다. 패스키는 다른 출처의 페이지에서 쓰이지 않는다 `[가정: OpenBao의 WebAuthn 지원은 확인하지 않았다]` | |
| 신원 | 사용자 자신의 KMS 사람 신원. 권장은 사람 계정 `loupe-reader`(암호 + TOTP): 정한 KV 경로의 `read`와, 5.7절의 새 보안 정보를 넣을 경로의 **`create`만**(덮어쓰기인 `update`는 없음). `owner` 계정은 쓰지 않는다 | `owner` 토큰이 브라우저에 오면 피해가 KV 전체가 된다 [출처: `kms.md` 6.5절]. 덮어쓰기가 없어 브라우저 침해가 기존 키를 바꾸지 못한다 |
| 토큰 설정(KMS 쪽) | `token_ttl=15m`, `token_max_ttl=15m`, `token_explicit_max_ttl=15m`, `token_no_default_policy=true`. 정책은 정한 KV 경로의 `read`, 메타데이터 `read`·`list`, `auth/token/lookup-self`, `auth/token/revoke-self`뿐이고 **`renew-self`가 없다** `[가정: 매개변수 이름은 Vault와 같다고 보고 KMS M1에서 확인한다]` | 기본 정책의 갱신 권한이 빠져 잠금 뒤에 토큰이 늘어나지 않는다. 최대 수명은 어떤 경우에도 15분이다(Codex 2차 3) |
| KMS 쪽 설정 | CORS 허용 출처를 `http://127.0.0.1:4814` 하나로. KMS 이름(`kms.sys.internal.example`)과 사설 CA는 이 브라우저에만 [출처: `kms.md` O25] | 다른 출처는 응답을 읽지 못한다 |
| CSP(비밀 창) | `default-src 'none'; script-src 'self'; connect-src https://kms.sys.internal.example; style-src 'self'; img-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'; require-trusted-types-for 'script'` | 값을 다른 곳으로 보낼 길을 막는다 |
| 토큰 | JS 변수에만. `sessionStorage`, `localStorage`, IndexedDB, URL, 쿠키에 두지 않는다. 창을 닫거나 새로 고치면 다시 로그인 | 디스크에 남지 않는다 |

### 8.2 값 보기

| 동작 | 규칙 |
|---|---|
| 목록 | 이름, 서비스, 만료, 마지막 사용(KV 메타데이터). 값 칸은 처음부터 `••••`이다. 목록을 열 때 값을 읽지 않는다 |
| 보기 | 그 항목만 KMS에서 읽는다. 30초 뒤 다시 가리고 값을 담은 변수를 비운다. 한 번에 하나만 보인다 |
| 복사 | 그 항목을 읽어 `navigator.clipboard.writeText`로 넣고 화면에는 값을 그리지 않는다. 값 변수는 넣은 즉시 비운다. 20초 뒤, 그리고 잠금과 `pagehide` 때 클립보드에 빈 문자열을 쓰려 한다. 그 사이 다른 것이 복사됐는지는 알 수 없어 무조건 비운다 |
| 보장하지 못하는 것 | 창이 죽거나 강제로 닫히거나 브라우저가 끝나면 비움 타이머도 함께 죽어 **클립보드에 값이 남는다.** Chrome은 초점 없는 문서의 클립보드 쓰기를 거절할 수 있어 창을 숨긴 뒤의 비움도 실패할 수 있다. 실패하면 다음에 창이 초점을 얻을 때 다시 비우고 "클립보드를 비우지 못했다"를 보인다. 클립보드 기록(Win+V)과 관리자에 들어간 사본은 지울 수 없다. 그래서 기본 동작은 보기이고 복사는 두 번째 단추다 |
| 잠금 계기 | 유휴 3분, 창을 60초 숨김, "지금 잠그기", 시계 건너뜀(1초마다 벽시계를 보고 마지막 확인보다 10초 넘게 지났으면 절전에서 돌아온 것으로 본다), `pagehide`, 그리고 토큰 남은 수명 0 중 먼저 오는 것 |
| 잠금 순서 | ① 화면의 값을 지우고 값을 담은 변수를 비운다. ② 진행 중인 KMS 요청을 `AbortController`로 끊고, 잠금 세대 번호를 올려 늦게 도착한 응답은 버린다. ③ 토큰 변수를 비운다(사본을 들고 폐기만 한다). ④ `revoke-self`를 3초 안에 부른다. ⑤ 클립보드를 비우려 한다 |
| 폐기 실패 | **닫힌 쪽으로 실패한다.** 폐기가 실패하거나 시간을 넘겨도 ①~③은 이미 끝났고 다시 열지 않는다. 화면은 "KMS에서 토큰을 폐기하지 못했다. 최대 n분 뒤 스스로 만료된다"와 남은 시간을 보인다. 새 잠금 해제는 새 로그인이다. 토큰은 갱신 권한이 없어 15분을 넘지 못한다 |
| 가림 | 보기 30초 타이머에 더해 창이 초점을 잃으면 곧바로 가린다. 타이머는 벽시계 마감 시각으로 비교해 절전 뒤에도 늦게 가리지 않는다 |
| 감사 | 보기와 복사는 각각 KMS 읽기 요청 하나라 KMS 감사 장치에 항목마다 남는다. loupe는 따로 기록하지 않는다. 창 옆에 "이번 해제 뒤 열람 n, 복사 n"만 메모리 값으로 보인다 |
| 남지 않는 곳 | 검색, 그래프, 팔레트, 브라우저 이력(URL에 이름도 없음, 탭 제목은 "loupe · 비밀"), 로그(콘솔과 오류 보고에 이 창의 상태를 넣지 않음), 기기 저장소 |
| 쓰기 | "새 보안 정보"(8.3절)만. 기존 키의 교체, 서비스 부여, 폐기는 `kms` 명령이나 KMS 화면이다 [출처: `kms.md` 6.6절] |

### 8.3 보안 정보 넣기

5.7절에서 "보안 정보"를 고르면 이 창의 "새 보안 정보" 양식이 열린다.

| 칸 | 규칙 |
|---|---|
| 이름 | KMS 항목 이름. 비어 있지 않고 KMS 이름 규칙을 따른다. 문서의 보안 정보 블록에서 왔다면 그 이름이 채워져 있다 |
| 값 | 이 창에서만 친다. 에코 없는 입력칸(`type=password`, 자동 완성 끔)이고 "보기" 단추로만 잠시 보인다 |
| 메모 | 무엇의 키인지 한 줄. KMS 메타데이터에 들어가고 값은 넣지 않는다 [출처: `kms.md` 6.8절 `custom_metadata` 규칙] |
| 저장 | 잠금 해제된 `loupe-reader`로 KV `create`. 같은 이름이 있으면 실패하고 "이미 있다. 교체는 `kms rotate`"를 보인다 |

- 저장 뒤 입력칸과 변수를 비운다. 값은 loupe 본 출처, KB, 기기 저장소 어디에도 가지 않는다.
- 서비스에 부여하는 일(`kms grant`)은 이 창에 없다. 새 항목은 부여 전까지 아무 서비스도 읽지 못한다.
- KMS가 없거나 잠겨 있으면 양식은 잠금 해제를 먼저 요구한다. KMS 준비 전에는 "KMS 준비 전. 지금은 넣을 곳이 없다"만 보이고, 본 창의 보안 정보 블록은 이름만 가진 채 남는다.

### 8.4 남는 위험

값을 보는 순간 브라우저와 화면은 값을 본다. 설계가 줄이지 못하는 것을 그대로 적는다.

- 브라우저 렌더러 메모리, 화면, 화면 녹화와 원격 화면, 어깨 너머.
- 이 브라우저 프로필의 확장 프로그램. 비밀 창 출처에 권한이 있는 확장은 값을 읽는다.
- 클립보드 관리자와 **Windows 클립보드 기록(Win+V)**. 사용자는 기록을 그대로 두기로 했다(D16). 그래서 20초 뒤 비워도 기록에는 남는다. 비밀 창은 복사 단추 옆과 복사 직후 알림에 "복사한 값은 Windows 클립보드 기록(Win+V)에 남을 수 있다"를 짧게 늘 보인다.
- 같은 UID 프로세스(브라우저 프로필 파일, 디버그 포트, loupe 소스 변조). KMS 토큰을 가로채면 15분 안의 읽기 범위 전부다.
- KMS 쪽 CORS를 잘못 넓히면 다른 출처가 응답을 읽는다. KMS 설정 시험으로 막는다.

- 한글 조합 중에는 Enter, 화살표, `/`, `[[`를 단축키로 처리하지 않는다.
- 끌기마다 키보드 대안과 "이동" 메뉴가 있다. 그래프 캔버스는 v1처럼 키보드로 노드를 고를 수 없고 패널 목록과 팔레트가 대안이다 [v1: 12.2절].
- 편집기는 `role="textbox"`, `aria-multiline`. 슬래시 메뉴와 링크 고르기는 `listbox` + `aria-activedescendant`. 표는 `grid`.
- 저장 칩, 요청 상태, 쓰기 거절, 비밀 격리는 `aria-live="polite"`. 격리 알림은 규칙 ID만 읽는다. 비밀 창은 값을 읽어 주지 않는다.
- 색만으로 상태를 나누지 않는다(v1 원칙).

**태블릿 메모(나중).** 1024 px 아래에서는 탭 하나, 오른쪽 패널은 아래 서랍. 손잡이와 칩은 44 px 이상. 호버로만 보이는 것은 길게 누르기와 블록 메뉴로도 연다. 상단 찾기 단추가 주 경로다. 비밀 창은 태블릿에서 열지 않는다(KMS는 데스크톱만).
