# loupe v2 설계: 지식 작업 공간

- 상태: 구현 전 설계, 구현 기준 문서. 기준일 2026-11-05. 사용자가 UX 방향(블루프린트 3판, 13절)과 12.1절의 결정을 2026-11-04에 정했다. M0b 로그인은 구현 중이다. 구현은 11절 순서로 이 문서를 따른다. 쓰기 계약은 KB ADR-0005 9판(`42980bf`)이다(5절). Codex 교차 검토 결과를 반영했다(부록 B).
- 대상: `tools/loupe`. v1 설계(`docs/design/loupe.md`)의 읽기 화면, 그래프, 시간 여행, 주장 단위 출처, 안전한 렌더링은 그대로 두고 그 위에 로그인, 쓰기, 작업 공간을 더한다.
- 입력: 사용자 요구 7건과 결정(2026-11-04), v1 설계, KB 계약 0.3.2(`data-interface-v0.md`, `openapi.yaml`), KB 세션의 first_party 쓰기 답(2026-11-04, KB HEAD `9d5c141`), KB ADR-0001과 ADR-0004 T.1·T.7·T.8, `docs/design/relief-v2.md` 1~2절, `docs/design/kms.md`., KB ADR-0005 9판(`42980bf`, 8판 `b82f5d3`을 대체), 사용자의 UX 피드백(2026-11-04 두 차례), Codex의 로그인 보안 검토(2026-11-04).
- **쓰기 인터페이스의 주인은 KB다.** KB가 ADR-0005(loupe용 first_party 쓰기 인터페이스) 9판을 냈다. KB 구현 전이므로 loupe는 그 모양을 흉내 내는 kb-mock으로 먼저 검증하고(11절), 쓰기 호출은 어댑터 하나(5.1절)에 가둔다. 답이 없는 것은 10절에 모았다. 오늘의 inbox와 MCP 경로를 장기 API로 삼지 않는다.
- **Obsidian과 Notion은 UX 참고일 뿐이다**(사용자, 2026-11-04). loupe 데이터가 그 프로그램에서 보일 필요는 없다. 내보내기, 가져오기, 왕복 호환은 범위에서 뺐다(1절).

| 표 | TanStack Table 9.3.1 + Virtual(v1 Phase 3 계획). 보드는 나중 | Glide Data Grid, AG Grid |

| 공개 범위 | 새 기록은 모두 `private`(loupe만 본다). 문서와 주제는 만들 때만 "내부". 낮추기와 "지식베이스에 반영"은 동작마다 기기 확인(WebAuthn) | loupe는 private를 만들지 않음(이전 D11) |
| 비밀이 섞인 쓰기 | KB가 422로 **거절**하고 구간만 알린다 [ADR-0005]. loupe는 구간만 칠하고 보안 정보로 바꾸기·고치기·격리 보관을 고르게 한다 | 재시도, 클라이언트 검사로 대신하기 |
| 주제 조사 (D4, 정함) | loupe의 동작은 **"KB에 이 주제의 조사를 요청한다"** 하나다. 방법(수집, 에이전트 등 엔진), 예산, 상한은 KB가 정한다. loupe는 요청, 상태, KB가 고른 엔진, KB가 보고한 비용, 도착한 것을 보인다 | loupe가 수집 방식이나 에이전트를 고름 |
| 외부로 나가는 글 | `private` 주제는 아무것도 나가지 않는다(등록 소스와 로컬만). 메모 본문은 "지식베이스에 반영"에서, 보낼 요청에 묶인 기기 확인 동의 뒤에만 그 메모 하나가 외부 정제 엔진에 간다. 결과 공개는 두 번째 기기 확인이다. 요청 어댑터와 시험이 강제한다(5.8절, 7.4절) | 메모나 문서 본문 첨부, 버튼만으로 외부 전송 |
| 비밀 보기 (D5, 정함) | KMS 인증 뒤 값을 보인다. 브라우저가 별도 출처에서 KMS에 직접 붙고, 항목마다 요청 때만 읽고, 기본은 가림, 보기와 복사, 클립보드 자동 비움, 저장소·이력·URL·로그·검색 없음, 짧은 유휴 잠금, 열람마다 KMS 감사 | loupe 서버 프록시, 메타데이터만 |

**바뀐 규칙(D1, 정함).** 사용자가 loupe의 first_party 쓰기를 승인했다(2026-11-04). `CLAUDE.md` 구조 원칙의 "뷰어는 읽기 전용이다"를 "뷰어(loupe)는 KB의 쓰기 인터페이스로 first_party 기록만 쓰고, 수집된 사실을 고치지 않는다"로 고쳤다. 같은 줄의 "파생값을 KB에 되쓰지 않는다"는 그대로다.

| 원칙 | v2에서 |
|---|---|
| 뷰어는 읽기 전용이다 | **바뀌었다.** loupe는 first_party 기록(메모, 문서, 주제)과 조사 요청만 KB 쓰기 인터페이스로 낸다. 외부 사실(주장, 스냅샷, 엔티티)은 고치지 않는다 |
| KB는 계약으로만 읽는다 | 유지. 쓰기도 ADR-0005의 경로로만 한다. DB 파일, inbox 파일, MCP를 UI 쓰기 경로로 쓰지 않는다 [계약: C 1] |
| 파생값을 KB에 되쓰지 않는다 | 유지. 레이아웃, 커뮤니티, 인용 확인 결과, 정리 제안은 브라우저 안에만 둔다. KB는 저장만 하고 점수나 순위를 갖지 않는다 [KB답] |
| 도구끼리 종속되지 않는다 | 유지. loupe는 tower, relief, KMS의 코드를 쓰지 않는다. 에이전트 실행은 KB의 일이다(7절) |

## 1. 목적, 완료 기준, 비범위

KB를 사용자의 지식 작업 공간으로 쓴다. 주제를 중심으로 그래프를 보고, 빠르게 찾고, 블록 편집기로 문서를 쓰고 표로 훑으며, 메모를 주제로 키워 KB에 조사를 요청하고, 비밀은 따로 잠근다.

**완료 기준(v2 전체)**

1. 허용된 Google 계정으로 로그인한 사람만 KB 내용을 읽고 쓴다. 다른 출처의 페이지, 다른 UID, DNS 재바인딩은 읽기도 쓰기도 못 한다.
2. 찾기(`Ctrl+K`)에서 이름을 치고 Enter 한 번으로 그 주제, 문서, 메모, 엔티티에 닿거나 새 주제나 문서를 만든다. 한글 조합 중 Enter는 선택하지 않는다.
3. 메모 하나를 버튼 한 번으로 주제로 바꾸면 KB에 조사 요청이 가고, 작업 센터와 작업 상세 창에서 상태, KB가 고른 엔진, 비용, 도착한 것이 보인다. KB에 간 글은 메모 제목뿐이고, `private` 주제면 KB 밖으로 나간 글은 없다.
4. 문서를 쓰고 저장하면 판이 하나 늘고, 손대지 않고 닫으면 판이 늘지 않는다. 저장한 판은 이력에 남고 되돌릴 수 있다.
5. 비밀 값이 검색, 그래프, 브라우저 이력, URL, 로그, 기기 저장소에 남지 않는다. 메모에 키를 넣으면 저장 전 검사나 KB의 422가 저장을 멈추고 구간만 보이며, 값은 어디에도 저장되지 않는다.
6. v1 완료 기준 1~5(인용 두 번 클릭, URL 재현, 과거 보기 오인 불가, 그래프 예산, KB 없이 깨지지 않음)를 그대로 지킨다.
7. PC와 iPad에서 머리말 없이 그래프 위의 창 여러 개를 열고 옮기고 크기를 바꾸며 일한다. 폰에서는 메모와 대화 흐름으로 메모를 쓰고 반영한다(폰은 모바일 접속 단계 뒤).

| 비범위 | 이유 |
|---|---|
| Obsidian, Notion과의 데이터 호환(내보내기, 가져오기, 보관함 왕복, 머리말) | UX 참고일 뿐이다(사용자, 2026-11-04) |
| 외부 주장, 스냅샷, 엔티티 이름의 편집 | 수집 경로의 게이트를 지나야 한다 [계약: C 6.1]. 틀린 것은 내 화면에서 버린다(7.2절) |
| 수집 방식, 엔진, 예산의 선택 | KB의 일이다(D4, ADR-0004) |
| 완전 삭제(`kb redact`) | TTY 전용이다 [KB답]. loupe는 명령을 안내만 한다. 격리 해제는 loupe의 기기 확인 동작이다(5.8절) |
| 첨부 파일, 이미지 업로드 | KB에 첨부가 없다 [KB답] |
| 블록 단위 링크와 백링크 | 계약 v1에 없다 [계약: C 6.3] |
| 실시간 공동 편집(Yjs) | 사용자 1명이다. 에이전트 세션과의 충돌은 낙관적 잠금으로 다룬다(5.3절) |
| 폰 흐름과 모바일 접속의 구현 | 설계는 2.9절이고 구현은 나중이다. 첫 단계는 PC와 iPad(같은 화면)다. 로그인 화면만 390 px에서 쓸 수 있게 한다. 모바일 접속은 11.3절의 나중 단계 `[사용자 정정 2026-11-04]` |

**호환 요구를 뺀 덕에 단순해진 것.** 본문 형식은 KB가 Markdown을 저장하므로 Markdown 그대로다. 다만 다음이 없어진다.

- 머리말(front matter)을 쓰지도 읽지도 않는다. 제목과 속성은 기록 필드(`title`, `props`)뿐이다.
- 링크는 `[[id]]` 하나다. 저장 본문에 `[[제목]]` 표기를 남길 이유가 없고, 제목과 ID를 오가는 변환표, 이름 바꾸기 추적이 필요 없다.
- 데이터베이스 보기 블록의 정의는 loupe 전용 형식이어도 된다. Obsidian Bases나 Dataview와 맞출 필요가 없다.
- 가져오기의 충돌 처리, 비밀 검사, 링크 해결 경로가 통째로 없다. 시험 대상이 한 갈래 준다.
- 편집기 기준에서 "Obsidian이 읽는 Markdown 방언"이 빠진다. 기준은 KB 본문 왕복과 읽기 화면(remark)과의 일치뿐이다.

## 2. 정보 구조와 이동 (A)

화면 그림은 저장소 밖의 블루프린트 "loupe v2 UX 설계도" 3판이다(13절). 이 절은 그 그림이 따르는 규칙이다.

### 2.1 객체

KB의 기록 타입은 ADR-0005 4.1이 정했다 [ADR-0005]. loupe의 새 기록은 모두 기본 `private`다(5.6절).

| 객체 | KB 표현 | 만드는 곳 | 비고 |
|---|---|---|---|
| 문서 | 기록 `type: Page`. `props`는 `tags`, `order`, `icon`, 데이터베이스 보기 칸. `PART_OF` → 상위 `Page` [ADR-0005] | `Ctrl+D` 만들기 창, 찾기의 "새 문서" | 기존 `Document`는 외부 문서용이라 쓰지 않는다 |
| 메모 | 기록 `type: Note`. `props`는 `tags`, `pinned` [ADR-0005] | `Alt+N` 빠른 만들기, `Ctrl+M`, 폰 입력줄 | 제목 규칙 2.5절. 자동 삭제 없음 |
| 주제 정의 | 기록 `type: TopicSpec`. `title`이 이름, `body`가 범위 설명, `props`에 `slug`, `aliases`, `domain`, `parent`, `exclude`, `export_llm`, `export_query`. `DEFINES` → 엔티티 `e:topic:<slug>` [ADR-0005] | 메모 승격, 찾기의 "새 주제" | `slug`는 서버가 spec ID에서 만든다(`t-`+16자) [ADR-0005 L308]. loupe에 slug 칸이 없다 |
| 주제 | 엔티티 `e:topic:<slug>`(ADR-0004의 `Topic`). 수집의 닻 | KB | 그래프의 큰 노드. 상태 `active`, `paused`, `retired` |
| 검토 결정 | 기록 `type: Review`. `target`, `verdict:"reject"`(틀림 제보), `note`(500자), `source_url`(선택), `topic` [ADR-0005 L304] | 도착한 주장의 "틀림 제보" | KB가 자동 재검증 티켓을 연다. 주장을 직접 숨기지 않는다(7.2절) |
| 데이터베이스 보기 | 문서 안의 보기 블록(` ```loupe-view `), loupe 전용 형식 | 슬래시 명령 | 새 타입이 필요 없다(4.3절) |
| 엔티티, 주장, 출처 | 외부 데이터 | KB 수집 | v1 화면 그대로. 읽기 전용 |
| 조사 실행 | 티켓 `t-…`. 상태 `queued`, `in_progress`, `paused`, `cancelled`, `done`, `unanswerable`, `blocked_policy`, `budget_unavailable` [ADR-0005] | 승격, "조사 다시 요청" | 같은 주제의 열린 실행에는 합류한다(7.2절) |
| 비밀 객체 | KB에 없다. KMS의 레코드(칸)나 문서 | 비밀 창 | 8절. 그래프에는 문서의 보안 정보 블록이 가리키는 이름만 자물쇠 노드로 |

| 연결 | 표현 | 화면 |
|---|---|---|
| 문서, 메모 → 엔티티, 주장 | 본문 `[[e:…]]`, `[[c-…]]` → `LINKS_TO`. `[[id\|라벨]]`도 받는다 [ADR-0005] | 엔티티 창의 "노트 백링크" [v1: 2절] |
| 문서 → 주제 | `[[e:topic:…]]` → `LINKS_TO`, 또는 `ABOUT` | 주제 창의 문서 목록 |
| 주제 정의 → 승격한 메모 | 서버가 넣는 `PROMOTED_FROM` [ADR-0005] | 메모의 주제 칩, 주제 창 머리 |
| 반영 결과 → 원본 메모 | 서버가 넣는 `PROMOTED_FROM` [ADR-0005] | 메모 창의 "반영됨" 칩 |
| 주제 ↔ 수집된 엔티티, 주장 | KB가 다는 `IN_TOPIC` [ADR-0004] | 그래프, 작업 상세 창 |

### 2.2 화면 배치

**머리말과 바닥말이 없다**(사용자, 2026-11-04). PC와 iPad(600px 이상)는 같은 화면이고 폰(600px 미만)만 다르다(2.9절).

| 자리 | 내용 |
|---|---|
| 바탕 | 전면 그래프(2.3절). 다른 화면이 없다. 과거 보기면 그래프 둘레에 v1의 호박색 테두리 [v1: 4절] |
| 왼쪽 위 | 이름표, 찾기 알약(`Ctrl+K`, 2.4절), "＋ 만들기"(`Alt+N`) |
| 오른쪽 위 | 아바타. 점 하나가 KB 연결 상태(초록, 빨강). 누르면 메뉴와 설정(2.8절) |
| 왼쪽 아래 | 그래프 필터 기즈모(2.3절) |
| 오른쪽 아래 | 작업 센터 알약(3절, 7.2절) |
| 아래 가운데 | 내린 창 독. 내린 창이 있을 때만 보인다(2.7절) |
| 위 가운데 | 필요할 때만 뜨는 알약: "KB 끊김", "과거 보기 · 날짜 · 현재로" |
| 그 위 | 창(2.7절). 문서, 메모, 주제, 엔티티, DB, 작업 상세, 설정 |

- 떠 있는 조작은 그래프 위의 겹이고 창보다 위에 있다. 창이 그 자리를 덮지 않도록 창은 위·아래 띠 44px 안으로 들어오지 않는다.
- v1과 2판 설계의 **왼쪽 레일, 탭 막대, 오른쪽 맥락 패널은 없앴다**(사용자, 2026-11-04). 레일이 하던 이동은 찾기와 기즈모가, 탭은 창이, 맥락 패널은 미리보기와 창 안 탭(백링크, 판, 정보)이 대신한다.
- **주소와 창 제목에 본문을 싣지 않는다.** 주소는 맨 앞 창의 기록 ID 하나와 v1 화면 파라미터만 가진다(`#/w/<id>`, 2.7절). first_party 기록이 맨 앞이면 `document.title`은 "loupe · 문서", "loupe · 메모"처럼 종류만 적는다. 브라우저 이력은 제목을 저장하고, 메모 제목은 첫 줄이라 비밀이 들어갈 수 있기 때문이다. 외부 엔티티는 v1처럼 라벨을 쓴다.

| 버린 안 | 이유 |
|---|---|
| 레일 + 탭 + 오른쪽 맥락 패널(이전 판, 폐기) | 사용자가 좌우 패널을 원하지 않는다. 그래프를 가린다 |
| 모달 2겹 쌓기(2판 U1) | 여러 기록을 나란히 보는 쓰임을 막는다. 사용자가 창 여러 개를 골랐다(2026-11-04) |
| 자유 도킹(dockview, Golden Layout류) | 배치 상태가 크고 무겁다. 창 관리자는 위치와 크기만 가진다 |
| Notion식 페이지 트리 | KB는 그래프다. 위계는 주제와 링크로 표현한다 |

### 2.3 홈 그래프, 활성 노드, 필터 기즈모

홈은 **주제와 그 1홉 이웃**을 그린다. 주제는 크게, 엔티티는 원, 문서는 네모, 메모는 마름모, 비밀 객체는 자물쇠 이름표다. 조사 중인 주제는 점선 테두리, 실패는 빨간 점이다.

- 데이터는 v1의 이웃 경로(`/v1/nodes/{id}/neighbors`)를 주제마다 부른다 [계약: C 4.6]. 일괄 경로는 받지 않는다고 KB가 답했다(주제 20개 이하면 주제마다, 10절 N11).
- 렌더, worker 레이아웃, IndexedDB 좌표 캐시는 v1 Phase 2 코드다 [v1: 6절]. 캐시에는 ID와 좌표만 있다.

**활성 노드와 미리보기**(사용자, 2026-11-04).

| 계기 | 결과 |
|---|---|
| 노드 누르기, `Tab`·`Shift+Tab` 포커스, 찾기 결과에서 화살표로 옮기기 | 그 노드가 **활성**이 된다: 테두리, 이웃 엣지 강조, 미리보기가 붙는다. 마우스를 치워도 남는다 |
| 올리기(마우스) | 400 ms 뒤 미리보기. 벗어나고 150 ms 뒤 닫힌다. 활성은 바꾸지 않는다 |
| 활성 노드를 한 번 더 누르기, `Enter` | 창으로 연다(2.7절) |
| `Esc`, 빈 곳 누르기 | 활성을 푼다 |

- 그래프 캔버스는 키보드 포커스를 받지 못하므로(v1 12.2절) **보이는 노드의 접근성 목록**(화면 밖 `listbox`, 화면 순서)을 두고 그 포커스를 sigma 강조와 미리보기에 잇는다. `Tab` 순서는 주제 → 그 이웃이다.
- 미리보기에는 종류, 제목(first_party면 제목, 외부면 라벨), 주장·출처 수, 태그, 관계 몇 개가 있다. 본문은 첫 두 줄까지다.

**필터 기즈모**(사용자, 2026-11-04). 3D 보기의 원점 기즈모처럼 왼쪽 아래 작은 원이다.

| 요소 | 규칙 |
|---|---|
| 축 다섯 | 1 주제, 2 문서(`Page`), 3 지식(엔티티와 주장), 4 메모(`Note`), 5 비밀 객체 |
| 가운데 | 전체 |
| 누르기 | 그 축만. `Shift`+누르기(터치는 길게 누르기)는 더하기·빼기. 조합 예: 문서 + 메모 |
| 키 | `Alt+G`로 기즈모에 포커스, `0`~`5`, `Shift`+숫자 [가정: Chrome에서 `Alt+G` 확인 전, U6] |
| 펼침 | 올리기나 포커스 때 축에 이름표와 "문서만, 지식만, 메모만, 주제만, 비밀 객체만" 바로 고르기 |
| 닻 | 주제를 꺼도 주제는 점선 닻으로 흐리게 남아 묶음이 흩어지지 않는다. 숨은 노드로 가는 엣지는 그리지 않는다(U9) |
| 글 | 기즈모 아래에 "보이는 것: 문서 + 메모"를 늘 적는다. 색만으로 가르지 않는다 |
| 기억 | 이 탭의 `sessionStorage`에만. 주소에 싣지 않는다 |

- 거르기는 브라우저 안에서만 한다. KB에 질의를 다시 보내지 않고 받은 이웃을 숨길 뿐이다. 그래서 v1 그래프 예산(노드 수, 프레임)이 바뀌지 않는다.
- 전체 개요(`/graph`)는 찾기의 "이동" 묶음에 남는다.

### 2.4 찾기

v1 팔레트(cmdk 1.1.1, 서버 검색, NFC, 150 ms 디바운스)를 왼쪽 위 찾기 알약으로 옮긴다 [v1: 2절]. 결과는 알약 아래로 펼치고 그래프를 덮지 않는다.

| 묶음 | 내용 | 출처 |
|---|---|---|
| 주제 | 이름과 별칭 일치, 조사 상태 칩 | `/v1/search?types=TopicSpec` [ADR-0005 8장] |
| 문서, 메모 | 제목과 본문 문단. private도 나온다(`editor` 토큰) | `/v1/search?types=Page,Note` |
| 엔티티 | v1 그대로 | `/v1/search` |
| 만들기 | "새 주제 '…' 만들고 KB에 조사 요청", "새 문서 '…'", "메모로" | 입력값으로 만든다. 항상 맨 아래 |
| 이동, 시간 | v1 그대로, 전체 개요 | |

- **키.** `Ctrl+K` 하나다(K2 정함). 편집 영역 밖의 `/`도 찾기다. 이전 판의 `Ctrl+Space`는 버렸다(한글 입력기 전환 키와 겹친다).
- **한글.** 조합 중(`isComposing` 또는 `keyCode 229`)의 Enter와 화살표는 처리하지 않는다.
- **Enter.** 활성 결과를 창으로 연다. `Ctrl+Enter`는 맨 앞 창을 그 기록으로 바꿔 연다. 만들기 항목은 같은 이름의 주제가 없을 때만 첫 항목이 된다.
- **활성 결과.** 화살표로 옮긴 결과는 미리보기를 띄우고, 그래프에 보이는 노드면 그 노드도 활성으로 강조한다(2.3절).
- **입력값의 행방.** 찾기 입력은 검색 요청(`/kb/v1/search?q=`)에만 쓰이고 주소, 이력, `localStorage`에 남지 않는다. `loupe serve`는 요청 경로와 쿼리를 기록하지 않는다 [v1: 10절]. 전문 검색 화면은 두지 않는다.
- **입력 분류.** 찾기 입력은 검색 요청 전에 저장 전 검사(5.7절)를 지난다. 비밀 모양이면 검색하지 않고 "＋ 보안 정보로 넣기(KMS)"를 맨 위에 둔다.
- 비밀 값은 찾기에 없다. 비밀 객체의 이름(보안 정보 블록에 적힌 것)과 "보안 정보로 넣기" 명령만 있다(8절).

### 2.5 메모의 제목

KB 기록은 `title`과 `body`가 둘 다 필수다(`title` 300자 이하) [ADR-0005 4.2].

- **첫 줄이 제목이다.** 첫 줄의 앞뒤 공백과 Markdown 머리 기호(`#`, `-`, `>`)를 지우고 60자(문자소 기준)에서 자르며, 잘렸으면 `…`를 붙인다. 본문은 메모 전체다.
- 첫 줄이 비었거나 기호뿐이면 `메모 2026-11-04 09:14`(KST)를 쓴다.
- 카드와 창 머리에 계산된 제목을 흐리게 보이고 누르면 고칠 수 있다. 고친 제목은 `props.title_locked=true`로 저장하고 그 뒤로 자동 계산하지 않는다 [ADR-0005 L301~306].
- 메모를 주제로 승격하면 이 제목이 주제 이름이자 범위 설명이 된다(7.1절).

### 2.6 시간 여행과 쓰기

v1의 시간 기준은 그대로다 [v1: 4절]. **과거 보기나 시점 고정에서는 편집할 수 없다.** 창은 읽기 모드로 열리고 "현재로 돌아가 편집" 단추를 띄운다. 과거 판을 고치는 길은 판 탭의 "이 판으로 되돌리기"뿐이고 그것은 현재에 새 판을 만든다(5.3절).

### 2.7 창 관리자

내용은 모두 창이다(사용자, 2026-11-04: 여러 개를 띄우고 크기를 바꾸고 옮긴다). 블루프린트 W2.

| 항목 | 규칙 |
|---|---|
| 열기 | 노드, 링크, 찾기 결과, 작업 센터 항목, 만들기 단축키가 창을 연다. 이미 열린 기록이면 새로 열지 않고 그 창을 앞으로. 새 창은 맨 앞 창에서 24px씩 비켜 뜬다. 개수 제한은 없다 |
| 초점과 앞뒤 | 누른 창이 맨 앞(z 순서 맨 위)이 되고 굵은 테두리를 단다. 뒤 창은 머리만 흐려지고 내용은 그대로 보인다. 키 입력은 맨 앞 창만 받는다. 그래프는 창 뒤에서 계속 조작된다(어둡게 덮지 않는다) |
| 끌기 | 머리를 끌어 옮긴다. 왼쪽·오른쪽 가장자리에 놓으면 반쪽, 위 가장자리는 최대화로 붙는다. 창은 무대 밖으로 나가지 않는다 |
| 크기 | 네 모서리와 네 변의 손잡이. 최소 360×240 px. 머리 두 번 누르기와 □는 최대화와 복원 |
| 내리기 | 머리의 –, `Alt+M`. 아래 가운데 독의 칩이 된다(U7). 저장 안 한 창의 칩에는 "저장 안 됨"이 붙는다. `Alt+0`은 모두 내린다 |
| 닫기 | ✕, `Alt+W`. 저장 안 한 글이 있으면 먼저 묻는다. 초안은 KB가 받을 때까지 이 탭이 쥔다(5.2절). `Esc`는 창을 닫지 않는다(미리보기, 메뉴, 찾기 결과, 활성을 먼저 푼다) |
| 순환 | ``Alt+` ``와 ``Alt+Shift+` ``(U6) |
| 키보드로 옮기기 | 창 메뉴 "이동·크기" 뒤 화살표 10 px, `Shift`+화살표는 크기, Enter 확정, Esc 취소. `Alt+↑/↓`는 편집기의 블록 옮기기라 창에 쓰지 않는다 |
| 막는 창 | 반영 확인(5.8절)과 확인 필요(7.3절)의 기기 확인 창, 비밀 창(8절)만 뒤를 어둡게 덮고 다른 창 조작을 막는다 |
| 좁은 폭(600~1023 px) | 같은 관리자. 새 창은 무대 폭의 92%로 계단식으로 뜨고, "나란히"는 위아래 두 칸. 손잡이 44 px, 터치는 머리 길게 누르고 끌기 |
| 주소 | 맨 앞 창의 기록 하나(`#/w/<id>`)와 v1 화면 파라미터. 링크 복사는 그 창이다. 주소로 들어오면 그 기록 창 하나를 연다(v1 완료 기준 2, URL 재현) |
| 배치 기억 | 창마다 ID, 위치, 크기, 내림 여부만 이 탭의 `sessionStorage`에 둔다. 새로 고치면 되살리고 제목과 본문은 다시 읽는다(U8). 만료 뒤 다시 로그인해도 같은 탭이면 되살린다 |
| 접근성 | 창은 `role="dialog"`가 아니라 `role="region"`과 `aria-label`(종류). 막는 창만 `role="dialog" aria-modal="true"`. 맨 앞 창이 바뀌면 `aria-live`로 "문서 창, 3개 중 1번째"를 읽는다 |

- 구현은 자체 컴포넌트다. 위치·크기·z 순서 상태 하나와 포인터 이벤트(끌기, 손잡이)뿐이라 라이브러리를 들이지 않는다. `react-rnd` 같은 후보는 M0c에서 크기와 유지 상태를 비교해 쓸 만하면 쓴다(3번 지침) `[가정]`.

### 2.9 폰: 메모와 대화의 흐름

## 4. 편집기와 데이터베이스 컴포넌트 (C)

### 4.1 판단 기준

1. **원본이 KB의 Markdown이다.** KB 본문은 `body_format=markdown`(또는 `text`)이다 [KB답]. 블록 JSON을 원본으로 삼는 편집기는 저장마다 변환 손실이 판에 쌓인다.
2. **손대지 않은 문서는 보내지 않는다.** 저장 여부는 직렬화 결과의 비교가 아니라 편집 트랜잭션 유무로 정한다. 그래서 왕복이 바이트 단위로 같지 않아도 열고 닫기만 한 문서에 판이 생기지 않는다. 고친 문서에서는 손대지 않은 블록의 바이트가 바뀌는 비율을 v2-0에서 잰다. AST가 같다는 것만으로는 같은 Markdown이 보장되지 않는다(Codex 7).
3. **한글 IME.** 웹 검색으로는 후보별 한국어 결함 보고를 찾지 못했다 [출처: 부록 C]. 헤드리스 시뮬레이션과 **실제 Windows 한국어 IME 확인** 둘 다 통과해야 확정이다.
4. **읽기 화면과의 일치.** loupe는 읽기에 unified 11.0.5, remark-parse 11.0.0, remark-gfm 4.0.1, rehype-sanitize를 쓴다 [v1: 9절]. 같은 파서를 쓰면 `[[id]]`와 GFM 해석이 한 곳에 있다.
5. 라이선스, 크기, 유지 상태. 아래 후보 전부 설치 스크립트가 없다 [측정: `npm view <패키지> scripts`]. 인증 파일과 셸 설정을 건드리는지는 v2-0에서 잠금 파일 기준 소스 감사로 다시 본다. 크기는 압축 전 패키지 크기가 아니라 **운영 빌드의 gzip 증가분**으로 판정한다.
6. loupe의 7일 릴리스 대기 규칙을 지킨다 [v1: 머리말].

**M0a의 Tiptap 작업과 완료 조건.**

1. **코드 펜스 직렬화.** 펜스 길이를 코드 안의 가장 긴 백틱 연속보다 하나 길게(최소 3) 고르도록 직렬화를 고친다. 물결 펜스도 같은 규칙. 완료: `tilde-code-fence`와 내부 백틱 3·4·5개 표본이 재파싱 뒤 같은 코드 블록 구조와 내용.
2. **`[[id]]` 위키 링크 노드.** 사용자 정의 인라인 노드가 `[[id]]`를 파싱하고 **이스케이프 없이** 그대로 직렬화한다. 화면은 4.4절의 칩. 완료: 코퍼스의 위키 링크 표본 전부가 바이트 일치이고, 같은 본문을 읽기 화면의 remark 플러그인이 같은 ID 목록으로 읽는다.
3. **왕복 실패 감소.** 같은 36개 코퍼스에서 "그 외 변경"을 **17개에서 8개 이하로** 줄이고, 재파싱 구조가 원문과 달라지는 표본은 **0개**로 만든다. 남는 변경은 의미가 같은 형식 차이(목록 기호, 표 정렬 등)만이고 표본별 목록을 남긴다. 4.1절 2번(손대지 않은 문서는 보내지 않음)이 있으므로 이 수치는 고친 문서에만 걸린다.
4. **실제 한글 IME.** 사용자가 Windows 11 Microsoft 한국어 IME(두벌식)로 Chrome에서 스파이크의 13개 사례를 손으로 친다. **이것이 유일한 진짜 IME 근거다.** 최종 글자, 커서, 중복·누락, 조합 중 Enter·Ctrl+Enter·Backspace, 확정 뒤 실행 취소, 블록 이동을 보고 OS·브라우저·IME 판을 남긴다.
5. 운영 빌드 gzip: loupe에 넣은 뒤 편집기 청크의 gzip 증가분을 재고 편집 화면에서만 지연 로드되는지 `check-dist`로 막는다.
6. 4.5절의 악성 붙여넣기 묶음과 Trusted Types 위반 수.

- 문서와 메모의 `props`는 셀에서 고친다. 셀 하나도 기록 전체의 새 판이고 `expected_version`을 싣는다 [KB답]. 엔티티 칸은 주장에서 오므로 읽기 전용이다.

### 4.4 링크와 본문 규칙

`[[id]]`만 `LINKS_TO`가 되고 대상은 공개 ID여야 한다 [KB답]. **저장 본문의 모든 `[[...]]`는 해결된 ID다.**

| 쓸 때 | 저장 본문 | 화면 |
|---|---|---|
| `[[`를 치면 찾기와 같은 검색이 뜨고 고른 항목이 들어간다(Obsidian UX) | `[[e:product:claude-code]]` | 대상의 현재 라벨로 그린 칩 |
| 고르지 않고 닫았다 | `[[`, `]]` 없이 글자 | 점선 밑줄 "링크 아님" |
| `[[c-…]]` 단독 줄 | 그대로 | v1 주장 카드. 모양은 `c-`+base32 12자, 대상이 없으면 400 `link_dangling` [ADR-0005 4.6] |
| ` ```loupe-view ` | 그대로 | 데이터베이스 보기 |

- 별칭 표기 `[[id|라벨]]`은 KB가 받는다. `|` 뒤는 본문 글로만 남는다 [ADR-0005 4.3]. loupe는 `[[id]]`를 기본으로 쓰고 사용자가 라벨을 고친 링크만 `[[id|라벨]]`로 저장한다.
- **크기.** 본문이 64 KB를 넘으면 KB가 `raw/fp`로 옮기고, FW5 전까지 그 본문 읽기는 410 `content_removed`다. 본문 상한은 1 MiB(413)다 [ADR-0005 4.5]. 편집기 바닥에 크기를 보이고 48 KB에서 노란 칩, 64 KB에서 "이 크기를 넘으면 당분간 loupe에서 다시 열 수 없다. 나눠 쓰기를 권한다", 1 MiB에서 저장을 막는다.
- **첨부 없음** [KB답]. 이미지를 붙여 넣거나 끌어 놓으면 받지 않고 "KB는 첨부를 저장하지 않는다"를 띄운다.

### 4.5 편집기 안전

v1의 읽기 sanitize는 편집기의 안전 근거가 아니다(Codex 3). 편집기는 사용자 붙여넣기와 다른 작성자(`f:agent:…`)의 본문을 DOM으로 만든다.

| 경로 | 규칙 |
|---|---|
| 스키마 | 편집기 스키마는 허용 목록이다: 문단, 머리글, 목록, 할 일, 인용, 코드 블록, 표, 구분선, 강조, 코드, 링크, `[[id]]` 칩, 주장 인용 블록, 보기 블록. 나머지 노드와 표시는 글자로 떨어진다 |
| raw HTML | Markdown 안 HTML은 노드로 만들지 않고 글자로 보인다(v1 `remark-rehype` raw 끔과 같은 방침) |
| 링크 | `href`는 `http`, `https`만. 나머지는 링크를 지우고 글자만 남긴다. 렌더는 v1 외부 링크 규칙(`noopener noreferrer`, `no-referrer`) [v1: 9절] |
| 붙여넣기 | HTML 붙여넣기는 ProseMirror 스키마 파서만 지나고, 그 전에 모든 속성을 지운다(`href`만 위 규칙으로 남김). `img`, `svg`, `iframe`, `style`, `script`, `form`은 버린다. 평문 붙여넣기는 Markdown으로 파싱한다 |
| 노드 뷰 | 칩, 주장 카드, 보기 블록은 React 컴포넌트이고 값은 텍스트 자식으로만 넣는다. `innerHTML`, `dangerouslySetInnerHTML` 금지는 v1 ESLint 규칙 그대로 [v1: 9절] |
| CSP | v1 정책 유지(`script-src 'self'`, `connect-src 'self'`, `default-src 'none'`) [v1: 9절]. 쓰기도 같은 출처 `kb-write/`라 넓히지 않는다 |
| Trusted Types | `require-trusted-types-for 'script'`를 목표로 한다. ProseMirror 클립보드 파서가 분리된 요소에 `innerHTML`을 쓰므로 소독 뒤 통과시키는 이름 있는 정책 하나가 필요할 수 있다 `[가정]`. 적용 가능성과 위반 수를 v2-0에서 잰다. 불가하면 이유를 남기고 CSP와 스키마로 막는다 |

**시험(첫 쓰기 전, 11.1절 M1).** 악성 붙여넣기 묶음(`<script>`, `onerror`, `javascript:`·`data:` 링크, SVG, CSS 표현식, 중첩 `iframe`)과 악성 KB 본문(다른 작성자가 쓴 것으로 kb-mock에 넣음)을 편집기에 넣고 대화상자 0, 페이지 오류 0, 다른 출처 요청 0, CSP와 Trusted Types 위반 0, 저장 본문에 허용 밖 노드 0을 단언한다.

## 5. 쓰기 모델 (D)

KB의 쓰기 계약은 ADR-0005 9판(`42980bf`)이다 [ADR-0005]. 9판은 KB가 아직 구현하지 않았고 보완 뒤 재검토 전이다(ADR 머리말). 실제 KB 쓰기는 FW1~FW4·FW8 뒤이므로, 그 전의 모든 단계는 ADR 모양을 흉내 내는 kb-mock으로 검증한다(11절).

### 5.1 경로와 토큰

**하나의 소켓, 토큰 둘.** KB는 쓰기 전용 소켓을 두지 않는다. 읽기와 쓰기가 같은 Unix 소켓이고 경계는 토큰 범위다 [ADR-0005 2.1, 3.1]. 이전 판의 "쓰기 전용 0600 소켓" 가정은 버렸다.

| 토큰 | 범위 | `loupe serve`가 붙이는 곳 |
|---|---|---|
| `editor`(`kb token create --scope editor --label loupe`, TTY) | `private` 이하 읽기, 2.2의 기록·승격·연구 쓰기 | 모든 `/kb/*` 읽기와 `/kb-write/*`. 소켓 읽기에도 Bearer를 싣는다. 그래야 `private`가 보인다. 틀린 토큰은 401이고 무토큰 범위로 낮추지 않는다 [ADR-0005 L223] |
| `reviewer`(`--scope reviewer --label loupe-review`, TTY) | `editor`와 같은 읽기 + HITL 해결과 사용자 동작 | `GET /v1/hitl`, `/v1/hitl/*`, `POST /v1/actions*`, `GET /v1/actions/{id}`, `POST /v1/reviewer/enroll`에만. 두 토큰을 함께 보내지 않는다 [ADR-0005 L225~226] |

- 두 토큰은 `~/.config/loupe/kb-editor.token`, `kb-reviewer.token`(0600, 6.3절의 설정 디렉터리 규칙)에 있다. 브라우저, 환경 변수 값, 명령줄, 로그에 두지 않는다. 만료는 180일이고 남은 날을 설정 창에 보인다 [ADR-0005 3.3].
- Google 로그인은 누가 `loupe serve`를 쓰는지 가르는 loupe 안의 관문이다. KB는 그것을 보지 않는다. KB에 사람이 했다는 증명은 동작마다의 WebAuthn뿐이다(5.8절) [ADR-0005 3.2, 6.8].

**브라우저 → `loupe serve` → KB.** 브라우저는 같은 출처의 `kb-write/<동작>`에 `POST`만 보낸다. `loupe serve`가 고정 경로표로 KB 메서드에 대응시키고, 표 밖은 404다.

| 브라우저 | KB [ADR-0005 2.2] | 토큰 |
|---|---|---|
| `POST /kb-write/records` | `POST /v1/records` | editor |
| `POST /kb-write/records/{id}` | `PUT /v1/records/{id}` | editor |
| `POST /kb-write/records/{id}/tombstone` | `POST /v1/records/{id}/tombstone` | editor |
| `POST /kb-write/records/{id}/promote` | `POST /v1/records/{id}/promote` | editor |
| `POST /kb-write/topics/{spec}/research` | `POST /v1/topics/{spec}/research` | editor |
| `POST /kb-write/topics/{spec}/research/{run}/stop` | `POST /v1/topics/{spec}/research/{run}/stop` | editor |
| `POST /kb-write/writes/{ref}/discard` | `DELETE /v1/writes/{ref}` | editor |
| `POST /kb-write/actions`, `…/actions/challenge`, `…/actions/{id}/external-refine`, `…/actions/{id}/execute` | `POST /v1/actions`, `/v1/actions/challenge`, `/v1/actions/{id}/external-refine`, `/v1/actions/{id}/execute` | reviewer |
| `POST /kb-write/hitl/challenge`, `…/hitl/{item}/resolve` | `POST /v1/hitl/challenge`, `/v1/hitl/{item}/resolve` | reviewer |
| `POST /kb-write/reviewer/enroll` | `POST /v1/reviewer/enroll` | reviewer |

- 읽기 허용 목록(`KB_ALLOW`)에 `/v1/topics/{id}/research`, `/v1/writes/{ref}`, `/v1/actions/{id}`(reviewer), `/v1/hitl`(reviewer), `/v1/nodes/{id}/reviews`를 더한다. `/v1/ops/*` 제외는 그대로다 [v1: 10절].
- 모든 쓰기 호출은 브라우저의 `src/data/write.ts` 하나를 지난다. 이 어댑터가 필수 필드(`title`, `body`), `[[...]]`의 모양(종류별 정확한 모양, ADR-0005 4.6), 민감도(`public`, `internal`, `private`. `secret`은 막음)를 보내기 전에 확인하고, 응답을 5.9절의 상태로 바꾼다.
- 쓰기 응답은 `Cache-Control: no-store`다. `loupe serve`는 요청과 응답 본문을 기록하지 않는다.

### 5.2 저장

**요청 모양** [ADR-0005 2.4]: `{idempotency_key, change, on_secret?, record:{type, title, body, body_format, sensitivity?, props, links}, expected_version?}`. `change`는 `save`(사람이 누른 저장), `autosave`(자동 저장 단계), `auto`(사람 아닌 동작)다. loupe의 첫 단계는 `save`만 쓴다.

| 항목 | 첫 단계(M1~M2) | 나중(11.3절) |
|---|---|---|
| 언제 | `Ctrl+S`, 저장 단추, 메모의 `Ctrl+Enter`, 폰 보내기. 저장 안 한 채 탭을 닫으면 경고 | 자동 저장: KB 판은 30초 무입력, 창 닫기·내리기·초점 이탈, 탭 닫기, 계속 입력 중 5분마다, 명시 저장. `autosave`는 기록별 30초에 1판(넘으면 429) [ADR-0005 5.8] |
| 만들기 키 | `loupe:c:<초안 UUID>`. `change`를 넣지 않는다 [ADR-0005 5.1] | |
| 편집 키 | `loupe:e:<id>:v<expected_version>:<change>:r<개정 번호>`. 개정 번호는 같은 판 위에서 보낸 내용의 일련번호다. 이전 판의 본문 해시 칸은 버렸다(ADR이 다이제스트 칸을 피하라고 한다) | |
| 응답 | `id`, `version`, `unchanged`, `spooled`, `held`, `write_ref`, `payload_sha`, `quarantined`, `warnings`, `actor`(`app:loupe`), `claimed_author`(`user:sagae`) | |
| 저장 칩 | 저장 안 됨 / 저장 중 / 저장됨 v7 / 변경 없음 / 보내는 중(이유) / 저장 거절 / 격리 보관 / 충돌 | 기기에만 저장됨 |

**저장 직렬화.**

- 한 기록에 진행 중인 저장은 하나다. 저장 중에 또 저장하면 마지막 내용 하나만 대기열에 남기고, 앞 저장의 응답(새 `version`)을 받은 뒤 그 판을 `expected_version`으로 보낸다.
- 응답을 못 받았으면(시간 초과, 연결 끊김) **같은 키로** 다시 보낸다. KB는 같은 키에 첫 응답을 돌려준다. 만들기 키에 다른 내용을 보내면 재생이 아니라 409 `version_conflict` + `current`다 [ADR-0005 5.1].
- **자기 저장 인식.** 응답을 잃은 뒤 더 고쳐 보냈다가 409가 오면, `current.payload_sha`가 내가 마지막으로 보낸 내용의 `payload_sha`와 같을 때 내 저장으로 보고 `current.version` 위에 다시 보낸다. 아니면 5.3절의 충돌 화면이다. 이전 판의 "작성자가 `f:user`면" 규칙은 버렸다(작성자는 늘 `app:loupe`다).
- 낡은 `expected_version`이면 내용이 같아도 409다 [ADR-0005 2.3]. 그래서 변경 없음 판정은 KB 응답의 `unchanged`로만 한다.

**스풀과 초안 보존** [ADR-0005 5.9]. 202 `spooled` 또는 `held`면 `write_ref`를 `GET /v1/writes/{ref}`로 45초마다 따라간다(뒤에서 도는 요청이라 유휴 시간을 갱신하지 않는다, 6.1절 5). 초안은 다음 중 하나일 때만 지운다: 그 내용의 200·201, `write_ref`가 `committed`, 판 이력에 같은 `payload_sha`, 사용자가 버림. `failed`가 되면 그 창에 비교 띠를 띄우고(탭 메모리의 초안이 없으면 `GET /v1/writes/{ref}?include=body`로 내가 보낸 사본을 purge 전까지, 최대 7일 받는다. 그 뒤는 410 [ADR-0005 L610~612]), 사용자가 버리면 `DELETE`(`/kb-write/writes/{ref}/discard`)로 KB의 실패 본문도 지운다. 첫 단계의 초안은 탭 메모리뿐이다. `write_ref`(ID일 뿐 내용이 아니다)는 이 탭의 `sessionStorage`에도 두어 새로 고친 뒤에도 따라간다. 탭을 닫으려 하면 경고한다.

### 5.3 실행 취소, 되돌리기, 충돌, 보관

- **실행 취소.** 편집기 안의 `Ctrl+Z`는 편집기 이력이다. 저장된 판을 되돌리지 않는다.
- **판 되돌리기.** 판 탭(`/v1/nodes/{id}/history`)에서 판을 고르면 비교해 보이고 "이 판으로 되돌리기"는 그 내용으로 새 판을 만든다 [계약: C 6.4]. 판마다 "user:sagae · app:loupe" 또는 에이전트 작성자를 적는다. 10분 안의 연속 판은 한 줄로 접는다.
- **충돌.** 409 `version_conflict`이면 [ADR-0005 5.4] 편집기를 막지 않고 비교 띠를 띄운다. 응답의 `current`(판, `payload_sha`, `actor`, 본문 200,000자까지)로 기준 판, 내 변경, 다른 쪽 변경을 블록 단위로 나란히 보이고 블록마다 "내 것", "저쪽", "둘 다"를 고른다. 결과는 `current.version`을 `expected_version`으로 삼아 저장한다. 대상이 숨었으면 404, tombstone이면 `{version, status}`뿐이라 "다른 곳에서 보관됨"을 보인다. 같은 브라우저의 탭 둘은 BroadcastChannel로 "다른 탭에서 편집 중"을 미리 알린다.
- **보관은 HTTP tombstone이다** [ADR-0005 5.5]. 창 메뉴의 "보관"은 `expected_version`과 `reason`(500자 이하)을 실어 보낸다. 복원은 `PUT expected_version=<tombstone 판>`이다. 조사가 열린 주제는 409 `research_running`이라 먼저 멈춘다. 휴지통 창은 `GET /v1/nodes?origin=first_party&status=dead&types=Page,Note,TopicSpec,Review`이고 loupe가 만든 것만 나온다 [ADR-0005 L1011]. 거기서 복원한다(M2).
- **완전 삭제는 터미널에서.** "완전 삭제…"는 설명 상자만 연다: "KB는 TTY의 `kb redact <id>`로만 지운다. 되돌릴 수 없다." loupe는 실행하지 않는다.

### 5.4 기기 안 초안(나중, O9)

검사 전 내용을 IndexedDB에 쓰면 뒤에 지워도 "남지 않는다"를 지킬 수 없다(Codex 1). 그래서:

- **첫 단계에는 기기 저장 초안이 없다.** 끊긴 동안의 글은 탭 메모리에만 있고 탭을 닫으면 경고 뒤 잃는다.
- 자동 저장 단계에서 초안을 둔다면 **KB와 같은 규칙의 로컬 선검사를 통과한 내용만** 디스크에 쓴다. 규칙 집합은 KB가 공개한다(5.7절). 선검사에 걸리면 디스크에 쓰지 않고 5.7절 경고를 미리 띄운다.
- 초안은 탭이 아니라 초안 ID로 두고, 지우는 조건은 5.2절의 네 가지다. 재시작 뒤 재전송은 초안에 저장한 멱등 키 그대로 보낸다.

### 5.5 비밀이 섞인 쓰기

**KB는 비밀 모양을 거절한다** [ADR-0005 7.1~7.4]. 편집기 경로의 기본은 422 `secret_detected`와 `hits`(순번 필드, 코드포인트·UTF-16 구간, 규칙 ID)이고 아무 데도(원장, 스풀, 보류) 쓰지 않는다. 이전 판의 "KB가 격리하고 loupe가 화면에서 내린다"는 거절로 바뀌었다.

| loupe 동작 | 이유 |
|---|---|
| 그 창에서 `hits`의 UTF-16 구간을 칠하고 규칙 ID만 보인다. 값을 다시 그리지 않는다 | 무엇이 걸렸는지 안다 |
| 고를 길 셋: **보안 정보로 바꾸기**(구간을 본문과 실행 취소 이력에서 지우고 비밀 창의 "새 보안 정보"), **구간 고치기**, **비밀 아님 · 격리 보관** | 사용자가 분류를 고친다(5.7절) |
| "비밀 아님 · 격리 보관"은 같은 만들기 키, `change:"save"`, `on_secret:"quarantine"`으로 다시 보낸다. KB는 `secret`으로 격리해 저장하고 경고 `secret_detected:<규칙>`을 준다. loupe는 그 기록을 창, 백링크, DB 행, 찾기 최근 항목에서 내리고 편집기 상태와 실행 취소 이력을 버린다 | 격리된 기록은 `editor`도 읽지 못한다. `Ctrl+Z`로 값이 돌아오지 않는다(Codex 1) |
| 격리 뒤 그 ID의 404는 "격리됐거나 없음"으로 보인다 | 격리와 없음을 가르지 않는다(KB 규칙) |
| 되살리기는 사용자 동작 `release`(5.8절, 기기 확인). TTY `kb secret release`도 같은 증명을 거친다 [ADR-0005 6.8] | 해제는 사람 확인이다 |
| 작업 센터에 오류 항목: 기록 ID, 규칙 ID, 시각만 | 나중에 다룬다 |

- 붙여넣기처럼 큰 글은 `?dry_run=1`로 먼저 볼 수 있다. KB는 원장, 스풀, 큐, 로그 어디에도 남기지 않고 입력을 되풀이하지 않으며 `{would_reject, hits, secret_rules}`만 돌려준다 [ADR-0005 L993]. 다만 값이 `loupe serve`와 KB 메모리로 가므로 5.7절의 "서버로 가기 전에 멈춘다"를 대신하지 못한다.
- 이 절은 **뒷받침**이다. 첫 방어는 5.7절의 입력 분류와 저장 전 검사다. 422가 뜬다는 것은 저장 전 검사가 놓쳤거나 규칙 판이 어긋났다는 뜻이므로 거절 카드에 "저장 전 검사가 놓친 것"이라고 함께 적고 규칙 판을 설정 → KB 상태에 보인다.

### 5.6 민감도와 `private`

`sensitivity`는 `public`, `internal`, `private`, `secret`이다. **loupe의 새 `Page`·`Note`·`TopicSpec`·`Review`는 생략하면 `private`다**(사용자 확정, ADR-0005 3.6). 이전 판의 D11("loupe는 private를 만들지 않는다")은 뒤집혔다: `editor`·`reviewer` 토큰이면 `private`의 목록, 검색, 본문, 판 이력, 엣지와 그래프를 읽는다. 다른 주체(MCP, Claude Code 세션, `viewer`)에게는 보이지 않고 직접 조회도 `not_found`다. 거꾸로 `editor`·`reviewer`는 loupe가 쓴 것만이 아니라 **모든 작성자의 `private` 기록**을 읽는다 [ADR-0005 3.6]. 그래서 다른 앱이나 TTY가 쓴 비공개 기록도 loupe 그래프와 찾기에 나온다.

- **첫 단계의 판정.** `/v1/meta.write.private_open`이 참일 때만 `private` 만들기를 연다. 거짓이면 만들기 단추를 막고 "KB가 아직 비공개 기록을 받지 않는다"를 보인다(FW2·FW5 전) [ADR-0005 3.6].
- **만들 때 고르기(O1).** 메모는 늘 `private`다. 문서와 주제는 만들기 창에서 "내부"(`internal`)를 고를 수 있고 "Claude 세션이 읽는다"를 한 줄로 적는다. `public`은 loupe에 없다.
- **높이기**(`internal` → `private`)는 `editor`로 바로 된다. **낮추기**는 `PUT`이나 승격으로 하지 못하고(403 `declassify_requires_review`) 사용자 동작 `declassify`나 `publish`와 기기 확인을 거친다(5.8절).
- **상속.** 승격한 주제, 연구 티켓, 실행, 반영 후보는 원본의 민감도를 물려받는다. `private` 주제는 `export_llm`, `export_query`가 늘 거짓이다(7.4절).
- `secret`과 격리는 `private` 위다. `editor`도 읽지도 쓰지도 못한다.

### 5.7 입력 때의 분류 (D12)

사용자 결정: 비밀은 KB 쪽에서 뒤늦게 알게 되는 것이 아니라 **넣을 때 loupe 화면에서 가른다.** 정보를 넣을 때마다 "일반"과 "보안 정보" 중 하나를 고르는 분명한 조작이 있다.

| 분류 | 가는 곳 | 화면 |
|---|---|---|
| 일반 | KB first_party 기록 | 메모, 문서, 주제 |
| 보안 정보 | **KMS뿐.** KB에는 값이 가지 않는다 | 비밀 창(8.3절)의 "새 보안 정보" 양식 |

**넣는 곳마다의 조작**

| 곳 | 조작 | 보안 정보를 고르면 |
|---|---|---|
| 만들기 창(빠른 만들기, 메모) | 머리의 두 칸 전환 `[일반 \| 보안 정보]`. 기본은 일반. `Alt+S`로 바꾼다 | 입력칸을 비우고 잠그며 "보안 정보는 비밀 창에서 넣는다 → 비밀 창 열기"를 보인다. 이미 친 글은 넘기지 않고 지운다(실행 취소 이력 포함) |
| 찾기 | 만들기 묶음에 "＋ 보안 정보로 넣기(KMS)". 입력이 비밀 모양이면 이 항목이 맨 위로 온다 | 찾기 입력을 지우고 비밀 창을 연다 |
| 문서 | 슬래시 명령 `/보안 정보`가 **보안 정보 블록**을 넣는다. 블록에는 이름 칸과 "비밀 창에서 값 넣기" 단추만 있다 | 본문에는 참조만 남는다: ` ```loupe-secret-ref ` 블록에 KMS 항목 이름. 읽기 화면에서는 자물쇠 칩 "보안 정보: <이름> · 비밀 창에서 열기" |
| 데이터베이스 속성 | 속성 유형 "보안 정보 참조". 셀에는 이름만 | 문서와 같다 |
| 폰 입력줄 | ＋ → "보안 정보" | 비밀 창 새 탭 |
| 주제 만들기 | 없다. 주제 글은 KB로 가는 글이다. 비밀 모양이면 저장 전 검사가 멈춘다 | |

- **값을 창 사이로 넘기지 않는다.** loupe 본 출처와 비밀 창은 메시지를 주고받지 않는다(8.1절). 이미 친 값을 옮기는 길은 사용자가 비밀 창에 다시 붙여 넣는 것뿐이다.
- 보안 정보 블록의 **이름은 KB로 간다.** 이름 칸 아래에 "이 이름은 KB에 저장된다"를 적는다. KB는 KMS 참조 문자열을 지식으로 투영하지 않는다 [ADR-0004 T.1]. 그래프의 자물쇠 노드는 이 이름이다.

**저장 전 검사.** 일반으로 분류한 입력도 보내기 전에 브라우저 안에서 **KB와 같은 규칙**으로 검사한다.

- 규칙 집합은 KB가 공개한다: FW1이 `docs/contracts/first-party-secret-rules-v1.json`(판, 규칙 ID·패턴·플래그, 구간 정의, 합성 시험 벡터)을 내고 `/v1/meta.write.secret_rules`에 `{version, sha}`를 싣는다 [ADR-0005 L989~995]. loupe는 빌드 때 KB 저장소의 그 계약 파일을 읽어 넣고(원본은 KB에 두고 복사본을 원본처럼 두지 않는다), 시작 때 판과 해시를 `/v1/meta.write.secret_rules`와 비교한다. 다르면 사전 검사를 끄고 칩 "비밀 사전 검사 꺼짐: 규칙 판이 다르다"를 띄운다. 서버 검사가 권위이고 브라우저 검사는 안내다. FW1 전에는 kb-mock이 같은 모양의 규칙 fixture를 낸다(M1).
- 검사 대상: 메모와 문서의 제목과 본문, 속성 값, 주제 이름·범위·별칭, 찾기 입력(검색 요청 전), 폰 입력줄. 찾기 입력이 걸리면 **검색 요청을 보내지 않는다.**
- 걸리면 저장을 멈추고 그 구간을 가린 채 표시한다(규칙 ID만). 고르는 길은 셋이다.

| 선택 | 결과 |
|---|---|
| 보안 정보로 바꾸기 | 그 구간을 본문과 실행 취소 이력에서 지우고, 문서라면 그 자리에 보안 정보 블록을 넣고, 비밀 창의 "새 보안 정보"를 연다 |
| 고치기 | 저장하지 않고 편집으로 돌아간다 |
| 일반으로 보내기 | "비밀 아님"을 확인하고 보낸다. KB가 같은 규칙으로 422를 낼 수 있고 그때 5.5절의 "비밀 아님 · 격리 보관"으로 간다. 이 선택은 그 구간에만 적용되고 기억하지 않는다 |

- 규칙이 모든 비밀을 잡지는 못한다. 사람이 고른 분류가 첫째이고 검사는 둘째다.

### 5.8 사용자 동작과 기기 확인

사람 확인이 필요한 동작은 넷이다: **지식베이스에 반영**(`publish`), **격리 해제**(`release`), **공개 범위 낮추기**(`declassify`), **확인 필요 해결**(HITL) [ADR-0005 5.10, 6.8]. 모두 `reviewer` 토큰과 동작마다의 WebAuthn 사용자 확인(`userVerification:"required"`)을 요구하고, KB가 root 소유 신뢰 저장소(`/etc/sagae-kb/reviewers`)의 공개 키로 검증한다. 같은 증명을 다른 동작이나 바뀐 결과에 쓰지 못한다.

**지식베이스에 반영: 두 번의 확인**(사용자 결정 O2, ADR-0005 5.10 L624~646, 블루프린트 흐름 g, W7). 준비는 로컬에서만 하고, 외부 정제는 보낼 내용에 묶인 첫 번째 기기 확인 뒤에만, 결과 공개는 두 번째 기기 확인 뒤에만 일어난다.

| 단계 | 화면 | KB 호출 | 밖으로 나가는 것 |
|---|---|---|---|
| ① 로컬 준비 | 메모 창 머리의 "지식베이스에 반영". 확인 창 없이 바로 시작하고 작업 센터에 "반영 · 로컬 정제 중" | `POST /v1/actions {action:"publish", target, expected_version, idempotency_key:"loupe:a:<note>:v<n>:<UUID>"}` → **202** `{action_id, state:"preparing", status_url}`. 그 뒤 `GET /v1/actions/{id}`를 1초부터 늘려 가며 따라간다 | **없다.** 엔진 선택과 외부 필요성 판단도 로컬이다 [ADR-0005 L627] |
| ② 외부 정제 동의(필요할 때만) | 준비가 `ready`이고 `external_refine.status=consent_required`면 항목이 "외부 정제 동의 필요"가 된다. 누르면 **동의 창**(막는 창): 보낼 요청 미리보기(`external_refine.request_preview`), 엔진·모델, `external_payload_sha` 앞자리, "이 메모 v<n> 하나만, 이 요청 한 번만 보낸다. 다른 private 기록과 링크된 제목은 넣지 않았다", 로컬 결과가 있으면 "로컬 결과로 계속" | `POST /v1/actions/challenge {action_id, action:"publish_external_refine"}`(120초) → `navigator.credentials.get` → `POST /v1/actions/{id}/external-refine {challenge_id, assertion, idempotency_key}` → 202, `refinement_mode=external_consented`, 다시 `preparing` | 동의를 검증한 뒤 고정한 요청 본문 한 번. 다시 보내려면 새 동의 [ADR-0005 L628~633] |
| ③ 결과 확인 | 준비가 `ready`면 "확인 기다림 · 엔진 · 비용 · 걸린 시간". 누르면 **결과 확인 창**(막는 창): 원본(고정 판)과 후보를 나란히, 엔진(`engine.kind`, `backend`, `model`), `cost_usd`, `duration_ms`, 외부로 보낸 것(없음 또는 동의한 요청 1건), 확인이 묶이는 것(원본 ID와 판, 결과별 타입·민감도·본문 해시) | `POST /v1/actions/challenge {action_id, action:"publish"}` → `navigator.credentials.get` → `POST /v1/actions/{id}/execute {challenge_id, assertion, idempotency_key}` | 없다. KB가 `internal` `Note`·`Page`와 `PROMOTED_FROM`을 쓴다. 원본은 `private` 그대로 |

- **두 확인은 서로 대신하지 못한다.** 외부 정제를 시작하면 앞서 받은 로컬 결과용 도전은 무효다 [ADR-0005 L635].
- **준비 상태** [ADR-0005 L638~646]: `preparing`(후보 없음) → `ready`(후보, 엔진, 비용, 시간. 15분 동안 확인 가능, `expires_at`) → 실행되면 `expired`·`executed:true`와 `result`. `failed`는 고정 `code`(예: `prepare_timeout`, 로컬 결과도 없고 외부가 필요하면 `external_consent_required`). 준비 중의 도전·실행은 409 `write_in_flight`.
- **실패와 화면.** 403 `external_consent_required`: 동의 없이 외부가 필요하다 → 동의 창이나 로컬 결과. 403 `review_unverified`: 기기 확인 실패 → 다시 확인. 409 `review_stale`: 원본이나 결과가 바뀌었거나 기한이 지났다 → 다시 준비. 503 `review_trust_unavailable`: 신뢰 저장소 없음·안전하지 않음 → 단추 잠김과 이유 [ADR-0005 L959].
- 확인 창 문구: "기기 확인은 화면의 뜻까지 보증하지 않는다. 보낼 내용과 후보를 읽고 누른다." [ADR-0005 6.8 남는 위험].
- `declassify`(목표 민감도를 함께), `release`(내용 없이 ID·타입·규칙 ID·시각만)는 LLM이 없어 준비가 201이고 그 뒤 도전 → 실행 한 번이다. 창 메뉴 "공개 범위 낮추기"와 격리 알림의 "되살리기"가 연다.
- HITL은 7.3절. 경로는 `/v1/hitl/challenge`, `/v1/hitl/{item}/resolve`다.
- **인증기 등록**(O3): 설정 → 기기 → "등록 시작" → `navigator.credentials.create` → `POST /v1/reviewer/enroll`이 등록 ID를 돌려준다 → 사용자가 PC 터미널에서 `sudo kb reviewer enroll --request <ID>`. Windows Hello를 주로, 보안 키 하나를 예비로. RP ID는 `localhost`, 허용 출처는 `http://localhost:4812`이고 RP마다 허용 출처 목록을 따로 둔다 [ADR-0005 L832~836]. 폰 출처(M1)를 더하면 그 RP ID로 다시 등록한다.
- 인증기가 없거나 `/v1/meta.write.hitl.available`이 거짓이면, 또는 자기 출처의 `hitl.rp_ids[].registered`가 거짓이면 네 동작의 단추를 잠그고 이유(`trust_store`: `missing`, `unsafe`, `unreadable`)를 보인다 [ADR-0005 8.1].

## 6. 로그인 (D6, D17)

사용자 결정(2026-11-04): loupe에 로그인을 두고, **신원은 Google 계정**이다. 허용 계정은 하나이고 Google의 `sub`로 가린다. loupe 세션은 유휴 1시간이고 갱신이 없다. 시간이 지나면 다시 Google로 로그인한다. 로컬 토큰만으로는 UID를 가르지 못한다는 Codex 1차 3의 지적이 이것으로 닫힌다. 같은 UID는 여전히 막지 못한다(6.7절).

### 6.1 흐름

OIDC authorization code + PKCE(S256), loopback 리디렉션이다. 토큰 교환은 `loupe serve`가 한다. 브라우저는 Google 토큰을 보지 않는다.

1. 로그인 화면은 "Google로 로그인" 단추 하나다. **loupe는 어떤 암호도 받지 않는다**(6.5절 비상 경로 제외). 단추는 `POST /auth/google/start`를 부른다(6.3절 검사). 서버는 `login_id`, `state`(256비트), `nonce`(256비트), PKCE `code_verifier`를 만들어 메모리에 5분 둔다. 응답은 Google 인가 주소와 `login_id`, 그리고 이 탭만 아는 `login_secret`(256비트)이다. SPA는 `login_secret`을 `sessionStorage`에 두고 같은 탭에서 인가 주소로 이동한다.
2. 인가 요청: `response_type=code`, `scope=openid`(이메일도 필요 없다), `redirect_uri`=로그인을 시작한 허용 출처의 콜백(기본 `http://localhost:4812/auth/google/callback`, 6.3절 허용 출처 목록 `[사용자 정정 2026-11-04]` `[ADR-0005 반영 2026-11-04]`), `state`, `nonce`, `code_challenge`, `code_challenge_method=S256`, `prompt=select_account`, `login_hint`=허용 계정의 `sub`(Google은 `login_hint`로 이메일과 `sub`를 모두 받는다. 저장하는 것이 `sub`뿐이라 이메일을 쓸 수 없었다 `[구현 M0b]`). `access_type=offline`을 보내지 않으므로 **refresh token이 없다**.
3. Google이 콜백으로 돌려보내면 서버는 `state`가 살아 있는 `login_id`의 것인지 보고(한 번 쓰면 지운다), `code`를 `code_verifier`와 함께 토큰 끝점에서 바꾼다. ID 토큰은 서명(Google JWKS), `iss`(`https://accounts.google.com` 또는 `accounts.google.com`), `aud`(이 클라이언트 ID), `exp`, `iat`, `nonce`(이 `login_id`의 값, 한 번만), **`sub`가 허용 값과 같음**을 확인한다 [출처: Google OpenID Connect 문서]. oauth4webapi는 TLS로 받은 ID 토큰의 서명을 기본으로 보지 않으므로 `validateApplicationLevelSignature`를 따로 부른다. `iss`의 두 표기는 oauth4webapi가 `.d.ts`에 싣지 않은 `_expectedIssuer` 기호로 받는다. 이 기호가 없어지면 `https://accounts.google.com`만 받는다 `[구현 M0b]`. 이메일은 표시용이고 판정에 쓰지 않는다. Google 액세스 토큰과 ID 토큰은 확인 뒤 버리고 저장하지 않는다.
4. 콜백은 성공이든 실패든 `/#/auth/finish`로 303 이동한다. URL에 코드도 세션도 싣지 않는다. SPA는 `sessionStorage`의 `login_secret`과 `login_id`로 `POST /auth/google/finish`를 부르고, 서버는 콜백이 끝난 `login_id`이고 `login_secret`이 맞을 때만 loupe 세션을 내준다. 다른 탭이나 다른 브라우저가 시작한 로그인에 남의 코드를 끼워 넣는 로그인 CSRF가 여기서 끝난다.
   - **콜백 증명** `[보안 검토 2026-11-04]`. 콜백은 `/#/auth/finish?cb=<1회용 증명>`으로 303 이동한다. 증명은 조각(`#` 뒤)에만 있어 서버 요청, 로그, `Referer`에 가지 않고, SPA는 읽자마자 `history.replaceState(null,'','#/')`로 주소에서 지운다. 로그인을 팝업(새 창)에서 했으면 팝업이 증명을 같은 출처 `BroadcastChannel`로 로그인을 시작한 탭에 넘긴다. finish는 `login_secret`(로그인을 시작한 탭)과 콜백 증명(Google을 끝낸 브라우저) **둘 다** 요구하고 둘 다 한 번만 쓰인다. 같은 머신의 다른 사용자가 자기 탭에서 로그인을 시작하고 사용자가 그 인가 주소로 Google을 끝내게 하는 로그인 중계는 증명이 사용자 브라우저에만 가므로 실패한다.
5. 세션: 256비트 임의값, 서버 메모리에 해시만, 응답 본문으로 받아 `sessionStorage`에 두고 `Authorization: Bearer`로 보낸다. **쿠키를 쓰지 않는다** [relief: 1.2절, 2.3절]. 유휴 1시간, 최대 12시간 `[가정]`. 연장 토큰이나 조용한 재로그인은 없다. 만료되면 로그인 화면으로 가고, 저장 안 한 글은 그 탭 메모리에 남아 다시 로그인한 뒤 저장할 수 있다. 같은 탭에서 Google로 이동하면 메모리가 사라지므로, 만료와 잠금 뒤의 재로그인은 새 창(`noopener`)에서 하고, 그 창의 `/#/auth/finish`가 같은 출처 `BroadcastChannel`로 알리면 원래 탭이 자기 `login_secret`으로 finish를 부른다. 앱은 덮개 아래 `inert`로 남는다 `[구현 M0b]`. **유휴 판정** `[보안 검토 2026-11-04]`: 유휴 시계는 사용자 입력으로만 갱신한다. 클라이언트는 입력이 몰린 한 번마다 `X-Loupe-Activity: 1`을 한 번 보내고, 그 뒤 입력이 있었던 동안만 60초마다 핑을 보낸다. 작업 센터, 쓰기 대기, 조사 상태의 폴링 같은 뒤에서 도는 요청은 절대 갱신하지 않는다. 열어 둔 탭이 폴링만으로 세션을 살려 두지 못한다. `isTrusted`인 입력 이벤트만 활동으로 센다. `X-Loupe-Activity`는 힌트일 뿐 사람이 있다는 증명이 아니다. Bearer를 쥔 스크립트는 이 헤더를 꾸밀 수 있다 `[보안 검토 2026-11-04]`. `loupe serve`가 다시 시작하면 로그아웃이다.
6. 잠그기: 아바타 메뉴의 "잠그기"(2.8절)와 `Ctrl+Alt+L`이 서버 세션을 지운다. Google 쪽 로그아웃은 하지 않는다(브라우저의 Google 세션은 사용자의 것이다).

라이브러리는 **oauth4webapi 3.8.8**(MIT, 의존성 0, 설치 스크립트 없음, 2026-09-05 게시)을 쓴다 [측정: `npm view`]. 같은 저자의 openid-client 6.8.9는 jose를 함께 들이고 11-02 게시라 7일 규칙에 걸린다. 직접 구현하지 않는다.

### 6.2 사용자의 설정 절차

에이전트는 이 절차를 대신하지 않는다. 비밀은 저장소에 두지 않는다.

1. Google 계정의 2단계 인증을 켜고 패스키나 보안 키를 등록한다. 이것이 실제 피싱 방어다(6.6절).
2. Google Cloud 콘솔에서 프로젝트를 하나 만들고 OAuth 동의 화면을 "외부", 게시 상태 "테스트"로 두고 자기 계정만 테스트 사용자로 넣는다. 범위는 `openid`뿐이다.
3. 사용자 인증 정보 → OAuth 클라이언트 ID 만들기 → 애플리케이션 유형 **"웹 애플리케이션"**, 이름 `loupe` `[사용자 정정 2026-11-04]`. PC와 나중의 모바일(iPhone, Galaxy Fold, iPad)이 같은 클라이언트를 쓰게 하려는 것이다. Google 웹 클라이언트 규칙: https가 필수이되 `localhost`와 loopback IP는 예외, 원시 IP는 loopback 말고 금지, 최상위 도메인은 공개 접미사 목록에 있어야 하고, 와일드카드와 조각(`#`)은 안 된다 [출처: Google OAuth 2.0 for Web Server Applications, 2026-11-04 확인]. **승인된 리디렉션 URI**에 둘을 넣는다: 지금 `http://localhost:4812/auth/google/callback` `[ADR-0005 반영 2026-11-04]`(IP 출처는 WebAuthn RP ID가 될 수 없어 PC 출처를 `localhost`로 둔다, 6.3절), 나중 모바일 단계에서 내부 https 출처의 `https://loupe.<내부 도메인>/auth/google/callback`. 처음에는 첫째만 넣어도 된다. 이미 넣은 `http://127.0.0.1:4812/auth/google/callback`은 지우기를 권한다: loupe는 기본 설정에서 그 값을 `redirect_uri`로 보내지 않고, 쓰지 않는 등록 URI는 코드가 갈 수 있는 곳만 늘린다. 이전 판의 "데스크톱 앱"은 loopback만 받아 모바일 출처를 더할 수 없어 바꿨다.
4. 클라이언트 ID와 클라이언트 보안 비밀을 KMS에 넣는다: `kms key add loupe-google-oauth --to loupe`(TTY, 에코 없음, `kms.md` 6.6절). 티어는 T1이다. KMS agent가 `~/.config/loupe/google-oauth.json`(mode 600, 저장소 밖)으로 렌더한다. 웹 애플리케이션 클라이언트의 보안 비밀은 실제 기밀(confidential client)이다. 저장소에 두지 않고 KMS 자료로 다룬다 `[사용자 정정 2026-11-04]`. KMS가 생기기 전에는 `loupe google-setup`(TTY 전용)이 같은 파일을 에코 없이 받아 쓴다.
5. 허용 계정 등록: 터미널에서 `loupe google-enroll`(TTY 전용). 브라우저로 한 번 로그인하게 하고, 받은 `sub`와 이메일을 터미널에 보여 준 뒤 사용자가 `y`를 치면 `sub`만 `~/.config/loupe/auth.json`(mode 600)에 쓴다. 이메일을 보여 주려고 이 명령만 `scope=openid email`을 쓴다. 고정 리디렉션 URI를 이 명령이 직접 받으므로 그동안 `loupe serve`와 소켓 유닛을 멈춰야 한다(포트가 차 있으면 그렇게 안내하고 끝난다). 실행 중인 `loupe serve`는 `auth.json`의 `sub`가 바뀐 것을 다음 요청에서 보고 모든 세션을 끊는다 `[구현 M0b]`. 웹에서 허용 계정을 정하거나 바꾸는 길은 없다. 이 파일이 없으면 `loupe serve`는 "설정 필요" 화면만 낸다.
6. 바꾸기: 계정을 바꾸려면 `loupe google-enroll`을 다시 돈다. 바뀌면 모든 세션을 끊고, 진행 중인 로그인과 콜백까지 끝났지만 finish 전인 로그인을 모두 무효로 한다. finish는 세션을 내기 직전에 `sub`를 지금의 허용 값과 다시 비교한다 `[보안 검토 2026-11-04]`. 클라이언트 비밀이 새면 콘솔에서 새로 만들고 `kms rotate loupe-google-oauth`.

### 6.3 검사

모든 `/kb/*`, `/kb-write/*`, `/auth/*` 요청이 아래를 통과해야 한다. v1의 `localhost` 허용과 `navigate` 통과는 데이터 경로에서 없앤다 [relief: 2.1절 `guard.ts` 표].

| 검사 | 읽기(`/kb/*`) | 쓰기(`/kb-write/*`), `/auth/*`의 POST | Google 콜백(`GET /auth/google/callback`) |
|---|---|---|---|
| Host | 허용 출처 목록의 한 출처와 정확 일치(기본 `localhost:4812`) | 같다 | 같다 |
| Origin | 있으면 Host가 고른 그 출처와 정확 일치 | 반드시 있고 정확 일치 | 최상위 이동이라 Origin이 없거나 Google이다. 대신 `state` |
| Fetch Metadata | `sec-fetch-site`가 있으면 `same-origin`만 | 같다 | `sec-fetch-mode=navigate`, `sec-fetch-dest=document`만 |
| 세션 | `Authorization` 유효 | 쓰기는 유효. `/auth/*`는 해당 없음 | 해당 없음 |
| 형식 | GET, HEAD | POST, `application/json`, `X-Loupe-Write: 1` 또는 `X-Loupe-Auth: 1`. CORS 응답 헤더 없음 | `state`, `code` 외 파라미터 무시. 오류 파라미터는 실패로 |

구현 `[구현 M0b]`: Fetch Metadata 두 헤더가 콜백에 **없어도** 403이다. 앱 자신의 정적 파일은 v1처럼 다른 사이트에서 온 최상위 이동을 받지만 Host는 정확 일치이고, 목록에 없는 loopback 이름(`127.0.0.1`, `[::1]`)은 경로와 해시를 그대로 둔 채 308로 `localhost`에 보낸다 `[ADR-0005 반영 2026-11-04]`. 그 이름으로 온 `/kb/*`, `/auth/*`는 403이다. 출처의 포트는 `LOUPE_PORT`(기본 4812)다. 원본 내려받기(`/raw`)는 링크로는 세션 헤더를 실을 수 없어 SPA가 Bearer로 받아 `application/octet-stream` Blob으로 저장한다. 서버의 `Content-Disposition: attachment`와 sandbox CSP는 그대로다. 시험용 환경 변수가 둘 있다: `LOUPE_OIDC_ISSUER`(흉내 제공자. HTTP는 loopback 주소일 때만 허용)와 `LOUPE_SESSION_IDLE_MS`(1시간보다 줄이기만 한다). 둘 다 같은 UID만 바꿀 수 있고, 같은 UID는 6.7절대로 막지 않는다.

- 바깥 페이지는 `/auth/*` POST의 사전 요청에서 끝나므로 로그인을 시작하거나 끝낼 수 없다. 콜백을 직접 부르게 해도 살아 있는 `state`가 없어 실패하고, 실패는 세지 않는다. 암호가 없으므로 실패 잠금도 없다. 로그인 시작은 분당 10회로 제한한다 `[가정]`.
- **허용 출처 목록** `[사용자 정정 2026-11-04]`. `~/.config/loupe/loupe.json`의 `{"origins": [...]}`(mode 600)이고, 파일이 없으면 `http://localhost:<LOUPE_PORT>` 하나다 `[ADR-0005 반영 2026-11-04]`. 항목은 Google 웹 클라이언트 규칙에 맞는 것만 받는다: http는 `localhost`만(IP 출처는 WebAuthn을 쓸 수 없어 `127.0.0.1`도 받지 않는다 `[ADR-0005 반영 2026-11-04]`), 그 밖은 호스트 이름의 https, 경로·와일드카드·사용자 정보 없음. 맞지 않는 항목은 버리고 상태 화면의 설정 문제에 적는다. Host가 목록의 어느 출처와도 맞지 않으면 403, Origin은 Host가 고른 출처와 같아야 한다. `redirect_uri`는 로그인을 시작한 출처의 콜백이고 `login_id`와 함께 저장된다. 콜백이 다른 출처로 오면 그 로그인은 실패(`origin_mismatch`)이고, finish를 다른 출처에서 부르면 403이며 그 로그인은 지워진다. 세션은 Bearer라 출처마다 따로 로그인한다. 서버는 여전히 `127.0.0.1`에만 바인딩한다. 오버레이 노출은 11.3절의 나중 단계이고 별도 검토를 거친다.
- 로그인 화면은 `localhost:4812`로만 연다. `127.0.0.1`로 오면 그 주소로 보낸다. `sessionStorage`와 리디렉션 URI가 그 출처에 묶여서다. **기본 출처가 `127.0.0.1`이 아니라 `localhost`인 이유** `[ADR-0005 반영 2026-11-04]`: KB ADR-0005 6.8절은 publish, release, declassify, HITL에 WebAuthn 사용자 확인을 요구하고 KB는 RP ID `localhost`, 출처 `http://localhost:4812`를 등록한다. WebAuthn은 IP를 RP ID로 쓸 수 없다. 가상 인증기를 붙인 헤드리스 Chromium이 `http://127.0.0.1`에서 `SecurityError`를 냈고 `localhost`에서는 받았다(리드 측정, 2026-11-04). 소켓은 여전히 `127.0.0.1`에만 바인딩하고 Host 검사만 `localhost:4812`를 받는다.
- **tower 마운트(`/loupe`)를 끈다.** tower 프록시는 `authorization`을 지우고 GET, HEAD만 지난다 [relief: 2.1절]. v1 10절의 선택 마운트를 철회한다. 저장소와 tower 설정에 `/loupe` 항목은 없었다(지울 것이 없었다). 프록시를 거친 요청은 Host가 허용 출처가 아니라 403이고, 세션 헤더도 지워지므로 열리지 않는다 `[구현 M0b]`.
- **포트 점유.** v1의 systemd 소켓 유닛이 4812를 늘 쥔다 [v1: 10절]. 빈 포트를 다른 UID가 잡으면 Google 리디렉션의 `code`를 받을 수 있지만 PKCE `code_verifier`가 없어 바꾸지 못한다. 가짜 로그인 화면은 loupe 암호를 받을 것이 없다. **시작 때 다른 프로세스가 4812를 쥐고 있으면 `loupe serve`는 종료 코드 1로 시작을 거부하고 다른 포트로 물러나지 않는다.** 소켓 활성화로 물려받은 fd는 받는다 `[보안 검토 2026-11-04]`. 모든 응답은 `Referrer-Policy: no-referrer`를 싣는다 `[보안 검토 2026-11-04]`.
- **허용 계정이 바뀔 때** `[보안 검토 2026-11-04]`. 진행 중·완료 대기 로그인을 모두 무효로 하고 finish가 `sub`를 다시 비교한다(6.2절 6).
- **설정 디렉터리와 파일** `[보안 검토 2026-11-04]`. `~/.config/loupe`가 심볼릭 링크이거나, 사용자 소유가 아니거나, 그룹·다른 사용자가 쓸 수 있으면 loupe는 그 디렉터리를 거부한다(`loupe serve`와 TTY 명령이 시작하지 않고 이유를 적는다). 읽기는 `O_NOFOLLOW`로 열고 연 fd를 검사한다(소유자, 형식, 권한). 쓰기는 같은 디렉터리에 임의 이름의 임시 파일을 `O_EXCL|O_NOFOLLOW`로 열어 쓴 뒤 `rename`한다. 대상: `auth.json`, `loupe.json`, `google-oauth.json`, `breakglass-open.json`, KB 토큰 파일.
- **상태 머리의 저하 값** `[보안 검토 2026-11-04]`. 상태 머리(status header)의 저하(`degraded`) 값은 KB `/v1/meta`에서만 정한다. 브라우저가 보낸 값이나 다른 응답에서 가져오지 않는다.
- `loupe status`는 KB 소켓을 직접 읽으므로 세션이 필요 없다 [v1: 10절].

### 6.4 오프라인

Google 로그인에는 인터넷이 필요하다. WSL이나 PC가 오프라인이면 새 로그인이 안 된다. 이미 열린 세션은 유휴 1시간 동안 계속 쓰인다(세션 확인은 로컬이다). loupe 서버는 시작 때 Google에 닿지 않아도 뜬다. JWKS는 로그인 때 받고 캐시는 메모리에만 둔다.

### 6.5 비상 경로

**결정: TTY로 여는 비상 암호.** Google에 닿지 못할 때만 쓴다.

- `loupe breakglass set`(TTY 전용, 에코 없음, 12자 이상)이 argon2id 해시를 `~/.config/loupe/auth.json`에 둔다(`node:crypto`, 새 의존성 없음 [relief: 2.1절]). 값은 PHC 문자열, m=64 MiB, t=3, p=4(RFC 9106 두 번째 권장값)다. 여는 상태는 `auth.json`이 아니라 `~/.config/loupe/breakglass-open.json`(`until`, mode 600)에 둔다. 서버가 Google 로그인 성공 때 이 파일만 지우면 되고 `auth.json`을 쓰지 않는다 `[구현 M0b]`.
- 평소에는 암호 로그인 경로가 **닫혀 있다.** 터미널의 `loupe breakglass open`(TTY 전용)이 1시간 동안만 연다. 그동안 로그인 화면에 "비상 암호" 칸이 나타나고, 시간이 지나거나 Google 로그인이 한 번 성공하면 닫힌다. 여는 일과 쓰는 일이 모두 상태 화면과 서버 로그(시각만)에 남는다.
- "Google에 닿지 않음"을 서버가 판정해 자동으로 여는 방식은 쓰지 않는다. 네트워크를 막을 수 있는 쪽이 비상 경로를 열 수 있게 되기 때문이다.
- 비상 암호 로그인에는 6.3절의 검사와 relief식 실패 지연(검사를 통과한 시도만 셈, 5회부터 30초, 상한 5분, 영구 잠금 없음)이 붙는다. 구현은 5회째 30초에서 실패마다 두 배(60, 120, 240, 300초)이고, 지연 중에는 맞는 암호도 429다. 닫힌 동안 `POST /auth/breakglass`는 404다 `[구현 M0b]`. **동시 요청** `[보안 검토 2026-11-04]`: 비상 암호 시도는 한 번에 하나다. 요청 본문을 읽기 **전에** 동시 처리 잠금을 잡고, 확인 바로 **전에** 지연 상태와 열림 상태(`breakglass-open.json`의 `until`)를 다시 확인한다. `/auth/*` 요청 본문은 4 KiB(넘으면 413)와 5초(넘으면 408)로 자르고, 어느 쪽이든 잠금을 푼다. 확인에 성공한 뒤 세션을 내기 전에 열림 상태, `sub`, 해시를 다시 확인한다 `[보안 검토 2026-11-04]`.

| 선택지 | 얻는 것 | 잃는 것 |
|---|---|---|
| **TTY로 여는 비상 암호(결정)** | 오프라인에도 loupe를 쓴다. 평소에는 암호 경로가 없어 피싱할 것이 없다 | 비상 경로가 열린 1시간은 암호 하나가 문이다. 열려면 터미널에 있어야 한다 |
| 없음 | 문이 Google 하나뿐이다 | 오프라인이면 loupe를 못 쓴다. KB는 `kb` CLI로만 본다 |
| 늘 열린 로컬 암호 | 편하다 | 암호 로그인과 다를 바 없다(6.8절에서 버렸다) |

같은 UID는 비상 경로가 없어도 KB 소켓을 직접 읽으므로, TTY를 요구하는 이 경로가 같은 UID에게 새로 주는 것은 없다.

### 6.6 피싱 저항

- **실제 방어는 Google 계정의 2단계 인증, 특히 패스키나 보안 키다.** 패스키는 Google 도메인에 묶여 가짜 Google 화면에서 쓰이지 않는다. loupe는 사용자 계정의 설정을 강제할 수 없으므로 6.2절 1단계로 둔다.
- loupe 쪽: 받는 암호가 없다. `state`는 `login_id`에 묶여 한 번만 쓰이고 5분 뒤 사라진다. `nonce`는 ID 토큰에서 한 번만 받아들인다. PKCE S256이 가로챈 `code`를 쓸모없게 한다. 리디렉션 URI는 고정된 loopback 하나다. `sub` 하나만 들어온다.
- 사용자에게 보이는 규칙: 로그인 화면은 "Google로 로그인" 단추뿐이다. loupe 주소에서 Google 암호를 묻는 칸이 보이면 가짜다. Google 암호는 `accounts.google.com`에서만 친다.

### 6.7 남는 위험

| 주체 | 결과 |
|---|---|
| 다른 출처의 페이지, 다른 로컬 포트의 페이지 | 막는다. 세션은 이 출처의 `sessionStorage`에만 있고 자동 전송이 없다 |
| WSL 다른 UID, host network 컨테이너 | 막는다. 세션 없이는 읽기도 쓰기도 없다. 허용 `sub`로 로그인해야 한다 |
| DNS 재바인딩 | 막는다. Host 정확 일치 |
| 다른 Google 계정 | 막는다. `sub` 불일치 |
| Google 계정 탈취 | 못 막는다. 그 계정이 문이다. 2단계 인증과 패스키가 막는다 |
| loupe가 멈춘 동안 4812를 연 다른 로컬 프로세스(localhost 출처 탈취) | **수용한 위험** [ADR-0005 L840~841]. 같은 출처의 스크립트로 이 브라우저의 초안(IndexedDB)을 읽고 WebAuthn 창을 띄울 수 있다. 다만 유효한 KB 도전은 `loupe serve`만 쥔 `reviewer` 토큰이 있어야 나오므로 KB 동작을 승인시키지 못한다. 완화: 포트를 쥐고 있으면 시작 거부(6.3절), 초안을 보이기 전에 KB가 발급한 serve 신원 확인(나중, 11.3절) |
| 같은 UID(Claude 세션, npm 스크립트, Windows 같은 사용자) | **못 막는다.** KB 소켓을 직접 읽고 loupe 소스나 `auth.json`을 고칠 수 있다 [relief: 1.2절] |
| loupe 출처 안의 XSS | 세션을 쓸 수 있다. 4.5절의 스키마, CSP, Trusted Types가 막는다 |

### 6.8 버린 안

| 안 | 이유 |
|---|---|
| 암호만 쓰는 로그인(이전 판, relief 1단계) | 사용자 결정. 암호는 가짜 화면에 털리고, 피싱 저항을 loupe가 스스로 만들어야 한다 |
| Google refresh token으로 조용히 연장 | 오래 사는 자격이 디스크에 남는다. 사용자가 갱신 없음을 골랐다 |
| 이메일 허용 목록 | 이메일은 바뀌거나 다른 계정에 다시 쓰일 수 있다. Google은 `sub`를 식별자로 쓰라고 한다 [출처: Google OpenID Connect 문서] |
| 암묵 흐름, 브라우저에서 토큰 교환 | 토큰이 URL이나 브라우저에 남는다. Google은 PKCE 코드 흐름을 권한다 |
| "데스크톱 앱" 클라이언트 유형(이전 판의 결정) | loopback 리디렉션만 받아 나중의 모바일 https 출처를 같은 클라이언트에 더할 수 없다. 웹 유형은 loopback IP의 http를 허용한다 [출처: Google OAuth 2.0 for Web Server Applications] `[사용자 정정 2026-11-04]` |
| 세션 쿠키 | 쿠키는 포트를 가리지 않는다 [relief: 1.2절] |
| oauth2-proxy, tower 앞단 인증 | 서비스가 하나 늘고 tower 프록시가 `authorization`을 지운다. 도구 독립 원칙과 맞지 않는다 |
| 자체 OIDC 구현 | oauth4webapi가 있다(3번 지침) |

### 6.9 relief와의 일관성

relief 문서는 고치지 않는다. 두 도구가 같은 문을 쓰려면 relief 쪽에서 바뀔 것을 적어 둔다.

- relief 2.1절의 "Phase 1은 사람이 정한 암호 하나"가 Google 로그인으로 바뀐다. 쿠키 없는 세션, 정확한 Origin, 사전 요청으로 끝나는 POST 검사는 그대로 맞는다.
- relief는 자기 OAuth 클라이언트(또는 같은 클라이언트에 자기 리디렉션 URI)와 `http://127.0.0.1:4815/auth/google/callback`을 쓰고 허용 `sub`를 따로 등록한다. 세션은 출처마다 따로다. 코드 공유는 하지 않는다(도구 독립).
- relief 8B절의 원격 접근(Tailscale Serve, HTTPS 호스트 이름)은 loopback이 아니므로 그 경로의 리디렉션은 웹 애플리케이션 유형과 그 호스트 이름이 필요하다. relief가 정할 일이다.
- relief 8B.3절의 "패스키로 바꾸고 암호를 없앤다"는 Google 계정의 패스키로 대신할 수 있다. relief의 쓰기 재확인(L2, L3)과 KMS 잠금 해제는 Google 로그인과 별개로 남는다.

## 7. 주제 조사 요청 (E, D4)

사용자 결정: loupe가 에이전트를 움직이는 것이 아니라 **KB에 조사를 요청하는 체계**다. loupe의 동작은 "KB에 이 주제의 조사를 요청한다" 하나이고, 수집이든 에이전트든 방법, 예산, 상한은 KB가 정한다 [ADR-0004 T.8, ADR-0005 6.1].

### 7.1 만들기와 요청

**규칙 하나: KB로 가는 주제 글은 정해진 필드뿐이고, 한 함수가 만들고, 사용자가 보내기 전에 본다**(Codex 2차 2).

- **필드.** `TopicSpec`의 `title`(이름), `body`(범위 설명), `props.aliases`, `props.exclude`, `sensitivity`(`private` 기본, 만들 때만 `internal`). `slug`는 보내지 않는다. 서버가 spec ID에서 `t-`+16자로 정한다 [ADR-0005 L308]. 우선순위, URL, `reason`은 KB가 받지 않아 없앴다 [ADR-0005 6.1, 3.1].
- **함수.** `buildTopicSpec(fields)` 하나가 위 필드로 `record`를 만든다. 메모와 문서 객체를 인자로 받지 않는다. 연구 요청 본문은 `{idempotency_key:"loupe:r:<spec>:<run UUID>", run_id, change:"save", expected_version}`뿐이라 글이 없다 [ADR-0005 6.1].
- **미리보기.** 보내기 단추는 언제나 그 함수의 결과를 글자 그대로 보이는 자리에 있다. `ConfirmedTopicText`는 이 미리보기의 보내기 단추만 만든다.

| 길 | 동작 | KB 호출 |
|---|---|---|
| 메모 승격 | 메모 창 머리, 폰 말풍선 길게 누르기. 단추 글이 `주제로 승격: 「<메모 제목>」`이고 제목을 자르지 않고 다 보인다. 누르는 것이 확인이다(D13). 이름과 범위 설명은 둘 다 메모 제목(2.5절), 별칭·제외는 비어 있다. 메모의 둘째 줄부터는 어디에도 들어가지 않는다. "고쳐서 승격"은 만들기 창을 연다 | `POST /v1/records/{memo}/promote {idempotency_key:"loupe:p:<memo>:v<n>", change:"save", to:"topic", memo_version, research:{run_id}, record}`. 서버가 `TopicSpec` 타입과 `PROMOTED_FROM`을 넣고 같은 커밋에서 연구를 연다 [ADR-0005 5.7] |
| 새 주제 | 찾기의 "새 주제 '…' 만들고 KB에 조사 요청" → 주제 만들기 창(이름, 범위 설명, 별칭, 제외, 공개 범위). 아래쪽 "KB에 보낼 글" 미리보기 옆의 "보내기"가 확인 | `POST /v1/records`(`TopicSpec`) 뒤 `POST /v1/topics/{spec}/research` |
| 조사 다시 요청 | 주제 창, 작업 상세 창 | `POST /v1/topics/{spec}/research`(새 `run_id`) |

- **되돌리기(8초).** 알림의 "되돌리기"는 멈춤(`…/research/{run}/stop`)과 spec tombstone 두 호출이다. 승격 기록은 원장에 남는다 [ADR-0005 5.7].
- **합류.** 같은 주제의 열린 실행이 있으면 200 `existing:true`로 그 실행을 돌려준다. 화면은 "열린 조사에 합류"다. 이전 판의 문장 유사도 합치기는 없다 [ADR-0005 6.1].
- **예산 없음.** 예산 장치(FW6) 전에는 승격은 성공하고 `research.state=budget_unavailable`이다. 주제만 만들어지고 다시 요청 단추가 잠기며 "KB가 아직 조사를 받을 수 없다"를 보인다.
- **승격은 공개가 아니다.** `private` 메모를 승격하면 spec, 티켓, 주제, 실행이 모두 `private`다(O6 정함: 비공개로 남긴다). 더 넓은 조사가 필요하면 작업 상세 창의 "내부로 공개(기기 확인)" = 사용자 동작 `declassify`(5.8절).

### 7.2 보이는 것

작업 센터의 조사 항목과 작업 상세 창(블루프린트 W6). 원본은 `GET /v1/topics/{spec}/research`다 [ADR-0005 6.3].

| 칸 | 내용 |
|---|---|
| 상태 | `queued` → `in_progress` → `done`, 또는 `paused`, `cancelled`, `unanswerable`, `blocked_policy`, `budget_unavailable`. 이름 그대로 보인다. `blocked_policy`와 `budget_unavailable`은 다시 요청 단추가 없다 |
| KB가 고른 엔진 | `engines[]`: 결정적 수집기 수, LLM 과제·팔·호출 수 |
| 비용 | `cost.month_usd` / `budget_usd_month`. **읽기 전용**. 보고가 없으면 "보고 없음" |
| 결과 | `results.accepted_claims`, `edges`, `needs_review`와 지난 방문 뒤 새로 온 것. 수집 그래프에 쌓는다(방금 들어온 엣지는 점선) |
| 승인 대기 출처 | `pending_hosts` 수만. 승인은 KB 쪽(HITL `source_policy` 또는 `kb topic approve`) |
| 실패 | `failures[]` 최대 20건, 소스 ID로만 |
| 찾는 범위 | `discovery`와 `discovery_reason`. `private` 주제는 늘 `"narrowed"`, `private_topic_registered_sources_only`: "등록된 소스와 로컬만. 새 출처 검색과 외부 LLM을 쓰지 않는다" [ADR-0005 L728, L799] |
| 밖으로 나간 것 | `private` 주제면 "없음"(7.4절) |

- 갱신은 45초 폴링이다. 뒤에서 도는 요청이라 유휴 시간을 갱신하지 않는다(6.1절 5).
- **멈추기.** "주제 멈추기 요청"은 `…/research/{run}/stop`이다. 실행은 `cancelled`, 주제는 `paused`가 되고 이미 보낸 호출은 끝나고 정산된다 [ADR-0005 6.2].
- **결과는 자동으로 들어온다.** 받기 단추가 없다. 도착한 것은 이미 KB 인용 게이트를 지났다. 화면은 주장마다 v1 인용 판정(원문 일치, 위치 보정, 찾지 못함)과 원문 열기를 준다. "원문 일치는 인용이 원문에 있다는 뜻일 뿐 사실 여부나 원문에 심은 지시를 판정하지 않는다"를 표 위에 늘 둔다(Codex 6).
- **틀린 것은 "틀림 제보"**(O7, ADR-0005 L304, L777~785). 주장 옆 "틀림 제보"가 작은 창을 연다: 이유(필수, 500자 이하), 출처 URL(선택, 공개 출처의 절대 http(s) URL 하나). 보내면 `POST /v1/records`에 `Review {target:<주장 ID>, verdict:"reject", note, source_url?, topic}`(기본 `private`). KB가 그 리뷰에 묶인 재검증 티켓을 열고 게이트가 기존 근거와 새 출처 후보를 자동으로 다시 본다. **제보는 주장을 숨기거나 바꾸지 않는다.** 화면은 "제보함 · KB가 다시 확인 중"이고 결과는 다음 갱신에 반영된다. 주장별 제보 목록은 `GET /v1/nodes/{id}/reviews`다. 이전 판의 "버리기"(내 화면만 거르기)는 없앴다.

### 7.3 확인 필요(HITL)

KB가 자동 해석으로 의도를 스스로 정하지 못할 때만 항목을 만든다(사용자 확정) [ADR-0005 6.8]. 나머지는 묻지 않는다.

| 신호 | 화면 | 해결 |
|---|---|---|
| `topic_ambiguity` | 후보 둘 이상을 나란히(근거 수) | 고르기(`select`), 범위 보충(`clarify`), 거절 |
| `source_policy` | 새 출처 후보와 약관·robots 판정 | 승인, 거절 |
| `liveness_unresolved` | 충돌하는 생존 근거 | 확인, 거절, 미루기 |
| `gate_unresolved` | 함의 판정이 풀지 못한 주장 | 받기(`accept`), 거절(`reject`). `review_state`만 바뀐다 |

- 자리: 작업 센터의 "확인 필요" 항목과 노란 배지(O8). 주제 모호성은 그 주제의 작업 상세 창에도. 폰은 흐름의 노란 카드.
- 목록은 `GET /v1/hitl`(reviewer), 해결은 5.8절의 도전과 기기 확인 뒤 `POST /v1/hitl/{item}/resolve`다.

### 7.4 밖으로 나가는 글

**`private` 주제에서는 아무것도 나가지 않는다.** 이름도 외부 검색어나 외부 LLM에 쓰이지 않는다(`export_llm`, `export_query`가 늘 거짓). 연구는 등록된 소스, 기존 스냅샷, 앵커만 로컬에서 대조한다 [ADR-0005 3.6, L799]. loupe 기본값이 `private`이므로 승격 주제는 이 경우다.

`internal`로 만든 주제에서: 범위 설명(`body`)은 늘 로컬 모델에만 간다. 이름, 별칭 같은 짧은 칸은 `export_query`(기본 참)면 공개 검색어로, `export_llm`(기본 거짓)이 참일 때만 외부 LLM으로 간다 [ADR-0005 6.6]. 주제 만들기 창은 `internal`을 고르면 두 칸을 보이고 미리보기 아래에 "이 글은 외부 검색에 쓰인다", `export_llm`을 켜면 "외부 모델에 갈 수 있다"를 적는다.

**나가지 않는 것:** 메모 본문, 문서 본문, 주제에 링크된 기록의 내용, 찾기에 친 다른 글. 예외는 **지식베이스에 반영**(5.8절) 하나이고, 그때도 보낼 요청에 묶인 기기 확인 동의 뒤에 그 메모 하나의 고정된 요청 한 번만 간다. 반영 동의는 주제 연구에 쓰이지 않는다 [ADR-0005 L799].

| 강제 장치 | 내용 |
|---|---|
| 타입 | `write.ts`의 주제 경로는 `ConfirmedTopicText`만 받는다. 메모나 문서 객체를 받는 시그니처가 없다 |
| 함수 | `buildTopicSpec` 하나만 직렬화한다. 허용 키 밖의 필드가 있으면 보내지 않고 오류다. `private`면 `export_llm`·`export_query`를 거짓으로 고정한다 |
| 시험(경계) | 메모 첫 줄에 표식 A, 둘째 줄 이후에 표식 B를 넣고 승격한다. Playwright가 `kb-write/` 요청 본문을 모두 가로채 **B는 0번, A는 `title`과 `body` 자리에만** 나오고, 요청 본문이 승격 단추에 보인 글과 바이트 단위로 같음을 단언한다 |
| 시험(다른 경로) | 문서를 링크한 주제를 만들고 문서 본문 표식이 0번, 찾기에 표식을 친 뒤 만들기를 해 창에서 지운 글이 0번. `private` 주제 요청의 `export_*`가 거짓. `write.ts` 단위 시험은 허용 키 밖 필드와 `ConfirmedTopicText`가 아닌 값에서 실패 |

## 8. 비밀 보기 (D5)

사용자 결정: 별도 KMS 인증 뒤 loupe에서 비밀 값을 볼 수 있다. 가장 적게 드러나게 설계한다. **KMS가 생기기 전에는 잠긴 자리만 있다.** 구현은 KMS M1~M2 뒤의 나중 단계다(11.3절).

**비밀 객체**(사용자, 2026-11-04). 비밀과 개인 정보는 그래프와 찾기에 이름만 보이는 객체다. KMS 항목 하나가 **레코드**(서비스, 주소, 사용자, 암호, 복구 코드, 만료 같은 칸. KV 키마다 한 칸)이거나 **문서**(설명 글과 그 안의 값 칸)이고, 종류는 KMS `custom_metadata`의 `kind`(`record`, `doc`)에 둔다 `[가정: KMS M1에서 확인]`. 열면 **별도 출처의 작은 창을 모달처럼** 띄운다(S1 정함, 블루프린트 W5). 같은 출처 모달과 다른 출처 iframe은 버렸다: 앞의 것은 편집기 결함 하나로 KMS 토큰이 읽히고, 뒤의 것은 주소 줄이 없어 침해된 본 창이 가짜 암호 칸을 그려도 구별하지 못한다.

### 8.1 구조

| 항목 | 결정 | 이유 |
|---|---|---|
| 출처 | **별도 출처의 비밀 창** `http://127.0.0.1:4814`. 2026-11-04에 이 저장소, KB 저장소, 사용자 systemd 설정에서 4814를 grep으로 찾지 못했고 듣고 있는 프로세스도 없었다. 4815와 4816은 relief(`relief.md` 11절), 4810~4813은 loupe가 쓴다. 그래프와 찾기의 자물쇠 객체, 문서의 보안 정보 블록이 이 창을 연다. 주소 이름은 결정 S2(12.2절): `localhost:4814`는 본 창과 같은 사이트라 브라우저가 프로세스를 나누지 않을 수 있어 `127.0.0.1`을 권한다. KB 데이터, 사용자 본문, Markdown 렌더, 편집기가 이 출처에 없다 | loupe 본 출처의 XSS(4.5절)가 KMS 토큰과 값에 닿지 못한다 |
| 서버 | 이 출처는 정적 파일만 낸다. 값과 토큰은 **브라우저가 KMS에 직접** 요청한다. `loupe serve`도 비밀 창 서버도 KMS 요청을 프록시하지 않는다 | 서버 로그와 프로세스에 값이 지나가지 않는다 |
| 창 참조 끊기 | 본 창은 비밀 창을 `window.open(url, '_blank', 'noopener,noreferrer')`로만 연다. 두 출처 모두 `Cross-Origin-Opener-Policy: same-origin`을 보낸다. 비밀 창은 시작할 때 `window.opener`가 `null`이 아니면 아무것도 그리지 않고 "loupe에서 다시 열기"만 보이며, `window.name`을 비운다. URL 파라미터와 조각을 읽지 않고 `message` 수신기를 두지 않는다. `frame-ancestors 'none'` | 편집기 XSS가 비밀 창을 이동시키거나 이름으로 겨냥하거나 메시지를 보내지 못한다(Codex 2차 1) |
| 모달처럼 보이기 | 창은 `window.open(url, '_blank', 'noopener,noreferrer,popup,width=520,height=640,left=…,top=…')`로 본 창 가운데에 작게 띄운다. 본 창은 창을 연 순간부터 자기 화면을 어둡게 덮고 "비밀 창에서 열림"을 보이며, 본 창이 다시 초점을 얻으면 덮개를 걷는다. 본 창은 비밀 창의 상태를 알 수 없고(참조가 없다) 알려고 하지 않는다. 폰은 새 탭이다(M3) | 사용자가 고른 모양(S1)을 참조 없이 낸다 |
| 포트 점유 | `loupe.socket`에 `ListenStream=127.0.0.1:4814`를 `FileDescriptorName=secret`으로 더해 systemd가 4814를 늘 쥔다. relief 터미널이 같은 이유로 소켓을 쥔다 [relief: 7.1절]. `loupe serve`는 `secret` fd를 받았을 때만 비밀 창을 내고, 받지 못했으면(소켓 유닛 없이 띄움) 본 창의 비밀 객체 열기를 막고 이유를 적는다. 비밀 창을 TCP 포트에 직접 바인딩하는 길은 없다 | 다른 UID가 빈 4814를 먼저 잡아 가짜 KMS 로그인으로 암호와 TOTP를 모으지 못한다 |
| 가짜 화면 대비 | 포트를 쥐는 것이 1차 방어다. 페이지 스스로는 자기가 진짜임을 증명할 수 없으므로(가짜 페이지는 검사를 돌리지 않는다) 남는 방어는 사람 쪽이다: 본 창의 자물쇠 객체로만 열고, 주소 표시줄이 `127.0.0.1:4814`인지 본다. KMS가 출처에 묶인 로그인(패스키)을 지원하면 `loupe-reader`를 그것으로 바꾼다. 패스키는 다른 출처의 페이지에서 쓰이지 않는다 `[가정: OpenBao의 WebAuthn 지원은 확인하지 않았다]` | |
| 신원 | 사용자 자신의 KMS 사람 신원. 권장은 사람 계정 `loupe-reader`(암호 + TOTP): 정한 KV 경로의 `read`와, 5.7절의 새 보안 정보를 넣을 경로의 **`create`만**(덮어쓰기인 `update`는 없음). `owner` 계정은 쓰지 않는다 | `owner` 토큰이 브라우저에 오면 피해가 KV 전체가 된다 [출처: `kms.md` 6.5절]. 덮어쓰기가 없어 브라우저 침해가 기존 키를 바꾸지 못한다 |
| 토큰 설정(KMS 쪽) | `token_ttl=15m`, `token_max_ttl=15m`, `token_explicit_max_ttl=15m`, `token_no_default_policy=true`. 정책은 정한 KV 경로의 `read`, 메타데이터 `read`·`list`, `auth/token/lookup-self`, `auth/token/revoke-self`뿐이고 **`renew-self`가 없다** `[가정: 매개변수 이름은 Vault와 같다고 보고 KMS M1에서 확인한다]` | 기본 정책의 갱신 권한이 빠져 잠금 뒤에 토큰이 늘어나지 않는다. 최대 수명은 어떤 경우에도 15분이다(Codex 2차 3) |
| KMS 쪽 설정 | CORS 허용 출처를 `http://127.0.0.1:4814` 하나로. KMS 이름(`kms.sys.internal.example`)과 사설 CA는 이 브라우저에만 [출처: `kms.md` O25] | 다른 출처는 응답을 읽지 못한다 |
| CSP(비밀 창) | `default-src 'none'; script-src 'self'; connect-src https://kms.sys.internal.example; style-src 'self'; img-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'; require-trusted-types-for 'script'` | 값을 다른 곳으로 보낼 길을 막는다 |
| 토큰 | JS 변수에만. `sessionStorage`, `localStorage`, IndexedDB, URL, 쿠키에 두지 않는다. 창을 닫거나 새로 고치면 다시 로그인 | 디스크에 남지 않는다 |

### 8.2 값 보기

| 동작 | 규칙 |
|---|---|
| 목록 | 이름, 서비스, 만료, 마지막 사용(KV 메타데이터). 값 칸은 처음부터 `••••`이다. 목록을 열 때 값을 읽지 않는다 |
| 보기 | 그 항목만 KMS에서 읽는다. 30초 뒤 다시 가리고 값을 담은 변수를 비운다. 한 번에 하나만 보인다 |
| 복사 | 그 항목을 읽어 `navigator.clipboard.writeText`로 넣고 화면에는 값을 그리지 않는다. 값 변수는 넣은 즉시 비운다. 20초 뒤, 그리고 잠금과 `pagehide` 때 클립보드에 빈 문자열을 쓰려 한다. 그 사이 다른 것이 복사됐는지는 알 수 없어 무조건 비운다 |
| 보장하지 못하는 것 | 창이 죽거나 강제로 닫히거나 브라우저가 끝나면 비움 타이머도 함께 죽어 **클립보드에 값이 남는다.** Chrome은 초점 없는 문서의 클립보드 쓰기를 거절할 수 있어 창을 숨긴 뒤의 비움도 실패할 수 있다. 실패하면 다음에 창이 초점을 얻을 때 다시 비우고 "클립보드를 비우지 못했다"를 보인다. 클립보드 기록(Win+V)과 관리자에 들어간 사본은 지울 수 없다. 그래서 기본 동작은 보기이고 복사는 두 번째 단추다 |
| 잠금 계기 | 유휴 3분, 창을 60초 숨김, "지금 잠그기", 시계 건너뜀(1초마다 벽시계를 보고 마지막 확인보다 10초 넘게 지났으면 절전에서 돌아온 것으로 본다), `pagehide`, 그리고 토큰 남은 수명 0 중 먼저 오는 것 |
| 잠금 순서 | ① 화면의 값을 지우고 값을 담은 변수를 비운다. ② 진행 중인 KMS 요청을 `AbortController`로 끊고, 잠금 세대 번호를 올려 늦게 도착한 응답은 버린다. ③ 토큰 변수를 비운다(사본을 들고 폐기만 한다). ④ `revoke-self`를 3초 안에 부른다. ⑤ 클립보드를 비우려 한다 |
| 폐기 실패 | **닫힌 쪽으로 실패한다.** 폐기가 실패하거나 시간을 넘겨도 ①~③은 이미 끝났고 다시 열지 않는다. 화면은 "KMS에서 토큰을 폐기하지 못했다. 최대 n분 뒤 스스로 만료된다"와 남은 시간을 보인다. 새 잠금 해제는 새 로그인이다. 토큰은 갱신 권한이 없어 15분을 넘지 못한다 |
| 가림 | 보기 30초 타이머에 더해 창이 초점을 잃으면 곧바로 가린다. 타이머는 벽시계 마감 시각으로 비교해 절전 뒤에도 늦게 가리지 않는다 |
| 감사 | 보기와 복사는 각각 KMS 읽기 요청 하나라 KMS 감사 장치에 항목마다 남는다. loupe는 따로 기록하지 않는다. 창 옆에 "이번 해제 뒤 열람 n, 복사 n"만 메모리 값으로 보인다 |
| 남지 않는 곳 | 검색, 그래프(이름만 있다), 찾기, 브라우저 이력(URL에 이름도 없음, 탭 제목은 "loupe · 비밀"), 로그(콘솔과 오류 보고에 이 창의 상태를 넣지 않음), 기기 저장소 |
| 쓰기 | "새 보안 정보"(8.3절)만. 기존 키의 교체, 서비스 부여, 폐기는 `kms` 명령이나 KMS 화면이다 [출처: `kms.md` 6.6절] |
| 폰(M3 정함) | 새 탭의 비밀 창. 보기와 복사 모두 된다. 복사하면 "값이 폰 클립보드에 남을 수 있다"를 보이고 되는 기기에서 20초 뒤 비우기를 시도한다(iOS·Android 브라우저는 초점 없는 쓰기를 막을 수 있어 보장하지 않는다). 숨으면(`visibilitychange`) 60초를 기다리지 않고 바로 잠근다. 폰의 비밀 창 출처는 모바일 접속 단계의 https 이름이다(11.3절) |

### 8.3 보안 정보 넣기

5.7절에서 "보안 정보"를 고르면 이 창의 "새 보안 정보" 양식이 열린다.

| 칸 | 규칙 |
|---|---|
| 이름 | KMS 항목 이름. 비어 있지 않고 KMS 이름 규칙을 따른다. 문서의 보안 정보 블록에서 왔다면 그 이름이 채워져 있다 |
| 값 | 이 창에서만 친다. 에코 없는 입력칸(`type=password`, 자동 완성 끔)이고 "보기" 단추로만 잠시 보인다 |
| 메모 | 무엇의 키인지 한 줄. KMS 메타데이터에 들어가고 값은 넣지 않는다 [출처: `kms.md` 6.8절 `custom_metadata` 규칙] |
| 저장 | 잠금 해제된 `loupe-reader`로 KV `create`. 같은 이름이 있으면 실패하고 "이미 있다. 교체는 `kms rotate`"를 보인다 |

- 저장 뒤 입력칸과 변수를 비운다. 값은 loupe 본 출처, KB, 기기 저장소 어디에도 가지 않는다.
- 서비스에 부여하는 일(`kms grant`)은 이 창에 없다. 새 항목은 부여 전까지 아무 서비스도 읽지 못한다.
- KMS가 없거나 잠겨 있으면 양식은 잠금 해제를 먼저 요구한다. KMS 준비 전에는 "KMS 준비 전. 지금은 넣을 곳이 없다"만 보이고, 본 창의 보안 정보 블록은 이름만 가진 채 남는다.

### 8.4 남는 위험

값을 보는 순간 브라우저와 화면은 값을 본다. 설계가 줄이지 못하는 것을 그대로 적는다.

- 브라우저 렌더러 메모리, 화면, 화면 녹화와 원격 화면, 어깨 너머.
- 이 브라우저 프로필의 확장 프로그램. 비밀 창 출처에 권한이 있는 확장은 값을 읽는다.
- 클립보드 관리자와 **Windows 클립보드 기록(Win+V)**. 사용자는 기록을 그대로 두기로 했다(D16). 그래서 20초 뒤 비워도 기록에는 남는다. 비밀 창은 복사 단추 옆과 복사 직후 알림에 "복사한 값은 Windows 클립보드 기록(Win+V)에 남을 수 있다"를 짧게 늘 보인다.
- 같은 UID 프로세스(브라우저 프로필 파일, 디버그 포트, loupe 소스 변조). KMS 토큰을 가로채면 15분 안의 읽기 범위 전부다.
- KMS 쪽 CORS를 잘못 넓히면 다른 출처가 응답을 읽는다. KMS 설정 시험으로 막는다.

- 저장 칩, 조사 상태, 쓰기 거절, 맨 앞 창 바뀜은 `aria-live="polite"`. 거절 알림은 규칙 ID만 읽는다. 비밀 창은 값을 읽어 주지 않는다.
- 색만으로 상태를 나누지 않는다(v1 원칙). 기즈모는 글로도 말한다.
- **iPad와 펼친 Fold**는 PC와 같은 화면이다. 손잡이와 칩은 44 px 이상, 올리기로만 보이는 것은 탭(활성)으로도 연다, 창 끌기는 머리 길게 누르기. **폰**은 2.9절의 흐름이고 좌우로 미는 손짓은 넣지 않는다(iPhone, Galaxy의 "뒤로"와 겹친다).

## 10. ADR-0005와 KB에 필요한 것

ADR-0005 9판(`42980bf`, KB `kb-foundation` 가지)이 이전 판의 N1~N13, K-a~K-d와 loupe 대조 질문 Q1~Q14에 답했다. 답의 목록은 ADR 14.7(L1282~1301)이고, 아래 "L"은 그 판의 줄이다. 남은 것은 K-c 하나와 구현이다. 결정은 KB가 하고 loupe는 받은 답을 5절과 `write.ts`에 반영한다.

**답한 것**

| # | 요청 | 답 | 근거 |
|---|---|---|---|
| N1 | 경로와 전송 | 읽기와 같은 소켓, 쓰기도 Bearer(`editor`). `POST`, `PUT`, `DELETE` | ADR 2.1, 2.2(L98~128) |
| N2 | 작성자와 사람 확인 | `actor=app:loupe`, `claimed_author=user:sagae`. loupe 로그인은 KB가 보지 않는다. 사람 증명은 `reviewer` + 동작마다 WebAuthn | ADR 3.2, 6.8 |
| N3 | 종류 | `Page`, `Note`, `TopicSpec`, `Review`. 엔티티 `e:topic:<slug>`는 `DEFINES` | ADR 4.1 |
| N4 | 묘비, 복원 | HTTP tombstone과 `PUT expected_version`으로 복원 | ADR 5.5 |

## 11. 단계 (G)

명령은 모두 `cd /home/user/sagae-tools/tools/loupe`에서 돈다. 새 시험 파일은 그 단계에서 만든다. 기존 시험(`npm run check`, `npx playwright test`)이 모든 단계에서 계속 통과해야 한다. 브라우저 시험은 헤드리스다. 실제 KB가 ADR-0005를 구현하기 전(FW1~FW4·FW8)에는 **`dev/kb-mock`이 ADR-0005 모양을 흉내 낸다**: 경로, 요청·응답 필드, 422 `hits`, 409 `current`, 202 `write_ref`, 숨은 대상 404, `/v1/meta.write`. kb-mock의 쓰기 흉내는 `dev/kb-mock/write.ts` 한 파일이고 ADR의 예시 응답을 fixture로 쓴다.
